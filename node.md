<!-- THOUGHT:BEGIN — authored, not derived; carried across regenerating scans. The reasoning behind THIS version. -->
Added --set NAME so a secret can be rotated without ever touching a command line. The owner is about to livestream this box and asked for a safe way to paste a new OpenRouter key over ssh, which made the existing situation untenable in two ways at once. First, there was no way to set a key except editing .env by hand, and any shell form of that puts the secret in ~/.bash_history, in ps, and in the recording — on a livestream that is not a theoretical leak. getpass reads straight from the tty, so the value never reaches argv, history, screen or this process's stdout; the confirm prompt catches a truncated paste, which is the realistic failure when pasting a long key over ssh. Second, the write replaces EVERY line for the key rather than appending, because .env already carried OPENROUTER_API_KEY twice and a duplicated key is a live hazard, not untidiness: which value wins depends on the parser, so a rotation that appends can leave the dead key winning and the new one inert. The write is atomic through a same-directory tempfile plus os.replace with mode 0600 set before the rename, so an interrupted rotation cannot leave a truncated or world-readable secrets file. It refuses outright when stdin is not a tty rather than accepting a pipe, because accepting a pipe is exactly the habit that puts secrets in history.
