# mvp:grid-two-roots

`grid.py` is handed one root by its callers and has two different jobs for it.
It now keeps them apart:

| root | value here | what it is for |
|---|---|---|
| **graph root** | `/home/ubuntu/work/agi/.agi` | finding node **files** — `iter_node_files()` and nothing else |
| **repo root** | `/home/ubuntu/work/agi` | **every git invocation** — `refs/grid/*` and the object store live here |

`repo_root()` is a two-line delegation to `locations.repo_root()`, which is
`.parent` on a `.agi/` directory and the identity on anything else. That is why
this change is a no-op for every pre-`goal:g11` project: under the legacy layout
the two roots are the same directory, which is also exactly why the conflation
was invisible until G11 separated them.

All five git invocation sites in the file are routed through it — `git()`,
`ref_tip()`, `read_tree_entry()`'s `cat-file`, `ensure_repo()`'s `rev-parse`,
and `engine_tracked_files()`'s `ls-files`. Verified mechanically, not by
reading:

```
$ grep -n 'subprocess.run(\["git"\|"-C"' extensions/agi/bin/grid.py
178:  ["git", *GIT_IDENT, "-C", str(repo_root(root)), *args],
481:  ["git", "-C", str(repo_root(root)), "rev-parse", "-q", "--verify", ref],
541:  ["git", "-C", str(repo_root(root)), "cat-file", "blob", f"{rev}:{name}"],
615:  if subprocess.run(["git", "-C", str(repo), "rev-parse", "--git-dir"],   # repo = repo_root(root)
894:  res = subprocess.run(["git", "-C", str(repo_root(engine_root)), "ls-files"],
```

## What the conflation was actually doing

`git -C <repo>/.agi` sets git's **prefix** to `.agi/`, and every cwd-scoped
subcommand then resolves paths under that prefix. A grid commit's tree carries
`node.md` at *its own* root, under no prefix at all. Two consequences, both of
which reported success:

- **`ls-tree` matched nothing**, so `read_tree()` returned `[]` and every node
  read as `CHANGED` while byte-identical. Measured here at **812 of 812**.
- **`diff <ref>~1 <ref> -- node.md`** became `-- .agi/node.md`, matched nothing,
  and printed an empty diff with exit 0 for `goal:g11.1`, a node with three real
  versions. The same command from the repo root emits 3696 bytes.

`ref_tip`, `rev-list` and `commit-tree` take no pathspec and were correct
throughout, which is what made the whole thing look fine.

`--full-tree` had already been added to the two `ls-tree` calls, and it is the
correct flag for what those calls do. What it was not is the fix: it rescued
`status` and left `cmd_diff` broken, because `git diff` has no `--full-tree`.

## The `--full-tree` experiment (gate 3)

Three variants of this file were generated by text substitution from the shipped
source and driven against the **live 812-node corpus** by
`/tmp/g3/drive.py <variant>`, which calls `cmd_status(root, engine_root=repo)`
and `cmd_diff(root, "goal:g11.1", 1)` directly:

| variant | `status` CHANGED | `diff goal:g11.1` |
|---|---|---|
| **shipped** — repo-root split + `--full-tree` + `:(top)` | 14 | 3680 bytes |
| **A** — repo-root split, **both** prefix-proof spellings removed | **14** | **3680 bytes** |
| **B** — graph-root conflation, no flags (the raw defect) | **812** | 1 byte (empty) |
| **C** — graph-root conflation + `--full-tree` (what shipped before this node) | 14 | **1 byte (empty)** |

A and shipped report the byte-identical CHANGED set (`diff` of the two lists is
empty). The same three variants were then run against the **whole of
`test_grid.py`** through a harness at `/tmp/g3/harness`:

```
A (split, no flags)          68 passed, 1 skipped, 0 failed   <- identical to shipped
B (conflated, no flags)      61 passed, 7 failed
C (conflated, --full-tree)   63 passed, 5 failed
shipped                      68 passed, 1 skipped, 0 failed
```

**The root split alone carries every test. The flags carry none of them.**

**What shipped: the root split, and `--full-tree` / `:(top)` kept.** They are
the correct spelling for "this path is relative to the tree's own root", true
regardless of where git is run from, and variant A is the evidence that nothing
now leans on them. Keeping a correct-by-intent flag that is *provably* not
load-bearing costs nothing; removing it would only mean the next person has to
rediscover why the pathspec is unusual. The claim "it is belt-and-braces" is
now a test result rather than an assertion, which is the part that changed.

## Secondary, same defect class, same file

- **`find_project_root()`** delegates to `locations.project_root_from_env()`,
  not the plain `find_project_root()`. `grid.py`'s own `CONFIG_MARKER` /
  `CONFIG_MARKERS` constants are deleted. `$AGI_TREE_PROJECT_ROOT` now wins here
  as it does for every other entry point — `grid.py` versioning a different
  project than its caller believes is the one disagreement the grid cannot
  survive. Confirmed live: from `/tmp`, `AGI_TREE_PROJECT_ROOT=.../.agi grid.py
  versions goal:g11.1` prints `3`; before, it resolved nothing and exited.
- **`cmd_diff`** uses `:(top)node.md`. `git diff` has no `--full-tree`; the
  pathspec magic prefix is the only equivalent.
- **`ensure_repo()`** checks and *names* the repo root. A `.agi/` is never
  itself a repo, and `git init`-ing one because an error pointed there would
  create a nested repo whose object store is not the one holding `refs/grid/*`.
- **`cron_log()`** derives its name from the repo root. It doubles as the marker
  `cmd_cron` uses to find "our" crontab lines, and `install` removes every line
  carrying the marker before writing its own — so a name derived from the graph
  root gives **every migrated project the same `grid-sync-.agi.log`**, and
  installing for one would silently uninstall another's crons. Identity under
  the legacy layout, checked against the one live installed entry
  (`grid-sync-fantasia.log`; `/home/ubuntu/work/fantasia` has not migrated).
- **`cron_lines()`** emits `cd <repo>` and `git -C <repo>`. Byte-identical for
  any legacy project with an entry already installed.

## Regression tests

Eleven, appended to `extensions/agi/tests/test_grid.py`. Every pre-existing
fixture in that file builds a **legacy** tree where the two roots are the same
directory, which is precisely why this file could not see the defect. The new
`g11` fixture builds a real G11 layout — git repo at `<repo>`, graph at
`<repo>/.agi`, payload in the tracked source tree, no `payloads/`.

Two of them are load-bearing and fail from independent directions (both fail
under variant C, the state this node replaces):

- `test_no_git_invocation_ever_targets_the_graph_dir` spies on `subprocess.run`
  through a full commit → status → diff → log → versions cycle and asserts every
  `-C` argument is the repo. **This one cannot be masked by any flag, present or
  future, because it checks the cause rather than a symptom.**
- `test_diff_reads_node_md_when_the_graph_is_a_subdirectory` is the behavioural
  half, and the command no flag was covering.

Stated honestly because it is the sort of thing that gets overclaimed:
`test_status_reports_the_same_set_from_either_cwd` **does not** catch this bug.
Under the conflation, `-C` is the graph root no matter where you stand, so both
cwds agree — consistently wrong. It is a real invariant and worth pinning; it is
just not the one that would have caught this.

## Adjacent, deliberately not touched

- **`default_engine_root()` is a third root and is not `source_root()`.**
  `cmd_commit` / `cmd_status` / `cmd_checkout` default payload resolution to
  `Path(__file__).parents[3]` — the engine's own repo. For `agi` that equals
  `locations.source_root()` and for a legacy project with an `agi/` clone beside
  the tree it also equals it, so there is **no live impact today**. For a
  *migrated* project with a cloned engine (`fantasia/.agi` + `fantasia/agi/`)
  they diverge: payloads would resolve against the clone instead of the project.
  Latent, same defect class, out of this node's bound — it would change payload
  resolution for 159+ build nodes and belongs in its own change.
- **`PAYLOAD_DIR` / `cmd_checkout`.** Retired by `goal:g11`; left alone.
- **`.agi/nodes/deprecated/build/bin-grid.v2.md`** carries the same
  `payload_ref` as the live `build:bin-grid` — a leftover `@v2` node of the kind
  G6.3 abolished. Already deprecated; noted, not touched.
- **The other kid's files.** Ten `bin/*.py`, `tests/test_locations.py`,
  `.agi/nodes/mvp/bin-resolvers-onto-locations.md`, and an untracked
  `.agi/nodes/.chain_cache.pkl`. Seen in `git status`, reported, not touched.
