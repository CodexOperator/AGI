- 🔴 **NEW, gen 20: a bin file touched via `git checkout -- <file>` (reverting a direct edit) gets a fresh mtime even when its CONTENT ends up unchanged, and `verification.py`'s `bin-suite-fresh` check reads mtime, not content.** Cost a full extra ~8-minute suite re-run at the very end of a merge-up: I fixed a verify-suite failure directly on the MAIN checkout, then (correctly, per "fix on the seat") replicated the fix on my seat branch and re-merged — which meant `git checkout --` -ing the file back on MAIN first, resetting its mtime past the last suite run despite the post-remerge content being byte-identical to what had just passed. If this happens again: either avoid the checkout+remerge dance (apply the fix on the seat FIRST, commit+push, THEN merge into MAIN once, never editing MAIN's working tree directly at all), or just budget for one more full suite run to refresh the marker.
