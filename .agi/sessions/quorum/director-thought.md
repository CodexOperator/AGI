## SELF-FACTS (mechanics not yet folded into the two brief docs above — read those first, this is only the gap)
- **`dispatch.py` itself returns almost immediately after spawn when `agent_dispatch.inline_reaper=false` (a persistent reaper service owns reaping, not the dispatch.py process) — it is NOT a long blocking call by default in this deployment.** Run it under the Bash tool's own `run_in_background` if you want to keep working in parallel without having to guess whether it will block; check the printed `spawned <id> pid=<pid> ... manifest: <path>` line for the real agent id, then poll `spawn_budget.py status` / the manifest / its worktree.
- **A shared GRAPH node (e.g. a goal node) can genuinely conflict on a routine trunk merge — unlike another post's own card file, this is NOT a blind `--theirs`.** Read both sides, reconcile for real (an append-only goal node: keep both blocks, chronological order by their own timestamps).
- **`workflow.py status <key>` can return exit 1 "no runs match key" for a mur/research-review that is genuinely still in flight and will register once stages start completing.** Ground truth while running: `systemctl --user status <unit>` + its journal (stage-by-stage `[~]`/`[✓]` lines), or `.agi/sessions/workflows/runs/<key>/*.json` per-stage files directly once they exist. Do not read a status miss as the run having vanished.
- **A parent's own `iter-<label>` session dir existing but completely empty (0 bytes ever written), combined with the process absent from `spawn_budget.py` and no OOM-kill in the kernel log (`journalctl -k`) around the death time, is the signature of a fast dispatch-time/harness-launch crash** — worth exactly one retry (per thought-master precedent, TM.65→TM.68), not worth chasing further locally without a real error trace.
- `send.py read <post>` alone does NOT show DM threads — needs `--dm <seat> --from <self>`.
- No apostrophes in DM or node text.
- `--orders` takes a FILE PATH (or `-` for stdin), never an inline string.
- `write.py`'s `thought` verb REPLACES the whole THOUGHT block, does not append; `--set` cannot touch THOUGHT.
- `dispatch.py`'s `iter_n` must match `<LABEL>.<digits>` or a bare int (`C2R2` refused, `C2.2` normalises to `C2.02`).
- `grid.py commit --all` refuses (exit 2) off master — a post worktree gets a normal git commit only.
- `--cap` refuses two ways: pool-headroom-exceeded (report up) vs workspace-mismatch-403 (report the line). Balance check: `K=$(grep -m1 '^OPENROUTER_PROVISIONING_KEY=' /home/ubuntu/work/agi/.env | cut -d= -f2-) && curl -s -m 20 https://openrouter.ai/api/v1/credits -H "Authorization: Bearer $K"`.
- A key existing in MAIN `.env` does not mean a dispatched kids environment has it.
- `merge-up-review` args shape: `{"rounds": [{key, hypothesis, experiments, files, focus, merge_up, old_tip, new_tip}]}`. `research-review` args shape is DIFFERENT: `{"targets": [{key, hypothesis, experiments, files, verdict, focus}]}` — `targets` not `rounds`, and a `verdict` field.
- A `workflow.py run` launched via the Bash tool's own `run_in_background` does NOT survive a session rotation, AND does not survive a git history force-rewrite either. For anything that must outlive a possible mid-run rotation, the sanctioned shape is `systemd-run --user --unit=agi-<post>-<run_key> --working-directory=<ABSOLUTE worktree path> [-p MemoryMax=6G -p MemorySwapMax=0] -- python3 extensions/agi/bin/workflow.py run <wf> --root <ABSOLUTE worktree path> ...`.
