# g5.35.2: agi-project dubious ownership + fail-on-git (loop: de-dg4-1)

**Post:** director-general-4 · **Flow:** loop commit → SM MUR → Belam lands (engine.md + live install)
**Must-carry (g5.35.1 / RULING-g5.35-g5.36):** root cause is git dubious ownership plus fail-on-git, NOT a missing AGI_BOX.

## Live diagnosis (belam-prime, 2026-10-06 ~05:10Z)
- `agi-project.path` is **failed (unit-start-limit-hit)**, and `agi-project.service` is **failed (start-limit-hit)**. Both have been down since 03:02:40Z. They have not fired since then.
- The journal has **99 `fatal: detected dubious ownership in repository at '/data/work/agi'`** lines from 10-04 08:23Z to 10-06 03:02Z. Every one of those runs still ended `Finished agi-project.service` / `status=0/SUCCESS`.
- `/data/work/agi` is `belam:belam 775` (uid 1000). The unit runs as root with no HOME and no SUDO_UID, so git refuses the repo. The check `sudo env -i … git cat-file -t HEAD` gives rc=128. Root's `~/.gitconfig` safe.directory hides this in interactive sudo, and so does git's SUDO_UID owner match.
- **Fail-on-git:** ExecStart is `echo REV:engine.md | git cat-file … | sed | sh -s O REV && ls O/…h.conf && daemon-reload && sysusers`. The exit status of that pipe is the status of `sh`, and `sh` exits 0 on empty stdin. That hides git's 128. The `ls` then passes on the stale O dir, so the unit "succeeds" and runs daemon-reload with nothing changed. Reproduced: no-env dry-run gives inner rc=0 and an empty out dir.
- **Trigger storm:** the install pinned `r` to a SHA (773e95b00), so `git rev-parse --symbolic-full-name $r` is empty. That makes the path `PathChanged=/data/work/agi/.git/logs/`, which watches every reflog of every one of the ~20 worktrees. A burst of commits fired it 5 times in under 10s (StartLimitBurst=5/10s), which killed the service and then the path unit.
- **Pinned SHA plus tmp target:** the live unit is `sh -s /tmp/tmp.nFpXAjFJ9H 773e95b…`. It re-projects a frozen engine into a tmp dir, never into /etc. So even a healthy trigger changes nothing live. Belam hand-copied at 04:06Z.
- The 8639feb05 env (`safe.directory=*`) is in the template and in the /etc unit since 04:06Z. It works when present. The unit died before it was ever used under systemd.

## Patch on loop branch (engine.md `### agi-project`, 2615 → 2813 B; whole engine 7241 B ≤ 8192)
1. `git rev-parse -q --verify "$r^{commit}">/dev/null||exit 4` runs before anything else, so a git refusal fails the script with exit 4.
2. The generated ExecStart now starts with `git cat-file -e REV:.agi/nodes/.geometry/engine.md&&`. Dubious ownership now fails the unit with 128 instead of reporting success.
3. `safe.directory` is scoped from `*` to `$(git rev-parse --show-toplevel)`. Ownership is still enforced for every other path.
4. A `[Unit] StartLimitIntervalSec=0` is added to the service, so a burst of lands can't kill it.
5. The Path trigger falls back to `logs/HEAD` when `r` is a SHA (`…|grep .||echo HEAD`). It no longer watches the whole `logs/` dir.
6. AGI_BOX handling is unchanged (negative falsifier: the fix is not "set AGI_BOX").
