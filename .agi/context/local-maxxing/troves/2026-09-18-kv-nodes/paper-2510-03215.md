## PAGE 2 — full text (pdf) https://arxiv.org/pdf/2510.03215 (fetched 2026-09-18)

### Mechanism (one paragraph)
Two frozen LLMs (a "Sharer" S and a "Receiver" R) share no weights. Instead of S emitting text,
C2C takes S's KV-cache and R's KV-cache, projects S's cache into R's hidden dim with a small
trainable fuser (3-layer MLP), fuses via a learnable per-layer gate (dynamic weighting: projected
sharer cache + receiver cache), and adds the result into R's cache. R then decodes from the fused
cache. LLMs stay frozen; only the fuser trains (MEASURED, Fig.5 / Sec 3.2.2 / L1456).
Oracle result (MEASURED, quoted): "enriching the KV-Cache semantics can improve response quality
without increasing cache size". Layer-wise effect is non-uniform: enriching top-5 layers beat
enriching all layers; enriching worst layers hurt (MEASURED, Fig.4 / L~420). That motivates gating.
### Headline numbers (MEASURED)
- Avg accuracy gain over individual models: +11.00%, +9.64%, +11.88% for the three Sharers (Sec 4.2).
- Over text-to-text (T2T): +5.36%, +4.15%, +3.06% (Sec 4.2).
- Latency speedups vs T2T: 3.46x, 1.51x, 14.41x (Sec 4.2).
- Table 3 (MMLU-Redux; Sharer Qwen2.5-0.5B-Instruct, Receiver Qwen3-0.6B), total time:
  Receiver-only 308ms; T2T Sharer 346ms; T2T Receiver 1596ms; C2C 445ms. C2C fuses in 90ms
  parallel vs T2T Sharer's 1312ms decoding of 80 output tokens.
### Models evaluated (MEASURED, Sec 4.1)
Qwen2.5 (0.5B/1.5B/...), Qwen3 (0.6B/4B), Llama3.2-1B, Gemma3; sizes 0.6B-14B; cross-generation,
cross-family, cross-specialization (general/code/math), pre-trained + instruct.
### Hardware / cost (MEASURED)
- Efficiency metric measured on "a single NVIDIA A100 GPU with batch size one" (L635).
- Fuser training: 500k OpenHermes2.5 samples, 1 epoch, macro batch 256, 1929 steps; lr 1e-4,
  10% warmup, wd 0.01, max seq len 2048 (L1977-1992).
- Training cost (Table 12): at 300 steps "<9 GPU hours" reaches near-final accuracy; full 1929 steps
  ~5.6 wall-clock h / ~44.7 GPU h (Qwen2.5-0.5B pair). 50 steps = 1.20 GPU h, MMLU-Redux 40.36.
- Estim. fuser is tiny (3-layer MLP) — ESTIMATE: trainable params <<1% of either LLM (not stated as a number).
- Failure mode (MEASURED, Sec A.4.6): Sharer's contextual understanding is not always accurate and
  "can mislead the Receiver into generating wrong answers".

## PAGE 4 — Mooncake (top-1) https://arxiv.org/abs/2407.00079 (fetched 2026-09-18)
- Qin, Li, He, Zhang, Wu, Zheng, Xu. v1 24 Jun 2024; v4 3 Sep 2025. Serving platform for Kimi (Moonshot AI).
- MECHANISM (MEASURED): KVCache-centric disaggregated architecture — separates prefill and decoding
  clusters; uses underutilized CPU/DRAM/SSD as a disaggregated KVCache store; KVCache-centric scheduler
  balances throughput vs latency SLOs; prediction-based early rejection under overload.
- NUMBERS (MEASURED, quoted): "up to a 525% increase in throughput in certain simulated scenarios";
  "enables Kimi to handle 75% more requests". v4 paper reports large-scale production deployment.
- HARDWARE (MEASURED): GPU cluster + CPU/DRAM/SSD tiers. Not a single-box technique; a serving-system
  design. ESTIMATE: not runnable on A1/local-town as-is; the *idea* (put KV in DRAM/SSD, not VRAM) is
  the transferable part.
- ENABLES: (1) parallel decoding — no, it is serving orchestration; (3) KV-as-store — YES, closest
  published proof that KV caches can live in tiered DRAM/SSD storage and be routed/reused at scale.

## PAGE 5 — CacheBlend (top-2) https://arxiv.org/abs/2405.16444 (fetched 2026-09-18)
- Yao, Li, Liu, Ray, Cheng, Zhang, Du, Lu, Jiang. v1 26 May 2024; v3 3 Apr 2025.
- MECHANISM (MEASURED): reuse precomputed KV caches for arbitrary (non-prefix) text chunks; selectively
  recompute KV of a small subset of tokens to partially update each reused cache (fixes missing
  cross-attention between chunks); recompute pipelined with cache retrieval so caches can sit on slow,
  large storage without adding latency. Built for RAG multi-chunk inputs.
- NUMBERS (MEASURED, quoted): "reduces time-to-first-token (TTFT) by 2.2-3.3x and increases the
  inference throughput by 2.8-5x from full KV recompute without compromising generation quality";
  3 open-source LLMs, 4 benchmark datasets.
- HARDWARE (MEASURED): GPU serving (LLMs evaluated on GPUs); no CPU-only claim. Storage-tier KV is
  the point, so slow/large devices are explicitly in scope.
- ENABLES: (2) agent messaging layer — YES, direct: "fuse caches from multiple retrieved chunks" is
  exactly stitching independently-computed KV segments into one context. (3) graph nodes as KV —
  YES, closest analogue: a node's cache computed once, stored, retrieved, blended into a new prompt.

## PAGE 6 — YOCO (top-3) https://arxiv.org/abs/2405.05254 (fetched 2026-09-18)
- Sun, Dong, Zhu, Huang, Wang, Ma, Zhang, Wang, Wei (Microsoft). v1 8 May 2024; v2 9 May 2024.
- MECHANISM (MEASURED): decoder-decoder architecture — self-decoder computes global KV ONCE, cross-decoder
  reuses it via cross-attention; "only caches key-value pairs once"; prefill can early-exit without
  changing output. Architectural change, not post-hoc compression.
- NUMBERS (MEASURED, quoted): "improves inference memory, prefill latency, and throughput by orders of
  magnitude across context lengths and model sizes"; "extend YOCO to 1M context length with near-perfect
  needle retrieval accuracy". S2 cites=151.
- HARDWARE (MEASURED): GPU memory is the stated target ("substantially reduces GPU memory demands").
  Requires training models from scratch in the YOCO architecture.
- ENABLES: (1) massive parallel decoding — YES, structural: prefill early-exit + single cache = more
  concurrent requests per unit memory. (3) KV-as-graph-node — partial: one shared cache serves all
  layers, i.e. cache dedup by construction.

## PAGE 7 — CLA (runner-up) https://arxiv.org/abs/2405.12981 (fetched 2026-09-18)
- Brandon, Mishra, Nrusimha, Panda, Ragan-Kelley. Submitted 21 May 2024.
- MECHANISM (MEASURED): Cross-Layer Attention — share K/V heads between adjacent layers (extends MQA).
- NUMBERS (MEASURED, quoted): "reduce the size of the KV cache by another 2x while maintaining nearly
  the same accuracy as unmodified MQA"; trained 1B- and 3B-param models from scratch.
- HARDWARE (MEASURED): training experiments on GPUs. Requires training from scratch (architectural).
- ENABLES: (1) parallel decoding via 2x smaller cache; (3) KV-as-node — no.

## PAGE 8 — ChunkAttention (runner-up) https://arxiv.org/abs/2402.15220 (fetched 2026-09-18)
- Ye, Tao, Huang, Li. v1 23 Feb 2024; v4 1 Aug 2024.
- MECHANISM (MEASURED): prefix-aware self-attention; breaks KV tensors into chunks + prefix tree to
  share prefixes across requests at runtime; two-phase partition kernel for data locality.
- NUMBERS (MEASURED, quoted): "speed up the self-attention kernel by 3.2-4.8x ... system prompt ranging
  from 1024 to 4096".
- HARDWARE (MEASURED): GPU multi-tenant serving (custom kernel).
- ENABLES: (1) parallel decoding (shared prefixes across concurrent requests); (3) graph-node KV via
  prefix sharing — a shared "system prompt" cache is the primitive.

## PAGE 9 — Layer-Condensed KV (runner-up) https://arxiv.org/abs/2405.10637 (fetched 2026-09-18)
- Haoyi Wu, Kewei Tu. v1 17 May 2024; v2 4 Jun 2024.
- MECHANISM (MEASURED): compute/cache KVs of only a small number of layers; orthogonal to other
  memory-saving techniques.
- NUMBERS (MEASURED, quoted): "up to 26x higher throughput than standard transformers and competitive
  performance".
- HARDWARE: GPU inference; needs retraining/adaptation. ENABLES (1) parallelism via memory cut.

## SYNTHESIS — owner's three use-cases vs the top-3
(1) MASSIVE PARALLEL DECODING: YOCO (single cache, structural) and ChunkAttention (shared-prefix
    kernel) are the strongest; CLA/Layer-Condensed give 2x-26x memory cuts. All assume a GPU; on CPU
    the equivalent lever is llama.cpp `-np` slots + `--slot-save-path` + `-ctk/-ctv` quantised cache.
(2) AGENT MESSAGING LAYER: C2C is the only work here that sends KV *between models*; CacheBlend is
    the only one that *fuses* independently-computed caches into one context. Together they are the
    published basis for a KV-native agent bus (compute once, project/blend, never re-prefill).
(3) GRAPH NODES AS KV CACHES: Mooncake proves KV lives in tiered DRAM/SSD at production scale;
    CacheBlend proves non-prefix cached chunks can be blended losslessly-ish; C2C proves a cache can
    cross model boundaries. No paper does all three; the gap = our hypothesis space.
OPEN QUESTION for the town: none of these target CPU-only / sub-1B / no-GPU; C2C's fuser is a tiny
MLP (cheap on CPU) but its fusers are trained for GPU pairs. ESTIMATE: a CPU-only C2C-style fuser on
Qwen3-0.6B + Qwen2.5-0.5B is the most tractable first experiment on the A1 box.
