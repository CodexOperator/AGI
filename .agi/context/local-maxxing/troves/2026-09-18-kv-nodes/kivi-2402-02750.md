# kivi-2402-02750 — KIVI (2-bit asymmetric KV) — reading digest

## PAGE 1 — arXiv abs/html v2 (fetched 2026-09-18)
URL: https://arxiv.org/html/2402.02750v2 ; https://arxiv.org/abs/2402.02750
- TITLE (MEASURED): "KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache"
- AUTHORS (MEASURED): Zirui Liu, Jiayi Yuan, Hongye Jin, Shaochen Zhong, Zhaozhuo Xu,
  Vladimir Braverman, Beidi Chen, Xia Hu.
- DATE (MEASURED): submitted 5 Feb 2024; v2 25 Jul 2024.
- KEY INSIGHT (MEASURED, quoted): "the key cache should be quantized per-channel, i.e., group
  elements along the channel dimension and quantize them together. In contrast, the value cache
  should be quantized per-token." → asymmetric K/V quantisation.
- HEADLINE (MEASURED, quoted): "maintain almost the same quality while using 2.6× less peak memory
  (including model weight) ... up to 4× larger batch size, bringing 2.35×~3.47× throughput."
- GROUP SIZE (MEASURED, quoted): "group sizes 32 and 64 yield similar results, whereas performance
  significantly decreases when the group size reaches 128." Per-channel group = 32/64.
- RESIDUAL WINDOW (MEASURED, quoted): "with a residual length of 32, KIVI achieves a significantly
  higher memory compression rate ... changing the residual length from 128 to 32 does not result in
  a substantial performance gap." → last 32 tokens kept full precision, rest 2-bit.
- TUNING (MEASURED): "tuning-free" — no calibration, no training, per-channel/per-token scales
  computed on the fly.

## BYTE TABLE (ESTIMATE — arithmetic shown)
KIVI effective rate ≈ 2 bits + per-group scale/zero overhead + 32-token fp16 residual.
- 9B-class (36 layers, 8 kv_heads, head_dim 128) ESTIMATE:
  fp16 per token/layer = 2×8×128×2 = 4096 B = 4 KiB. Quantised to 2-bit ≈ 4 KiB/8 = 512 B
  + overhead (~2 scale+2 zero per 32-group × 8 heads ≈ 2 B/token/layer) ≈ 514 B.
  4k tokens: 36 × 514 × 4096 ≈ 75.8 MB (vs 576 MiB fp16) ≈ 7.6x raw KV; residual 32 tok negligible.
  32k tokens: ≈ 606 MB (vs 4.5 GiB fp16).
- 27B-class (64 layers, 8 kv_heads, head_dim 128) ESTIMATE:
  fp16 4 KiB/token/layer. 2-bit ≈ 514 B.
  4k: 64 × 514 × 4096 ≈ 134.7 MB (vs 1.0 GiB fp16).
  32k: ≈ 1.078 GB (vs 8.0 GiB fp16).
- NOTE (MEASURED paper framing): "2.6× less peak memory" is peak incl. model weights, NOT raw KV
  ratio. Raw KV compression at 2-bit is ≈7-8x (ESTIMATE above), but end-to-end is 2.6x because
  weights dominate. Important for ARM4C: KV shrink ≠ whole-model shrink.
