- AUTHORS (MEASURED): Coleman Hooper, Sehoon Kim, Hiva Mohammadzadeh, Michael W. Mahoney,

- FOUR METHODS (MEASURED, quoted): "(i) Per-Channel Key Quantization ... (ii) Pre-RoPE Key

  Non-Uniform KV Cache Quantization ... per-layer sensitivity-weighted non-uniform datatypes ...
  (iv) Per-Vector Dense-and-Sparse Quantization, where we isolate outliers separately for each

- HEADLINE QUALITY (MEASURED, quoted): "4-bit quantization with less than 0.02 perplexity
  degradation, 3-bit quantization with under 0.1 perplexity degradation, and 2-bit quantization with
  under 0.5 perplexity degradation on Wikitext-2, relative to the fp16 baseline, across all models
  (while attaining 3.7×, 4.8×, and 6.9× memory savings, respectively)."
- CONTEXT REACH (MEASURED, quoted): "serving the LLaMA-7B model with a context length of 1M tokens
  on a single A100 GPU ... 10M context length inference with the LLaMA-7B model on an 8-GPU system."
- SPEED (MEASURED, abstract): "up to ~1.7x speedups, compared to baseline fp16 matrix-vector
  multiplications, for the LLaMA-7B model."
- CONCRETE MEMORY (MEASURED, quoted): LLaMA-65B at 32K tokens needs "30.3GB for the model weights
  compressed to 4-bit, and 46.5GB for the KV cache when compressed with nuq2-1%".

## BYTE TABLE (ESTIMATE — arithmetic shown)
KVQuant rates: nuq4 ≈ 4-bit (3.7x), nuq3 ≈ 3-bit (4.8x), nuq2 ≈ 2-bit (6.9x) incl. sparse outlier
overhead. Ideal fp16→rate ratios: 16/4=4x, 16/3=5.33x, 16/2=8x; KVQuant real is lower (3.7/4.8/6.9)
because of per-vector outlier + scale overhead.
- 9B-class (36 layers, 8 kv_heads, head_dim 128) ESTIMATE, fp16 = 4 KiB/token/layer:
  4k tokens fp16 = 576 MiB.
    4-bit (÷3.7) ≈ 156 MiB; 3-bit (÷4.8) ≈ 120 MiB; 2-bit (÷6.9) ≈ 83 MiB.
  32k tokens fp16 = 4.5 GiB. 4-bit ≈ 1.22 GiB; 3-bit ≈ 960 MiB; 2-bit ≈ 667 MiB.
- 27B-class (64 layers, 8 kv_heads, head_dim 128) ESTIMATE, fp16 = 4 KiB/token/layer:
  4k tokens fp16 = 1.0 GiB. 4-bit ≈ 277 MiB; 3-bit ≈ 213 MiB; 2-bit ≈ 148 MiB.
  32k tokens fp16 = 8.0 GiB. 4-bit ≈ 2.16 GiB; 3-bit ≈ 1.67 GiB; 2-bit ≈ 1.16 GiB.
- ARM4C RELEVANCE (ESTIMATE): 2-bit KVQuant makes a 27B/32k cache ~1.2 GiB — the only configuration
  where 27B+long-context is even addressable on ARM4C's ~7 GiB free. But KVQuant is CUDA-only and
  unlicensed → use its IDEAS (per-channel K, pre-RoPE, outliers), not its code, on CPU.
