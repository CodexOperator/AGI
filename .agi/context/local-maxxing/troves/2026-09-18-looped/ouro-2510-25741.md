## PAGE 1 — arXiv abs/html (fetched 2026-09-18)
URL: https://arxiv.org/abs/2510.25741 ; https://arxiv.org/html/2510.25741v2
- TITLE (MEASURED): "Scaling Latent Reasoning via Looped Language Models"
- AUTHORS (MEASURED): Rui-Jie Zhu, Zixuan Wang, Kai Hua, Tianyu Zhang, Ziniu Li, Haoran Que, Boyi Wei,
  Zixin Wen, Fan Yin, He Xing, et al. (ByteDance Seed / UC Santa Cruz / Princeton).
- DATE (MEASURED): submitted 2025-10-29.
- MECHANISM (2 lines, MEASURED): a Looped Language Model (LoopLM) — the whole decoder layer stack is
  applied `total_ut_steps` times with shared weights (a prelude/recurrent-block/coda shape), with
  (i) iterative latent computation, (ii) an entropy-regularized objective over exit depth, (iii) an
  adaptive early-exit gate. Reasoning happens in latent space, not in emitted tokens.
- DIFFERENCE FROM TEMPORAL RECURRENCE: DEPTH recurrence — the same position is iterated; state does
  not carry across token boundaries beyond ordinary KV attention (contrast RLT, digest
  `recurrent-looped-transformer-rlt.md`).

## UNIQUE PARAMS vs EFFECTIVE DEPTH (MEASURED config + GGUF README)
- `ByteDance/Ouro-1.4B` config: `num_hidden_layers: 24`, `hidden_size: 2048`, `total_ut_steps: 4`,
  `early_exit_threshold: 1.0`, `torch_dtype: bfloat16`, vocab 49152, ctx 64K (extendable).
- `ByteDance/Ouro-2.6B` config: `num_hidden_layers: 48`, same hidden/vocab, `total_ut_steps: 4`.
- GGUF README (MEASURED): "the entire 24-layer decoder stack is applied 4 times per token with shared
  weights, so a 1.4B-parameter model computes at an effective depth of 96 layers"; the GGUF loads as
  `n_layer = 96` at 1.43 B parameters — depth expanded, weights stored once.
- ESTIMATE arithmetic: Ouro-1.4B eff. depth = 24 x 4 = 96; Ouro-2.6B = 48 x 4 = 192.

## CPU RUNNABILITY (MEASURED / ESTIMATE)
- transformers path: CPU-capable; needs `trust_remote_code`; card warns vLLM ignores adaptive exit.
- GGUF path: **requires a PATCHED llama.cpp today** — the `ouro` architecture is not upstream
  (MEASURED: GGUF README; and grep of llama.cpp master `src/llama-arch.h` shows no `ouro`). The patch
  is submitted as a llama.cpp PR from `BrandeisPatrick/loop-transformer`; stock llama.cpp/Ollama/LM
  Studio cannot load these files yet.
- Loop count is a RUNTIME dial (MEASURED, unique for a GGUF):
  `llama-cli -m Ouro-1.4B-Q8_0.gguf --override-kv ouro.num_loops=int:N` (N=1,2,4).
- ESTIMATE tok/s on the 4-core aarch64 box, `BW/(weight_bytes x loops)`, BW 12-24 GB/s:
  Ouro-1.4B Q4_K_M: 13.4-26.8 @1 loop, 3.3-6.7 @4 loops; Q8_0 @4: 2.0-3.9; Ouro-2.6B Q4 @4: 1.8-3.6.
- Cross-check MEASURED on a consumer ARM laptop SoC (GGUF README): ~36 tok/s @1 loop, ~9.5 tok/s @4.

## QUALITY vs SAME-UNIQUE-PARAMS NON-LOOPED (MEASURED)
- GGUF eval (200-problem GSM8K subset, 3-shot CoT, greedy, strict match; GGUF README):
  F16 1 loop **26.0%** -> 2 loops 67.0% -> 4 loops **80.5% ± 2.8**; Q8_0 4 loops 79.8%; Q4_K_M 4 loops
  75.0%. Reference transformers bf16 4 loops 80.0; published paper figure 78.92. Token-identical greedy
  smoke output; every depth within one SE of the reference.
- Paper Table 10 (Ouro-1.4B base, same params, UT step 1 -> 4):
  ARC-C 37.63 -> 60.92; ARC-E 63.85 -> 83.96; CommonsenseQA 44.64 -> 75.43; HellaSwag 55.24 -> 74.29;
  MMLU 41.21 -> 67.45; Winogrande 56.99 -> 72.30. Extrapolation beyond 4 steps degrades (trained at 4).
- Headline (MEASURED abstract/card): 1.4B/2.6B match 4B/8B standard transformers => 2-3x parameter
  efficiency; 2.6B@4 loops: OlympiadBench 76.44 vs Qwen3-8B 75.25, BeyondAIME 39.0 vs 38.0.
- Quantisation note (MEASURED): Q4_K_M costs ~5 pts, and the penalty is FLAT in loop depth (6.0 @1 loop
  vs 5.5 @4 loops) — the "error compounds per loop" hypothesis was tested and is false.

## TRAINING RECIPE COST (MEASURED)
- 7.7T tokens total: Stage 1 pretrain 6T; Stage 2 CT annealing 1.4T; Stage 3 long-context 20B;
  Stage 4 mid-training 300B. AdamW (b1=0.9, b2=0.95), WSD LR schedule. 2.6B upcycles 24 -> 48 layers
  by duplication (recurrence makes upcycling smooth). Hardware / GPU-hours NOT stated (gap).

## VERDICT FOR THE TOWN
