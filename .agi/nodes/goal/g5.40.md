## Target end-state
- A committed sample, frozen in params BEFORE any run: the 20 most recently landed (by landing commit date on core/season3/main at mint) hypotheses with verdict proved whose falsifier names an in-tree runnable check (script + inputs). Excluded at selection, each with its reason listed: any check that calls rotate / heal / send / dispatch / crons. Fewer than 20 qualifying = take all and state n.
- Per item ONE mutant, written into params before any run: its own named mutant; else the ARM SWAP (treatment vs control: swap their inputs; a number vs a threshold: replace the measurement with the control / null run's value); else the one-line inversion of the claimed property; a check with none is listed NOT KILLABLE.
- Each check run at its item's pre-run commit, in an archived scratch tree (never ~/t, never a worktree of the live repo): killed = reads RED / not-proved under its mutant; survived = still reads proved.
- The counts (n, killed, survived, not killable, not runnable) handed to idea:an-evidenced-disproof-scores-as-a-proof's owner (sanctuary-master) as one data row.

Both columns reported per item. Either way the counts are the deliverable.
2b. n (remix): the qualifying items that HAVE a mutant AND ran; NOT KILLABLE and NOT RUNNABLE are reported beside n and never counted as survived; NOT KILLABLE is its own reported number (a vacuity signal).
