# goal:g7.16.1.11.35

## Why this exists
goal:g7.16.1.11: every pi stage dies on encryption-town (belam-s2-II 22:3xZ via SM 22:5xZ, which stopped the Prime's PASS B5). `extensions/agi/bin/mem_cap.py` `wrap_argv` returns `["prlimit", f"--as={_as_bytes(cap)}", "--", *argv]` when no user systemd manager is reachable (:384, the NAMED RESIDUAL DH.421 at :379-381), and agi-belam has none on E. Under `prlimit --as=2G` node's undici cannot instantiate its llhttp wasm ("WebAssembly.instantiate(): Out of memory": V8 reserves large VIRTUAL regions for wasm), so the stage exits 1 named "memory-cap". Reproduced by me at 4fc8a1dc26 with Node 20.20.2: `prlimit --as=2147483648 node -e 'fetch("http://127.0.0.1:9")'` prints a `node:internal/deps/undici/undici` OOM trace; the same fetch under `--as` unset, `--data=2147483648` and `--data=1073741824` settles with an ordinary "fetch failed". `Buffer.alloc(1.5e9)` dies under BOTH `--as=1G` and `--data=1G` (the data limit still bounds what a process commits). The three callers of `wrap_argv` (dispatch.py:3024, heal.py:4331, workflow.py:1909) all launch harnesses, so the fallback is wrong for every one of them.

## Target end-state
- RULED (DG1 gen 20, SM asked: skip the fallback for a node harness, or scope it into the system agi.slice): NEITHER. The prlimit fallback bounds `RLIMIT_DATA` (`prlimit --data=<bytes>`) instead of `RLIMIT_AS`. RLIMIT_DATA counts private writable mappings, the memory a process has actually committed, and not PROT_NONE reservations, so the cap still bites on a process that allocates (a runaway pi stage, a python MemoryError) and node's wasm reservation no longer dies. This answers conjunct (a)'s question without an argv-name heuristic: no caller passes a flag and mem_cap reads no argv, because the fix is in what the fallback bounds, for every argv. Skipping the cap for node would leave pi stages unbounded on a box with no user manager (the box where a cap matters), and the system agi.slice needs root or a polkit rule for a non-root launcher (not this leaf's).
- `is_cap_death` still recognises the death (an `ENOMEM` from a bounded allocation surfaces as MemoryError / "out of memory", rc 1), and its docstring and `_as_bytes`'s ("for `prlimit --as`") are corrected.
- The DH.421 comment (:379-381) is rewritten to the new rule: the fallback bounds the committed DATA of each process and nothing about the tree's width, and why it is not `--as` (V8 wasm reservation).

## Invariants
- The systemd path is byte-unchanged: `wrap_argv` returns the same argv when `systemd_run_usable`, and `cap is None` still returns the SAME argv object.
- A cap that was a bound stays a bound: an allocation past the cap dies under the fallback (rc != 0).
- No host act: this is bytes only; a stage already running keeps its limits.
