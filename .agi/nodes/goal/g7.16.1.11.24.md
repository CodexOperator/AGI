# goal:g7.16.1.11.24

## Why this exists
goal:g7.16.1.11: a post unit gives its shell AGI_SEAT only, while the box piece needs AGI_POST, so the one command a post types by hand to read its mail dies. Checked at trunk 1a63cd6f04: .agi/nodes/.geometry/engine-root.md:28 sets `Environment=... AGI_SEAT=%i` and nothing else of the name (AGI_SEAT is deprecated this season: extensions/agi/bin/geometry_config.py:57 prints that notice on every send.py call, and belam's rule below says it); .agi/nodes/.geometry/engine-post.md:180 starts the box piece with `P=${AGI_POST:?}`, so a hand `box` in any post's shell exits 'parameter not set' (TM 04:0xZ). The two wake pieces already work around it (agi-run, engine-wrap.md:26: `AGI_POST=${AGI_POST:-$AGI_SEAT}`; cccc.ts derives it the other way round on purpose, AGI_SEAT first: engine-wrap.md:43, R9 at :91), and engine-wrap.md:91 records the gap as SM mur residue R6, banked there as "a host act, banked, not this leaf": this is that leaf. It is the sibling of goal:g7.16.1.11.23 (belam's session name) in the same unit family, not a widening of it.

## Target end-state
- Every post unit's environment carries `AGI_POST=<instance name>`, the same value as `AGI_SEAT=<instance name>`, so a hand `box` and `box n` from any post's own shell find their post without an export. (A hand send needs nothing: send.py resolves the sender from AGI_AGENT_ID, then AGI_SEAT, send.py:937-950; only `box` needs AGI_POST.)
- agi-run's `AGI_POST=${AGI_POST:-$AGI_SEAT}` (engine-wrap.md:26) stays a fallback only: it never overrides a pane that already has AGI_POST. cccc.ts KEEPS AGI_SEAT first (`AGI_POST:E.AGI_SEAT||E.AGI_POST`, engine-wrap.md:43, R9 at :91) and is not flipped: flipping it reintroduces R9.
- The unit text is installed on every box by the host act from the pinned commit's bytes, so the change reaches a running post at its next unit start, not before.

## Invariants
- AGI_POST equals AGI_SEAT for one instance: they never differ in a rendered unit.
- AGI_SEAT stays in the Environment= line: other readers still read it and their derivations (`${AGI_POST:-$AGI_SEAT}`) must keep working. Removing it is a separate, later leaf.
- A kid's hand `box` / `box read` never acts as its parent. agi-kid (engine-wrap.md:68) execs with AGI_SEAT=$k and INHERITS the post env, so once the unit sets AGI_POST=%i a kid's own `box` reads the PARENT's ref and advances the parent's held ref (R9's hazard; cccc.ts's poll is covered by its AGI_SEAT-first order, a kid's hand `box` is not). Before the unit line lands, agi-kid sets AGI_POST=$k too (or unsets it). R9 rejected touching agi-kid for ITS round; this leaf reopens that as its own precondition, and the council may choose the mechanism.
- No lane may export AGI_POST itself to get green: a lane that exports it is what hid R6 while every lane was green.

## Falsifier

A lane renders the post unit text from the geometry for one instance name and reads both `AGI_SEAT=<name>` and `AGI_POST=<name>` in its Environment= line, then runs `env -i` with only that Environment= line applied and `box n` in the same pane exits without 'parameter not set'; and, in the env agi-kid builds on top of that post env (AGI_SEAT=<kid>), `box n` reads the kid's own name and not the parent's; the lane exits 0 only then (it must NOT export AGI_POST by hand).
2. Negative: `git grep -n 'AGI_POST=' -- .agi/nodes/.geometry/engine-root.md` shows no `AGI_POST=` value other than `%i`, and the rendered AGI_SEAT and AGI_POST differ for no instance name.
