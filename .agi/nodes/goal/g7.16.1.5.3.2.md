# goal:g7.16.1.5.3.2

## Why this exists
goal:g7.16.1.5.3 (complete): heal's worktree sweep archives then removes, on the invariant "a worktree with uncommitted state is never removed before its archive ref exists; no byte is lost". belam's [red] (VERIFIED signed, 18:27Z 10-07, PASS B4 on tip bdec0256c0, relayed by sanctuary-master) shows the invariant broken, confirmed in the bytes on the trunk c7d2f98f56: extensions/agi/bin/heal.py:1905 `status_lines, _ = _git(["status", "--porcelain"], wt)` discards git's return code, and _git (:1184) is best-effort (a broken git = (empty, nonzero)). A FAILED status (OOM-killed child, corrupt index) reads CLEAN: an UNMERGED a00-* tree gets needs_archive=True with dirty=[], _sweep_archive (:1675) pins HEAD only and returns verified, and `git worktree remove --force` (:2011) drops its uncommitted bytes. Live on the box since 10-01.

## Target end-state
- A worktree whose `git status` fails is REFUSED this pass: skipped, ONE named log line `[sweep] refused <id>: git status failed (rc N)`, recorded in _SWEEP_SKIP like the other refusals; never archived and never removed on a failed read.
- Same class: a failed `git rev-parse HEAD` on a tree whose gitdir still exists is refused by name, never archived or removed with head "" (the DG2.C1 orphan branch, gitdir gone, stays as it is). Measured: with an empty head and a failed status, _sweep_archive builds an empty `want` list and returns None (read as "archived") before the --force remove, so this site is NOT already safe.
- A tree whose status succeeds and is clean+merged is removed as today.

## Invariants
- No uncommitted byte is removed before its archive ref exists; a read that FAILED is never read as "nothing to archive".
- A refusal is per tree and per pass: the sweep goes on with the other trees; no tree is archived or removed on a refusal.

## Falsifier
1. A pytest (a stub _git returning ([], 128) for `status --porcelain`) on an UNMERGED dirty tree: the tree stays on disk with its bytes intact, the refused line is logged, no archive and no `worktree remove` call; the same for a failing rev-parse on a tree with a live gitdir; a control where status succeeds and the tree is clean+merged is removed as today. It exits 0 only when done, and is RED on the trunk c7d2f98f56.
2. Negative: `git grep -n 'status_lines, _ = _git' -- extensions/agi/bin/heal.py` exits 1.
