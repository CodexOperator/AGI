# goal:g7.16.1.11.20.2.1

## Why this exists
goal:g7.16.1.11.20.2 (complete): every alarm reaches its reader as signed box mail, ONE message per alarm, and 'a spool line is sent exactly once'. Its drain keeps that promise by asking, before each send, whether the seat's own out-ref already carries the line's Alarm-id (already_sent). That guard assumes an id names ONE alarm. A random id of 16 bits does not.

THE PRODUCT RISK, named: two DIFFERENT alarms to one reader in one second with the same 4 hex chars: the first is sent, so its Alarm-id is on the out-ref, and the second is SILENTLY skipped as 'sent before a crash'. An alarm the owner or a post needed never arrives, and nothing records that it was dropped. That breaks .20.2's title ('ONE message per alarm') from the other side: not doubled, but lost.
A second silence beside it (sp 03:48:07Z): `already_sent` returns False when git cannot run (OSError, a timeout) and when `git log` exits non-zero. 'Could not read the out-ref' and 'not on the out-ref' read the same, so an unreadable ref sends the alarm AGAIN, with no line. The return codes (director-goals-1 and sp, RUN 03:5xZ on a scratch repo): a ref that is ABSENT gives `git log` rc 128 and `git rev-parse --verify --quiet` rc 1; a ref that is present gives 0 and 0; a broken object store gives 128 and 128; a path that is not a repo gives rev-parse rc 128. And an absent out-ref is NORMAL: it is a seat's FIRST alarm to a reader. So `git log` rc 128 alone cannot mean 'could not read'; the absence test is rev-parse rc 1.

## Target end-state
- An alarm's random id has 64 bits: `new_id` reads `secrets.token_hex(8)`, so two alarms to one reader in one second collide with probability about 2^-64 per pair and never in practice. The deterministic `--id` (same content, same id, by design) is untouched.
- A skip is never silent. When the drain skips a line because its Alarm-id is already on the seat's out-ref, it prints ONE line on stdout, the channel the `sent` line uses: `alarm_spool: skipped <id>: already on <seat>'s out-ref`. A true duplicate (a send whose unlink never ran) is still sent once and never twice, and now a reader can see it was skipped.
- `already_sent` tells 'not found' from 'could not read', in three cases. (1) The out-ref is ABSENT (`git rev-parse --verify --quiet <ref>` exits 1): NOT FOUND. The alarm is sent, and NO could-not-read line is printed (a seat's first alarm to a reader). (2) The ref exists and `git log` finds no Alarm-id: NOT FOUND, sent. (3) The ref exists but `git log` exits non-zero, or `rev-parse` exits with anything other than 0 or 1, or git cannot run (OSError, a timeout): COULD NOT READ. The line is HELD: it stays in the spool, the drain prints ONE line naming the ref and the cause, and the next drain retries it. This is decided here, not left to the builder (alive 03:55:09Z): HOLD keeps 'a spool line is sent exactly once' true, and the cost is one drain's delay. A HELD line is NOT counted as a send retry, so a held line that was already sent never reaches the dead-letter file.
- A spool line written before the change, whose id has the old width (8 hex, a dash, 4 hex), still drains: the id is an opaque string to the drain.

## Invariants

- The skip line and the could-not-read line carry the alarm id, the seat and the ref only. No alarm text, no token, no key.
