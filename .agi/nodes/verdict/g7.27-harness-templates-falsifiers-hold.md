# verdict:g7.27-harness-templates-falsifiers-hold

## Evidence

### F1 — templates-only argv, no flag construction in rotate.py: GREEN

- `tests/test_harness_template.py:61` `::test_claude_builder_renders_frozen_argv`
  pins the PRODUCTION builder `rotate._build_claude_command` against the OLD
  hand-built argv as a LITERAL (`claude --remote-control N --permission-mode
  bypassPermissions --debug-file D.LOG [--model M] [--effort E] [--settings
  JSON] CARD`). It would catch a dropped/renamed flag in
  `templates/harness/claude-code.toml`.
- `tests/test_harness_template.py:90` `::test_copilot_builder_renders_frozen_argv`
  does the same for `rotate._build_copilot_command` and
  `templates/harness/copilot-cli.toml`.
- `tests/test_harness_template.py:186` `::test_claude_production_path_reaches_render`
  monkeypatches `rotate.harness_template.render` with a sentinel and asserts
  `_build_harness_command(None, ...)` RETURNS the sentinel with
  `harness_id == "claude-code"` — i.e. the production claude path goes THROUGH
  the renderer, not an inline argv.
- `tests/test_harness_dispatch_shapes.py:166`
  `::test_adapter_production_path_reaches_render_with_the_dispatch_shape`
  is the same sentinel probe on the DISPATCH side (cc/copilot adapters), for
  both shipped harnesses.
- `tests/test_harness_dispatch_shapes.py:183`
  `::test_no_flag_construction_remains_in_either_adapter_body` strips
  docstrings/comments from each adapter's `build_command` body and asserts
  none of `--output-format --strict-mcp-config --add-dir --tools
  --allowedTools --disallowedTools --mcp-config --allow-all --remote -p`
  appears in live code.

Direct read of `rotate.py` corroborates: `_build_claude_command`
(`rotate.py:896`) and `_build_copilot_command` (`rotate.py:1014`) are now thin
hooks, each a single `return harness_template.render(...)`. Neither contains a
flag literal. They are STILL DEFINED — deleting those names is
`goal:g7.27.1`'s scope, not this verdict's — so the claim "zero flag
construction inside rotate.py" holds by MEASUREMENT of the hook bodies, not by
absence of the names.

### F2 — a fourth harness adds a template without editing rotate.py: GREEN

- `tests/test_harness_template.py:133`
  `::test_synthetic_fourth_harness_renders_without_editing_rotate` writes a new
  `fake-harness.toml` into a tmp template dir, renders it, asserts the built
  argv, asserts it is in `available()`, and asserts
  `rotate._validate_harness(None, "fake-harness")[0] == 0` — accepted with no
  rotate allowlist edit.
- `tests/test_harness_template.py:162` `::test_build_harness_command_dispatches_on_template`
  asserts `rotate._build_harness_command("fake-harness", ...)` BUILDS the fake
  argv and `got[0] != "claude"` — no silent fallthrough.
- `rotate._known_harnesses()` (`rotate.py:~962`) derives the buildable set from
  the templates on disk, per the code and its docstring.

### F3 — unexpressible bits stay behind a NAMED thin hook, no scripting escape hatch: GREEN

- `tests/test_harness_template.py:152`
  `::test_template_vocabulary_has_no_scripting_escape_hatch` writes a template
  with `script = "import os"` and asserts `harness_template.load("evil")`
  raises `HarnessTemplateError` — the vocabulary is declarative and closed, so
  a template can never become a program.
- The named thin hooks are: `rotate._build_claude_command` (`rotate.py:896`)
  and `rotate._build_copilot_command` (`rotate.py:1014`), each rendering
  `templates/harness/*.toml`; and `rotate._build_harness_command`
  (`rotate.py:1032`) is the ONE dispatch seam a harness enters `spawn_window`
  through. `harness_template.render` is the only argv producer.

## Confidence

0.9 — all three falsifiers green on the named tests plus a direct read of the
two hook bodies. Residual 0.1: the "zero flag construction in rotate.py" clause
is evidenced by the frozen-literal tests and the hook bodies, not by a single
test that greps rotate.py as `test_no_flag_construction_remains_in_either_adapter_body`
greps the adapters; a future regression could add a flag literal to a
`_build_*` hook outside the arg positions those tests pin.
