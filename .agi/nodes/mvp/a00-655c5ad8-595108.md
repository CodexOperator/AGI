# mvp:a00-655c5ad8-595108

## MVP

Added a batch mode to the proven single-artifact ingest command:

```text
cli.py ingest --sessions-root <dir> --last <N> --goal <live-goal-id> --root <.agi>
```

`session_ingest.latest_artifacts` considers only immediate session directories
with `trajectory.jsonl` and an `agent.json` whose status is `done`,
`done-unreported`, or `checkpointed`. It orders them by completion/start time
with the canonical path as a deterministic tie-breaker and selects the newest
N. A short eligible set, missing metadata for a running session, and an
in-flight session therefore cannot be silently substituted for a selected
artifact.

Each selected path is passed through the existing `ingest` mechanics. Batch
identity is the stable session-directory name, not transcript bytes, so a
later checkpoint updates the same node. The explicit `--goal` is threaded to
every item and the existing resolver still requires it to resolve to one live
goal node.

## Inputs

- `--sessions-root`: directory containing `<agent-id>/trajectory.jsonl` and
  `agent.json` records.
- `--last N`: positive newest-completed count.
- `--goal`: one explicit live goal id/address, required in batch mode.
- `--root`: graph root override.

Exactly one of the positional artifact or `--sessions-root` must be supplied.

## Outputs and refusals

- One `doc:session-...` node id on stdout per successful selected artifact.
- One `REFUSED <artifact-path>: <reason>` line on stderr per failed selected
  artifact; processing continues so good artifacts still land.
- Exit 1 when any selected artifact fails; exit 2 for batch-level refusal
  (missing goal, invalid count, short selection, or ambiguous invocation).
- Running the same selection twice emits the same ids and updates rather than
  duplicates nodes.
