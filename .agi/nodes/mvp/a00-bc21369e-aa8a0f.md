# mvp:a00-bc21369e-aa8a0f

## MVP

Durable held-pane startup cleanup for `tmux_hold` plus a fast successful-exit path in production dispatch.

The implementation now:

- tracks whether `start()` created its own tmux session and kills only that session when a later tmux operation fails;
- never kills a caller-supplied restart pane;
- removes the mode-0600 `hold.json` immediately after the runner consumes it, and also removes it on held-start failure before direct-`Popen` fallback;
- accepts an already-complete rc=0 process before entering the startup grace loop.

Focused regressions in `extensions/agi/tests/test_tmux_hold.py` cover both ownership branches, runner startup failure, and rc=0 without any grace sleep. The suite passes: **6 passed**.

## Inputs

`tmux_hold.start(argv, *, env, cwd, log, mode, seat, agent_id, state_dir, pane_id=None)`, where `pane_id` distinguishes a new session from a caller-owned restart pane. `_run(spec_path)` consumes the local JSON spec.

## Outputs

A held process on success, or a cleaned-up failure that permits direct `Popen` fallback. No newly created orphan session or secret-bearing `hold.json` remains after the covered failure paths.
