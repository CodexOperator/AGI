# hypothesis:a00-429760b1-de3002

## Hypothesis

`cmd_loop` is a rotation path (`spawn_window` at the end) that, unlike
`cmd_rotate_self`, does not carry the graph↔profile drift guard. Therefore a
deliberate desync between a linked node and its profile artifact can be
silently rotated past on the loop path.

Claim: wiring `_check_profile_drift(root)` into `cmd_loop` in the same
position and shape as `cmd_rotate_self` makes the loop **refuse non-zero, by
name, before any side effect**, and the wire probe for that is a behavioural
drive of `cmd_loop` — not a source-byte grep, which stayed green when only
`cmd_rotate_self` called the guard.

Proved by:
- a drifted scratch graph: `cmd_loop` returns 1, stderr names the drifted node,
  and `spawn_window` is never reached;
- an in-sync scratch graph: the loop proceeds past the guard to `spawn_window`;
- monkeypatching `_check_profile_drift` changes `cmd_loop`'s behaviour — the
  call is live at the `cmd_loop` site.

Disproved by: the drifted drive returning 0, or reaching `spawn_window`, or
the clean drive being refused.

Child experiment: `experiment:cmd-loop-drift-guard-behavioural-wire`.
