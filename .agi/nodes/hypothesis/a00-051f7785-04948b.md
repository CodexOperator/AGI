# hypothesis:a00-051f7785-04948b

## Hypothesis

**The first production spawn and later restart should cross one durable-launch seam, rather than first spawn bypassing the hold and falling directly into `subprocess.Popen`.** When that seam is available for a persistent seat, first spawn creates and returns the seat's stable named pane, and any creation marker is derived from the actual launch result rather than stamped to repair a later restart.

## Test

Exercise the production `_open_round` path with the durable-hold seam available, then kill the seat process and restart through the same dispatch flow. No experiment may call an out-of-band hold/start helper first.

## What would prove it

All three observations hold:

1. A first-spawn launch reaches the hold/start seam; the tmux-available path does not create the persistent seat with a direct anonymous `Popen`.
2. After `kill -9`, the restarted seat resolves the same stable pane identity (pane id or stable named pane), with no manually prefounded pane.
3. A fallback `Popen` reports creation honestly (`created` is false when the hold was not the creating launch), so restart cannot invent first-spawn provenance.

## What would disprove it

Any one of these falsifies the claim: the first production launch calls `Popen` while hold is available; restart adopts a new pane identity after the seat is killed; or a fallback `Popen` is recorded as the creator of an already-existing held pane.

## Scope

This tests only the missing first-spawn handoff and provenance boundary in `goal:g7.31.1.2.2`. Environment preservation and the no-tmux fallback remain owned by sibling goals `goal:g7.31.1.2.1` and `goal:g7.31.1.2.3`.
