# hypothesis:a00-3dd96465-80b8a8

## Hypothesis

A generic, injectable durable-pane seam makes a persistent seat reattach to
the SAME named tmux pane after its process dies:

- **first launch** creates the named window and sets `remain-on-exit on`, so
  the pane survives the command's exit;
- **reattach** (`respawn-window -k -t <session>:<name>`) addresses the SAME
  window when `list-windows` already shows the name, and NEVER issues a second
  `new-window` for it;
- the seam is reached by a real engine call site, not only by its test.

The seam is `extensions/agi/bin/tmux_seat.py:ensure_pane`, wired at
`rotate._launch_window` (the ONE seat launch path) and at
`heal._launch_recovered` (the dead-seat restart path).

## Claim / falsifier

Kill the seat process; a restart through the seam reattaches to the SAME tmux
pane name (`tmux list-windows` / capture still shows the seat) with zero
`new-window` for that name.

Disproved if any of: the pane vanishes on process exit; reattach opens a
second window; the same-name branch never fires; or no production call site
reaches the seam.

## Result

**Proved** (experiment:durable-tmux-pane-reattach-a00-3dd96465). A fake-tmux
test drives the seam (4 passed) and a live tmux 3.4 private-socket probe shows
the falsifier on a real server:

    after SIGKILL:  seat-a @1 1   (pane dead, window still there)
    ensure_pane -> "respawn" rc 0
    after reattach: seat-a @1 0   (same window @1, live again, new pid)
    SAME_WINDOW_ID True; zero new-window for seat-a

## Boundaries the next round inherits

- `spawn_window` refuses an existing window name BEFORE `_launch_window`, so
  the reattach branch is reached by the recovery/restart path, not by `spawn`.
  A later round should let spawn itself reattach a dead pane (and not refuse
  it), or the reattach-to-same-pane property only holds for recovery.
- `_launch_recovered` returns an empty window @id on the respawn branch:
  tmux 3.4 `respawn-window` rejects `-P` (`unknown flag -P`).
- `remain-on-exit on` is set at first launch, so a seat that exits cleanly
  leaves a dead pane holding its name until the next restart reuses it; an
  abandoned dead pane accumulates until killed.
- Production lines 62 vs ceiling 40 (1.55x, below the 2x stop); the new
  `tmux_seat.py` is 49 of those lines.
