# hypothesis:a00-f1a63afd-090b9f

## Hypothesis

If the durable-pane seam is used by the **initial** production spawn, not only
by recovery, then `dispatch._open_round` will no longer launch persistent
harnesses as anonymous detached processes. A first successful launch will
found one deterministic, seat-scoped named tmux pane through the same
adapter/held-pane interface used later, and its returned identity will be what
the agent record names.

This is intentionally a claim about ownership of the first-launch seam, not a
claim that generic one-shot Popen is wrong. A harness declares whether it
needs a held pane; held harnesses use the pane seam, while ordinary one-shot
harnesses retain the ordinary process path.

## Mechanism

1. Persistent-harness policy selects a deterministic pane name from seat/agent
   identity, so retries and recovery address the same object.
2. Initial launch calls the held-pane start/rejoin seam once and receives the
   real process plus pane identity.
3. Dispatch records that identity only after the start succeeds; a failed
   start is an error and leaves no live-looking agent record.
4. Restart/rejoin uses the recorded identity and cannot make a new pane look
   pre-existing merely by stamping `created: true`.

## What would prove it

A production-path experiment (not a direct unit call to the holder alone):

- invoke the real initial-dispatch path with a fake persistent adapter whose
  start seam records its call and returns a real long-lived child;
- assert the start seam is called on the first launch, and direct anonymous
  `Popen` is not used for that harness;
- assert the pane id is deterministic and present in the written agent record;
- kill and rejoin, asserting the same pane id is addressed and `created` is
  not fabricated on that rejoin;
- run the covering adapter/dispatch tests.

The decisive red-first check is to remove the initial held-pane dispatch call
and observe at least the first-launch call/pane-identity assertion fail.

## What would disprove it

- The first launch bypasses the held-pane seam or still writes an anonymous
  detached pid with no pane identity.
- Pane names differ between first launch and rejoin.
- `created: true` can appear without a successful create in this call.
- The experiment only proves that `tmux_hold.start` works when called directly
  out of band, rather than proving production initial dispatch calls it.
