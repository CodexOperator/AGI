# hypothesis:a00-0168a674-0cc2db

## Hypothesis

**Held restart must sanitize the child environment before it returns the surviving tmux pane, and that exact environment must reach the pane through every hold adapter path.**

The current control flow is claimed to return from the `HOLD_PANE=True` restart branch before the normal `child_env(...)` construction. If so, a restart preserves the pane's identity but bypasses the credential policy and harness variables applied to a fresh `Popen` child.

## Testable claim

For the same seat and provider configuration, fresh spawn and held restart produce the same child-environment policy:

1. `child_env(...)` is evaluated before the held-restart early return.
2. Its result is threaded explicitly into `tmux_hold` start, reattach, and command execution; no tmux-server ambient environment is relied upon.
3. When `needs_credential` is false, `OPENROUTER_API_KEY` is absent from the environment handed to the held pane even if the dispatcher inherited it.
4. When credential is required, the selected key and all forwarded harness variables are present in that same environment.
5. The normal non-held `Popen` path remains behaviorally unchanged.

## Proof

An experiment red-first removes or bypasses the held-pane environment argument and must make the test fail. After the fix, focused tests should spy the actual hold adapter boundary and assert the complete environment map in both credential modes, plus an equality/shape check against the fresh-spawn policy. Run the adapter/dispatch tests that cover the touched files.

## Falsifier

The claim is disproved if any held start, reattach, or command path can receive no explicit sanitized environment; if tmux is allowed to inherit an unfiltered environment from its server; if the no-credential test still sees `OPENROUTER_API_KEY`; or if the normal fresh-spawn environment changes as a side effect.
