# hypothesis:a00-ffd04a24-02b8b5

## Hypothesis

The **heal/cron surface** — the live crons node's `services:` table
(persistent systemd units) plus its `cadences:` jobs — carries **no message
daemon / message-router process**. The standing L4 ruling is repo + nudge,
not a router process; `goal:g7.31.4.3` is the falsifier-3 of `goal:g7.31.4`
holding the line on that surface.

**Proved by:** a regression guard that enumerates the real surface and
reports nothing message-daemon-shaped, plus a negative control that shows
the same guard FAILS on a planted message-router entry.

**Disproved by:** any service or job on that surface named/shaped like a
message router — or the guard failing to flag a planted one.

## Inventory of the surface today (from the real bytes, this checkout)

- `services:` (the only persistent processes):
  - `agi-reaper` → `heal.py watch` (death reap + heal; not a router)
  - `agi-alarms-sanctuary-master` → `rotate.py alarms` (not a router)
- `cadences:` jobs: `grid_sync`, `branch_push`, `publish_engine`,
  `engine_push`, `mail_poll`, `nudge_sweep`, `prime_merge`.
  `mail_poll` and `nudge_sweep` run `send.py` as a **one-shot periodic
tick** (`read --box-local`, `wake --all-local`), never a long-lived
  daemon; the others are grid/push/merge ticks.
- `KNOWN_JOBS` in `crons.py` agrees with that list — no hidden command
  renders for a job outside it without an explicit `cmd`.

## Result

Negative-control command and output are recorded in
`experiment:a00-ffd04a24-daemon-guard`.

## Scope note

backstop: any new persistent process fails the suite and forces a human
review.
