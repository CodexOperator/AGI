# hypothesis:a00-3dd9eb76-eb2e65

## Hypothesis

A `profile_ref` that would be refused (resolves outside the repo root, or under
`.agi/nodes/`) is validated BEFORE `node_writer.update_node`, so a refused
`write.py` edit leaves the node byte-identical (nothing lands) and exits
non-zero naming the refusal — while the happy path is unchanged: a legal
`profile_ref` still moves the artifact bytes to the node's normalized body in
the same `write.py` action.

## What proves it

1. A scratch node declaring `profile_ref: ../escape.md`, edited through
   `write.py 'replace body ...'`, returns rc!=0 with the node file sha
   UNCHANGED and no artifact (or stray `.tmp`) written.
2. The same for a ref under `.agi/nodes/`.
3. A legal `profile_ref` plus a `write.py` edit still moves the artifact to the
   normalized body (frontmatter/THOUGHT stripped, exactly one trailing
   newline) in the same action, rc=0.
4. `pytest test_profile_sync.py test_write.py -q` is green and the no-file-write
   ast guard stays green.

## What disproves it

The node body changing on a refused ref; the happy path projecting stale or
partial bytes; a refusal that writes anything (node, artifact, or a stray
`.tmp`).

## Status

Proved on the built bytes — see experiment:profile-ref-prevalidation. The
pre-fix defect (node body changed despite rc=2) is reproduced on a byte-copy of
the unpatched `write.py`, and the patched tree leaves the node sha identical.
