# hypothesis:a00-d8d8a1f0-1137fc

## Hypothesis
Against a REAL private tmux server — never the `window_path` fixture seam —
the seat-start registry pane pin and live tmux agree:

1. `rotate._successor_window_id(seat, session, window_path=None)` returns the
   same `@id` a real `tmux list-windows -t <session> -F '#{window_id}
   #{window_name}'` reports for that seat name — the pin the spawn writer
   commits IS what tmux says.
2. `seat_status.seat_occupation(row, session, window_path=None)` reports
   `occupied` iff the row's `window` cell equals that live `@id` (and any
   positive `pid` is alive); `pane-drift` when the row pins another real
   `@id`; `unoccupied` when tmux has no window by the seat name.
3. `seat_status.collect(<real graph root>, {}, tmux_session=...,
   window_path=None)` renders `pane=occupied(<@id>)` in both renderers — the
   registry shows occupied, which is the falsifier verbatim.

**Disproved if** any live read disagrees, or if the helper only works when the
seam file is supplied.

## Result
The PANE half is proved live: `experiment:seat-pane-pin-live-tmux-witness`
passed 7 tests against a real throwaway tmux server (private `TMUX_TMPDIR`),
with both live negative controls (drift, unoccupied) and the end-to-end
`collect` render.

The falsifier's SESSION half is **not** proved and is explicitly deferred.
tmux witnesses the pane only; `session_id` / `session_name` / `session_ref`
land on the row only through the registry JOIN and a later `rotate.py ack`
back-fill, not at seat start. That is a real gap in the falsifier's wording
("pane/session pin matching tmux"), recorded rather than papered over.
