# No message daemon on the heal/cron surface: a reproducible absence-check

## Claim

## The check (data in, findings out)

Three surfaces, each a pure function that takes the data as a PARAMETER so a
caller can feed a declaration that DOES contain a message daemon and see it
flagged BY NAME:

1. `message_job_findings(jobs)` — `mail_poll`/`nudge_sweep` must be periodic
   ticks (`every_mins`/`schedule`); any message-flavoured job outside the
   closed set, or any `KNOWN_JOBS` name that is itself a daemon/router, is a
   finding.
2. `message_service_findings(services)` + `service_allowlist_findings(...)` —
   a systemd unit is long-running by construction, so any message token in its
   name or exec argv is a daemon; any service outside the reviewed
   non-message allowlist is surfaced.
3. `find_message_daemon_processes(procs)` — takes an injectable
   `(pid, comm, args)` table, matches *program-identity tokens* (basenames of
   the first few argv tokens), never a substring of the whole argv. `ps`
   appears only in `read_process_table`, never in the scanner.

(basename of the first few argv tokens) removes that false positive; the live
scan above is the after.
