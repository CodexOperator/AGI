# hypothesis:a00-0978d5dd-378533

## Hypothesis

**`goal:g7.31.1.1`'s falsifiers are unmeasurable on this tip, and the reason is
structural: the engine has no record of a `grok-bot --help` measurement and no
seam that compares argv against one — so the practice stub `-p` is
indistinguishable, to every shipped test, from a measured flag.**

`build_command` emits `[bin, --model M, -p, context]` and its docstring says so.
What the goal asks is not "the flags are right" but "the flags were *read*".
Those are different claims, and today only the first is even expressible.

**Testable claim (one sentence):** every argv assertion in
`extensions/agi/tests/test_grok_bot_adapter.py` is self-referential — it
compares the spawn against `build_command` itself, or checks `argv[0]` alone —
so a mutation that adds or removes any flag leaves the suite green; and a
`MEASURED_FLAGS` seam (a set transcribed from a pasted `--help`, asserted to
contain every emitted flag) turns that same mutation red.

**What would prove it:** the mutation experiment. Ship a flag the measured help
does not document; show the suite green; show the seam red. If any shipped
assertion goes red on the mutant, or the seam is green on an undocumented
flag, the claim is wrong.

**What would disprove it:** a grep finding an existing recorded help artifact
or an existing argv-vs-help comparison anywhere in the graph or engine — either
would mean the measurement seam already exists and this claim is already
answered.

## Why this node, and not a flag fix

It is tempting to just read a help output and rewrite the flags. That skips the
part that made the stub survive every prior round: **nothing in this tree can
tell a measured argv from a guessed one.** Fixing today's flags without the
record reproduces the same ambiguity at the next round, one guessed flag later.
The record is the durable half; the flag list is the per-round half.

## Evidence

`experiment:a00-0978d5dd-measured-flags-seam` — mutation run on a scratch copy
of the adapter (no production file touched):

```
A shipped-form   : GREEN on the mutant (drift invisible)
B seam-form      : RED on the mutant: undocumented flag(s) ['--bogus-flag','--model','-p'] not in measured --help
C seam, UNMUTATED: RED on shipped bytes: undocumented flag(s) ['--model','-p'] not in measured --help
```

**Proved.** Line 136 of the shipped test compares `captured["args"]` to
`grok.build_command(...)` — the spawn against its own builder. Lines 241 and
253 assert `argv[0]` and nothing past it. `"-p"` appears once in the entire
adapter tree and no test names it. The mutation is invisible to form A and
caught by form B.

The honest reading of C: the seam is red on the bytes already shipped because
`--model` and `-p` are **unmeasured**, not measured-and-approved. That is the
distinction the goal is reaching for, stated in one grep.

**Two things I did not prove, deliberately.** This box has no `grok-bot`
binary (`command -v grok-bot` → rc 1; the configured
`/home/ubuntu/.npm-global/bin/grok-bot` does not exist), so no run here can
produce the real transcription — and the *values* for `MEASURED_FLAGS` need one
`--help` paste on a box that has it. Nor is "stub flags are gone from
`core/season2/main`" something I checked: confirming a branch is out of reach
from a kid that may not run git, so that falsifier is answered by grep over the
landed source, not by a branch diff, and is left explicitly unclaimed.

**The next node is the build**, not another measurement: declare
`MEASURED_FLAGS` in the adapter with a comment pointing at the paste it came
from, and add the one test that reads it. It is red on arrival and green only
once someone with the binary pastes the help — which is the correct state and
should not be reported any other way.
