## Hypothesis (claim under test)

First spawn founds the named held pane — not only restart; production does not
stamp `created=true` fabrication on the first restart after anonymous `Popen`.

Falsifier: the first-spawn path under production `_open_round` uses the
hold/start seam, with a stable `pane_id` across `kill -9` and **no out-of-band
`tmux_hold.start()` call from the experiment**.

## What I ran (an experiment, not a re-read)

`extensions/agi/bin/dispatch.py:2651` defines `def _open_round(mode: str)` inside
`main()` (line 1505), inside a `For` at 2251 — it is a closure over
`spawn_args` / `spawn_env` / `log_file` / `branch_root` / `mem_cap`.

Reaching it live costs a paid agent spawn, so I did the documented
**static-wire probe**, and made the "real" part as real as it can be:

* the executed code object is **lifted by AST from `dispatch.py` itself**
  (`ast.get_source_segment`) — not a re-typed copy, not a paraphrase;
* it is compiled and executed with a namespace where `subprocess.Popen` is a
  recording shim that forwards to the **real** `subprocess.Popen` with the
  **same kwargs** (only `argv` is substituted `["sleep","600"]` for the paid
  agent argv), and `mem_cap.wrap_argv` is identity;
* the child really starts and is really `kill -9`'d;
* **`PATH` is shimmed with a logging `tmux`**, so any tmux call made *by the
  production code path* is recorded whether or not it is greppable in source.

## Finding

**The falsifier is not satisfied — the first-spawn path founds no named pane.**
`start_new_session=True` gives the child its own session id and nothing else;
there is no pane, no name, no id that survives, and the child is simply gone
after `kill -9`. The near-miss the parent warned about did **not** happen here:
this probe never created a pane. It only *listed* panes; the identical before /
after sets are the evidence that the production spawn created nothing.

The parent's static belief is **confirmed by execution**, not merely re-read:
`find . -name 'tmux_hold*'` → empty, and no `tmux` string inside `_open_round`.

## An extra datum the parent did not have

The environment *does* have named hold panes — but they are named
`agi-hold-director-belam-a00-<8hex>` and belong to **director seats**, one per
director agent id. `grep -rn 'agi-hold' extensions/` → **no hits**; the string
is in no `.py`/`.sh` in this tree. So the hold seam exists in the *box*, for
the director tier, and is created by something outside this checkout — while the
**kid first-spawn path has no seam at all**. That sharpens the gap: the next
build has to bring the director-side hold down into `main()`'s first spawn, not
invent it.

## Three things this probe could NOT prove

1. **Not a live agent round.** argv was `sleep`, so a real agent spawn was never
   exercised; a harness that only breaks on a real adapter's argv is untested.
2. **Not the restart path.** `_open_round` is called again on a transient-death
   retry in the same `main()`; I called it once. Whether a restart stamps
   `created=true` is **unmeasured here** — the second half of the claim is
   still open, and it is where a `created=true` fabrication would actually
   live (a stamp in the registration step, not in `_open_round`).
3. **Not the whole first-spawn path.** I executed the closure, not `main()`.
   Anything `main()` does *around* the spawn — a pane it founds before
   `_open_round`, or an identity it derives from a tmux window name
   (`dispatch.py:2550`, `:2772` mention tmux window names as a fallback) — is
   outside what this probe can see.
