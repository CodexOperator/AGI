# hypothesis:a00-0acd992f-781f14

## Hypothesis

A node file that cannot be parsed but whose raw frontmatter bytes carry
`profile_ref:` cannot be proven profile-in-sync, and must be surfaced by
`profile_sync.check_all` as a named `unreadable` failure — never silently
skipped. This holds for BOTH malformed-frontmatter shapes:

1. a frontmatter block that opens `---`, is closed, but whose YAML is invalid;
2. a frontmatter block that opens `---` and is **never closed** (no body
   boundary exists, so the whole raw text is the intended frontmatter).

The residue-5 tightening (`\A---\s*\n(.*?)\n---`, `goal:g7.31.5.3`) kept only
shape (1): it required a closing delimiter, so an unclosed file returned `""`
and was dropped from the sweep — a regression of the DH.48 invariant (an
unparseable file whose raw bytes carry `profile_ref:` cannot be proven in sync).

**Claim.** `_raw_profile_ref` must distinguish three shapes: a closed
frontmatter block (search that block only — body prose is not a link), an
unclosed opening `---` (whole raw text is frontmatter, so a `profile_ref:`
line there IS a hint), and no frontmatter at all (no hint). Under that
partition, an unclosed file with a hint surfaces as `unreadable`; one without
a hint is a clean no-op.

**Prove it.** A scratch repo holding an in-sync linked node plus an unclosed
file carrying `profile_ref:` must make `profile_sync.py --all` exit 1 and name
the path `UNREADABLE`, and `rotate._check_profile_drift` must refuse naming
it. The control — unclosed file with NO `profile_ref:` — stays green (exit 0,
file skipped, guard `None`). The existing body-prose test stays green.

**Disprove it.** The unclosed file still vanishes from `check_all`, or `--all`
exits 0 on the P4 shape.

## Agent Notes
Fixed _raw_profile_ref to partition closed / unclosed-opening / no-frontmatter shapes, so an unclosed-frontmatter file carrying profile_ref surfaces as a named unreadable failure (P4 regression) while a no-hint unclosed file stays a clean no-op; 18 production lines, 22 tests pass.
