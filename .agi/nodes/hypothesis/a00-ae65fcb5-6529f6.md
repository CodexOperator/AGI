# hypothesis:a00-ae65fcb5-6529f6

## Hypothesis

Adding the opt-in persistent dispatch mode will not change any non-persistent kid/parent spawn's observable contract: the dry-run argv (including argument order and absence of persistent-only flags), return behavior, and fire-and-forget lifecycle remain identical to the pre-change behavior. The test should compare a recorded non-persistent dispatch dry-run before and after the persistent-mode implementation, and should include a deliberate omission of `--persistent`; a difference in any captured field disproves the claim.

## Why this matters

Persistent seats are a new lifecycle path, but the safe rollout depends on the default path remaining a pure compatibility extension. A regression here would silently change existing kid/parent dispatch even when the new feature is unused.

## Falsifier

A byte-level argv or lifecycle difference in the non-persistent dry-run, or a changed default for a dispatch that omits `--persistent`, disproves the hypothesis.
