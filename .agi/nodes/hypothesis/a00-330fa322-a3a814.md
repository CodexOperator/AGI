# hypothesis:a00-330fa322-a3a814

## Hypothesis

`send.py send <to> <text>` (and `send.py wake <to>`) can produce the SAME
caller-facing result for a local-box seat and a foreign-box seat while every
transport branch lives inside ONE internal resolver — so the caller never
passes `is_ssh` or tests `foreign`. A foreign seat whose town declares a mesh
`location` gets the SAME wake token typed on its own box through `ssh <alias>
tmux send-keys`; a foreign seat with no alias gets NO wake but ONE named
`mail_poll delivers the inbox` line instead of today's silent refusal, the
inbox block having already landed either way.

**Proved** when: a local send types the token on bare tmux; the identical
send call against a foreign mesh row reaches a faked remote transport carrying
the token and never the body; a foreign no-mesh row still exits success, types
nothing, attempts no ssh, and names the fallback; and grepping the diff shows no
`is_ssh`/transport branch at any `send`/`wake` call site and no new daemon.

**Disproved** when: the transport decision has to leak to the caller (a
`foreign`/`is_ssh` test appears at the call site), or the no-mesh case goes
silent, or the body reaches the transport instead of the token.

This node's experiment is `experiment:a00-330fa322-mesh-transport`; the ship
claim is conditional on the remote half being proven with fakes, not on a live
mesh run.
