## Hypothesis

The whole-graph profile drift guard (`_check_profile_drift`, wired into
`cmd_rotate_self` by DH.48) also reaches **every** rotation path, in
particular the super-ralph primitive `cmd_loop`. A deliberate graph↔profile
desync must make `cmd_loop` refuse non-zero, naming the offending node,
**before any side effect — including the successor `spawn_window`** — and
an in-sync graph must remain a clean no-op on the same path.

This is testable without speculating: (a) `--all`/the guard names the desynced
node; (b) the real `cmd_loop` returns 1 and never calls a monkeypatched
`spawn_window`; (c) the same `cmd_loop`, graph in sync, reaches the stub
exactly once. It is disproved if `cmd_loop` spawns a successor while a linked
node is drifted, or refuses a clean graph.

branch guard and before the meter/spawn. On drift it prints
`rotate refused: profile drift — ...` and returns 1 with `spawn_window` never
called; on a clean graph it reaches the spawn exactly as before. The
source-string wire assertion residue is replaced by a behavioural probe on the
real call site. Residues 5 (frontmatter-only raw hint) and 6 (unreadable on an
unguarded raw read) are fixed; residue 4 (`cmd_spawn`) is documented as the
raw-launcher exception rather than double-guarded.
