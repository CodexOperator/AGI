# hypothesis:a00-b38510a1-e28c27

## Hypothesis

`extensions/agi/bin/magic_pane.py` is the magic-pane messaging seam: ONE
module, exactly two transport routes, chosen from the DESTINATION harness
family with the same-harness set held as data (`NATIVE_HARNESSES`), never an
`if harness == "grok"` soup.

- **SAME-HARNESS (grok -> grok):** `send_message` types the message DIRECTLY
  into the destination seat's tmux pane (literal `send-keys -l`, pause, then a
  SEPARATE Enter). This route never invokes `send.py` or its transport, and the
  module does not import it.
- **CROSS-HARNESS (grok -> claude / pi):** `send_message` FIRST writes a
  `.nudge` artifact under the sessions comms root
  (`sessions/comms/pane-nudge/<seat>.nudge`), THEN invokes
  `send.py send <to> <text> --from <sender>` as a subprocess.

### Testable claim (three conjuncts)

1. **NATIVE.** With a faked tmux, a grok->grok call produces exactly
   `tmux send-keys -l -t agi-rc:<seat> <text>` then
   `tmux send-keys -t agi-rc:<seat> Enter`; no captured argv contains
   `send.py`, no artifact is written, and the module source carries no
   send.py import.
2. **CROSS.** With a faked send.py seam, a grok->claude / grok->pi call writes
   the nudge artifact file AND the captured argv contains the send.py
   invocation -- one trace, both events, artifact on disk BEFORE the
   subprocess is launched.
3. **IMPORT GRAPH.** After `import magic_pane`, `rotate` / `dispatch` are not
   reachable: a source grep finds no such import, and a fresh interpreter
   loading the module has neither in `sys.modules`.

### Disproof

Any conjunct failing: a native argv smuggling `send.py`, an artifact written
after (or absent at) the send.py call, or a transitive rotate/dispatch import.
