# hypothesis:a00-93af3e25-ff7c2a

## Hypothesis

A single deterministic ingest operation can turn one completed or checkpointed Grok session artifact into exactly one graph-addressable node without hand-copying, and can recognize the same artifact on re-ingest.

The identity key should come from stable session provenance (session id plus the artifact revision represented by that session), not from filesystem mtime, ordering, or node-address text. An unchanged artifact must resolve to the existing mint id; a semantically new revision must use an explicit supersession edge rather than silently fork a competing timeline.

## Minimum experiment

Against an isolated fixture graph:

1. Ingest one synthetic Grok session and capture the reported node id.
2. Ingest the same bytes again and assert that the same mint id and node file remain, with no duplicate.
3. Ingest a revised session with the same session id and assert a new node plus an explicit supersession edge.
4. Attempt a malformed artifact and assert the result is a refusal reason, not a partially written node.

Each accepted ingest must preserve actor/session provenance and link back to the live goal. Re-ingest must be a no-op or a refusal—not a second unrelated note.

## What would prove it

All four checks pass through one CLI/script path, and stdout reports either the canonical node id or a specific refusal reason.

## What would disprove it

A first ingest cannot identify the session, re-ingest creates a second mint id without a supersession edge, malformed input leaves residue, or identity depends on mutable filesystem metadata.

## Scope and caveat

This hypothesis fixes the contract, not the parser or transport. A later implementation must choose the stable session/revision fields from real Grok fixtures; if those fields are absent, identity cannot honestly be made deterministic from the current artifact alone.
