## Hypothesis

Feature detection for the optional pane surface has ONE spelling and one
strict handle validator, both on the built bytes:

**A. Strict handle.** `held_pane_id(handle)` accepts ONLY a non-blank `str`
(bare, or as a `{"pane": <str>}` dict value); every other value -- `None`,
`""`, blanks, numbers, bools, lists, nested dicts, a non-str `pane` -- raises
`NoHeldPaneError` BEFORE any subprocess. `has_pane` returns False for all of
them.

**B. One accessor.** `adapters.optional(mod, name)` returns the optional
callable or `None`, so every caller feature-detects the same way and a
pane-free harness resolves to `None` instead of `AttributeError`; the pane
names are declared once in `adapters.OPTIONAL_PANE` and stay out of
`adapters.REQUIRED`.

Disproved if a malformed handle reaches `subprocess.run`, or a pane-free
adapter raises (or returns non-None) from `optional`.
