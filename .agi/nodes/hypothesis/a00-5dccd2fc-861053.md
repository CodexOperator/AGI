# hypothesis:a00-5dccd2fc-861053

## Hypothesis

A single public `deliver(from_harness, to_harness, ...)` entrypoint can
enforce the messaging contract by calling `route()` and selecting transport from
that decision alone: equal non-empty harness names use the native path, while
different names use the nudge plus `send.py` path. The routing decision must not
be duplicated in either transport, and the same-harness branch must never invoke
the cross-harness transport (or the reverse).

## Testable claim

Given spies for `route`, native transport, and `send.py` transport, a same-harness
`deliver()` call produces a native spy and no send spy; a cross-harness call
produces a send spy and no native spy. In both cases the transport's observed
decision matches `route()`'s return value.

## Falsifier

The claim is disproved if `deliver()` can be called with a route decision for one
transport and execute the other, if either transport can choose independently of
`route()`, or if the equality comparison uses harness-name special cases rather
than string equality alone. A live pane is not required; spies and return values
are sufficient to test the gate.

## Scope and next step

This is a small design claim, not a request to implement the adapter. A following
experiment should instantiate a minimal `deliver`/route seam and assert the two
transport outcomes, then measure whether the result remains true when the
transport implementations are replaced by inert fakes.
