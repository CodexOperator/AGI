# hypothesis:a00-04db36d2-49d095

## Hypothesis

**A small harness-neutral ingest boundary can turn a completed or checkpointed
Grok Bot session artifact into exactly one graph-addressable residue node, and
re-ingesting those same bytes must converge on that same node rather than
forking mint ids.**

### Why this shape

`goal:g7.32.1` names the missing pipe, not a particular parser or CLI.  The
existing `grok_bot_adapter.py` owns process argv, liveness, and restart, but
has no session-artifact read or node-write surface.  Therefore the smallest
useful hypothesis keeps harness detection and graph mutation outside the
adapter: ingest takes an explicit artifact path plus a validated parent id,
and Grok-specific recognition is a capability/config concern rather than a
special case in dispatch or rotate.

### Contract to test

```
artifact bytes + harness id + parent goal
             │ validate
             ▼
 canonical residue key (harness, native session id, source digest)
             │ write-if-absent / explicit supersession
             ▼
 graph node (mint id, parents, provenance, source ref)
```

A residue carries the native Grok session id, source artifact path or immutable
reference, content digest, actor, `thought_session`, and the supplied live-goal
edge.  Its body may summarize or point to the transcript; it must not silently
invent a parent.  Batch selection (“last N”) belongs to the caller, while the
ingest function itself accepts one artifact and has one observable outcome:
**created**, **already-present**, or **refused with a named reason**.

### Proves

1. A synthetic completed-session fixture creates a node and prints its graph
   id; the file exists and its parent/provenance fields match the input.
2. Re-ingest returns the same graph id and leaves the node count unchanged.
3. A checkpointed fixture is accepted; a running/unknown fixture is refused
   with its state named and writes nothing.
4. The same native session id with changed bytes is explicit supersession, not
   a second unrelated residue.
5. An existing adapter test still passes, while dispatch and rotate gain zero
   Grok-specific branches.

### Disproves

Any silent drop, duplicate mint on identical re-ingest, ambiguous treatment of
changed bytes, parent fabrication, or necessity to embed Grok recognition in
`dispatch.py` / `rotate.py`.

### Next experiment boundary

Build a fixture-only command/API and a focused test file.  Do not yet automate
remote session discovery or batch scheduling; those are separate claims once
the one-artifact atomicity contract is measured.
