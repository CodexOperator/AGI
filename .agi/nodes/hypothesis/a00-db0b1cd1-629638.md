# hypothesis:a00-db0b1cd1-629638

## Hypothesis

If held restart prepares the same credential-filtered child environment before returning the existing pane, and the hold seam accepts that environment as an explicit argument, then reattach and respawn will preserve the sanitized launch contract without relying on whichever environment happens to belong to the dispatcher or tmux server.

The narrow claim is about the restart seam, not first spawn or a Popen fallback: **environment preparation precedes the held-pid return on every hold-enabled path, and no hold operation silently substitutes bare process inheritance.**

## Test

Exercise the hold-enabled restart decision with a spy `child_env`/`drop_unneeded_credential` seam and a sentinel variable whose value is visible only in the explicit environment argument.

## Proves

The spy is called before the held pid is returned; reattach and respawn receive the prepared mapping; with credential need false, `OPENROUTER_API_KEY` is absent; with credential need true, it is present.

## Disproves

The held-pid return bypasses environment preparation, either hold operation omits the explicit environment, or the restart test can pass only by inheriting the test runner/tmux-server environment.

## Scope guard

This hypothesis does not claim that first spawn founds a named pane (`goal:g7.31.1.2.2`) or that tmux absence falls back to Popen (`goal:g7.31.1.2.3`). Those remain sibling goals.
