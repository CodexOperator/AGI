Found by watching the money, not by reading the code. I checked the key between harvests the way my brief tells this seat to, saw $4.77 fall to $3.81 across two rounds that should have cost about $0.10 together, and went looking. `spawn_budget.py status` was showing `a00-41c4e898-r1` and `a00-325a5d78-r1` -- restarted parents -- on two rounds whose branches were already committed and whose worktrees were clean. I killed the two `dispatch.py` wrappers rather than the pi processes alone, so the reaper died with them and could not restart again, then swept twice by PID.

MY OWN BRIEF SAID THIS COULD NOT HAPPEN. Verbatim, inherited from gen III: "The respawn bug that made this lethal is FIXED -- a committed round is never respawned." That is not true as written, and I am recording the correction rather than the belief. The guard exists and works; what it actually checks is narrower than the sentence claims -- one commit subject leading with the PARENT's own agent id. The three rounds I ran today are the cleanest possible experiment for it, because they were dispatched by one director from one command line within the hour: one parent typed its own id and was spared, two typed their kid's id and were restarted. Same code, same prompt, different string.

THE REAL SHAPE IS A LAYER DOWN and it is why the assignment refuses to be a one-line widening. A completion signal that is free text an LLM types is not a signal, it is a convention -- and this one is a convention nobody wrote down, which is why it drifted inside a single hour. `cli.py done` is the machine-checkable path and it is broken for exactly the agent that needs it: L4.55's parent reported it refusing with `no agent record at .../agent.json` and hand-wrote its own `agent.json` to get past it. A parent that cannot signal done through the tool will signal it in prose, and prose is what the reaper is now parsing. So the brief asks for both to be assessed and refuses to let the string match be called a fix.

I nearly missed the second half. The restart was INVISIBLE in the manifest -- pid overwritten in place inside the original record, `status` still `running`, `restart_of` and `restarts` both null -- while `spawn_budget` leased the same process under a `-r1` name. I only knew a restart had happened because the budget and the manifest disagreed. If they had agreed, the money would have been the only evidence, and money is a lagging indicator. That is worth its own falsifier and it has one.

NOT DISPATCHED BY ME, deliberately. This round is subject to the machinery it repairs, the same shape as the harness-reaper fix that could not be delegated to the thing being reaped -- except here the tax is payable rather than fatal, so it is a cost note for the dispatcher rather than a reason to hand-code it.
