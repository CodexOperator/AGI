**A transport module can be sufficient on its own.** `send.py`'s delivery leg
can be made to admit a new transport by *dropping a module into a directory*
— no edit to the selection loop and no import added to `send.py` — if one
directory-scan loader at startup imports every module there and lets it
register itself, and if the built-in file/pane-nudge transports move out of
`send.py` into such a module.

**Proved by:** a test that writes a brand-new module into a temp transport
dir, points the loader at it, and shows `send()` delivers through it with
`send.py` unchanged; the built-in `default` delivery present at import while
`def _deliver_default` is gone from `send.py`.

**Disproved by:** a new module only being reachable after an edit to
`send.py` (a new import or a new row in the selection loop), or a change in
what the built-in path writes.
