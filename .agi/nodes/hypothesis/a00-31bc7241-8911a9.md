# hypothesis:a00-31bc7241-8911a9

## Hypothesis

`probes` is declared in both the hypothesis and experiment field lists, but its
runtime type is not currently enforced by either schema's `validation.types`.
The schema registry is the right place to close that gap: adding `probes: list`
to both schemas should make a scalar value a validation error, while a list
remains valid.

This is deliberately narrower than claiming that `links.py schema` proves the
rule. That reader checks required fields and cannot observe a `validation.types`
entry; a registry-level negative case is needed.

## Acceptance probes

- Validate a temporary hypothesis with `probes: "not a list"` using the
  schema-registry validator: expect a `types:probes` violation.
- Validate the same node with a list-valued `probes`: expect no new type
  violation.
- Repeat the negative/positive pair for an experiment node, since both schemas
  declare the field independently.
- Confirm the existing corpus does not gain a new `types:probes` violation;
  if it does, the change must be reported rather than applied blindly.

## Disproof

Disprove the claim if the registry validator accepts scalar `probes` despite
`probes: list`, or if adding the rule produces a new live-corpus violation. A
`links.py schema` count alone is not evidence either way.
