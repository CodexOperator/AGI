## Hypothesis

The mesh transport (`goal:g7.31.4`) is correct on the built bytes once four
corrective conjuncts hold — each closed by a committed test that fails on the
pre-fix bytes:

(1) **Remote-shell quoting.** `_send_keys` builds the remote side as ONE
   command string and `shlex.quote`s every remote-side argument, so `ssh` (which
   joins its trailing argv with single spaces) and the REMOTE shell reconstruct
   exactly `["tmux","send-keys","-l","-t",target,text]`. Local calls are
   byte-identical (argv straight to tmux, no shell).
(2) **Foreign wake gates.** `wake()`'s non-local branch passes the SAME
   `_seat_has_pending` and `_announced_digest` / `_nudge_marker_stale` gates as
   the local path, and records `_record_announced` after a successful mesh
   delivery — so heal's every-seat every-poll wake never retypes an unchanged
   foreign state.
(3) **Transport-independent marker coalesce.** `_nudge_mesh` applies the marker
   coalesce window (a double send inside 30s types once); the pane-read guards
   (`_leave_copy_mode`, `_capture_pane`/`_nudge_coalesce_reason`,
   `_registry_status(pid)`, `_window_id_listed`) are IMPOSSIBLE remotely and are
   skipped BY NAME, never faked.
(4) **ssh-first conftest guard.** `conftest._guarded_run` answers any ssh-first
   argv with the same safe rc-1 `CompletedProcess`, so a mesh argv cannot reach
   a real host in a test that did not fake subprocess.

**Proved when:** the four committed tests pass on the built bytes and each
fails (or is demonstrably red) on the pre-fix bytes.

**Disproved when:** any test fails, or a `foreign`/`is_ssh` branch leaks to a
`send`/`wake` call site, or local (`prefix`-empty) argv changes bytes.
