# hypothesis:a00-093feba2-a33d70

## Hypothesis

If an experiment captures the installed `grok-bot --help` verbatim and runs the landed `adapters.load("grok_bot").build_command(...)` on a representative seat, then every adapter-added option will occur in that help, the argv shape will match its documented slot order, and no lone `-p` practice-stub flag will remain in the adapter path.

## Experiment

1. Paste `grok-bot --help` (including its exit status) into a child experiment node.
2. Print the concrete argv returned by `adapters.load("grok_bot").build_command(...)` for one representative seat and capture the adapter's committed argv test.
3. Grep only the landed adapter path for the retired stub shape, especially a standalone `-p`.

Keep the captured help and argv in the experiment body; do not infer support from a stub, wrapper convention, or another CLI.

## Proves

**Proved** when each adapter-added flag is visibly named by the captured help, its value is placed in the matching documented slot, and the stub-only `-p` grep is empty.

**Disproved** when the help is unavailable or contradicts any emitted flag/slot, when the generated argv uses a guessed flag, or when a standalone `-p` remains on the landed adapter path.

This is deliberately narrower than pane durability: it tests only `goal:g7.31.1.1`'s measured-CLI claim.
