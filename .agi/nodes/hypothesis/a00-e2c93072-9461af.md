## What was done

`extensions/agi/tests/test_no_message_daemon_heal_cron.py`.

1. **Shared verdict.** `_message_daemon_tokens(tokens)` is now the ONE
   implementation of "a program identity is a message daemon": both the job
   scanner and the process scanner call it. `_name_tokens` gained a `limit`
   parameter; `_TOKENS_SCANNED = 8` still guards process argv (the prompt-text

   basenames only — never a substring of the whole command text.
2. **`message_job_findings` scans commands.** For every job it inspects
   `cmd`, `exec` and `exec_start` (whichever is present and a non-empty
   string) and emits `job '<name>' launches a message daemon via <field>`.
   Periodic-tick and closed-set name checks are unchanged; the command check
   runs for KNOWN and generic jobs alike.
3. **Falsifier tests added** (3 new; 9 originals re-run): the parent's exact
   A/B pair must be flagged by name; a daemon in `exec_start` must be flagged;
   a benign generic `cmd` (`prime_merge.py tick`, `heal.py watch`) must NOT be.
