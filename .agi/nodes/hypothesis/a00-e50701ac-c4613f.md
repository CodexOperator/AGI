# Live tmux end-to-end: the seat pane pin, not the seam

## Hypothesis

Driving the REAL `/usr/bin/tmux` binary through
`rotate._successor_window_id(..., window_path=None)` — the subprocess
`tmux list-windows` arm, never a `window_path` fixture file — a seat row
reads `occupied` iff its `window` cell is the live `@id` tmux names for that
seat and its `pid` is alive. A killed window reads `unoccupied`, a stale pin
reads `pane-drift`, and a seated `cmd_spawn` with `window_path=None` lands the
live `@id` in the registry row.

This closes the ONE caveat recorded on experiment:seat-occupation-view,
verbatim: *"the seam is `window_path` … not a live `tmux` binary. The live
tmux path is exercised only through the fail-open branch."* The parent
falsifier says `tmux`; this node measures `tmux`.

## What would prove it

A private tmux server (fresh `TMUX_TMPDIR`, default socket, unique session)
whose window is created with the real binary: `seat_occupation(row, session,
None)` returns `occupied`/`live == @id`/`pid_alive True`; a spy on
`subprocess.run` shows the production branch IS the `tmux list-windows`
subprocess; `kill-window` flips the SAME call to `unoccupied`; a stale pin
reads `pane-drift` and a drift string naming the seat; and `cmd_spawn` with
`window_path=None` writes the live `@id` into `seats.md`.

## What would disprove it

Any state that could be produced by the `window_path` seam rather than a real
tmux client (subprocess spy empty, or result independent of the live server);
a killed window still reading `occupied`; a stale pin joining by substring; or
a registry row carrying an `@id` tmux does not have.
