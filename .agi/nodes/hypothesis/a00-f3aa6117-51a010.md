# hypothesis:a00-f3aa6117-51a010

## Hypothesis

**Claim.** `grok_bot_adapter.build_command` can emit a *measured* invocation —
the bare resolved `grok-bot` bin — and can retire its guessed stub flags
(`--model`, `-p`) without breaking the REQUIRED adapter surface, the tier
contract, or the restart respawn.

**Why now.** The landed adapter (sha256 `66b7891f…081c`) emitted
`[bin, "--model", <tier model>, "-p", <context_file>]`, which was never read
against the real harness. `goal:g7.31.1.1` owns the measured-CLI falsifier:
argv must match a recorded `grok-bot --help`, and stub-only guesses must be gone.

**Prove it by.** Installing the published package `grok-bot-cli@0.3.1` into a
scratch dir, running `grok-bot --help`, pasting the verbatim output into the
child experiment, and binding a test to it: every `-`-prefixed argv token must
appear in the recorded help, `-p`/`--model` must be absent, and argv[0] must be
the resolved bin. `pytest test_grok_bot_adapter.py` stays green.

**Disprove it by.** The recorded help containing `-p` or `--model` (then the
stub was right and the flags return), or any changed test failing, or argv[0]
not being the config `bin` cell.

**Bound.** The box has no installed `grok-bot` binary, so the measurement is
against the published npm package, not the box path; version drift is real —
`latest` (0.9.0) and 0.8.0 print no help (bundled TUI), so 0.3.1 is the last
version publishing static help. That bound is recorded, not hidden.
