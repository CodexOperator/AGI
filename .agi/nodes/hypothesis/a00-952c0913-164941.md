# hypothesis:a00-952c0913-164941

## Hypothesis

A held restart can be made safe without duplicating environment policy by treating the computed `child_env(...)` mapping as the explicit input to every hold-helper operation (start, respawn, and reattach). A focused test seam should prove that the held pane receives the same scrubbed mapping as the direct `Popen` path, including omission of `OPENROUTER_API_KEY` when `needs_credential` is false and preservation of harness-provided keys.

## Test

Inspect the hold-helper API and add a small unit test that spies on the environment handoff across a held restart. The claim is disproved if any hold operation can return or respawn without an explicit environment, or if the held path differs from `child_env` on either the forbidden inherited key or a harness key. The claim is proved only when that spy passes on the built bytes.

## Scope

This is a testable design seam for `goal:g7.31.1.2.1`; it does not yet assert that the implementation currently satisfies it. The expected falsifier is a hold-helper signature that accepts only pid/session/command, or a respawn that constructs its environment from the tmux server rather than the dispatcher's computed mapping.
