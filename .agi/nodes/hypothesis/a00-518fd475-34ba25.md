# hypothesis:a00-518fd475-34ba25

## Hypothesis

The first production spawn in `dispatch._open_round` should use the same
named-pane hold seam as restart, rather than calling anonymous `Popen`. The
seat's pane id must be derived once and recorded by the production launch
path, so a later restart can reattach without an out-of-band
`tmux_hold.start()` call. A restart must not invent `created=true` merely to
compensate for a launch that bypassed the hold.

## Test

Exercise `_open_round` with a fake adapter and a fake hold/start seam, then
simulate the first seat death and adapter restart. Assert that the first call
already created and named the pane, the same pane id is supplied on restart,
and the restart record does not fabricate `created=true`. Also assert that the
anonymous-`Popen` branch is unreachable for a configured persistent seat.

## Falsifier

The claim is disproved if a first configured persistent spawn reaches `Popen`
without the named hold seam, if restart chooses a different pane id, or if
restart marks a pane as newly created solely because the first launch lacked
hold metadata. Any of those outcomes reproduces the defect targeted by
`goal:g7.31.1.2.2`.

## Scope

This is a seam-level hypothesis: it names the production ordering and metadata
invariants, without prescribing the UI or the exact tmux command. The next
experiment should add the smallest fake-adapter test around `_open_round` and
run the existing dispatch tests alongside it.
