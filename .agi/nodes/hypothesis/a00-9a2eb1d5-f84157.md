## Hypothesis

Two open residues of the graph -> profile projection (`goal:g7.31.5.1`) can
turn into named, verifiable behaviour on the built bytes:

1. `profile_sync.py <missing-node>` refuses by NAME (the id is in the
   message) and exits 2 with no traceback and no artifact — never an
   uncaught `FileNotFoundError` from `project()`'s lookup.
2. A node carrying an INVALID `profile_ref` (outside the repo, under
   `.agi/nodes/`, or a directory) is refused BEFORE the graph body write
   lands, so a non-zero exit means the node bytes on disk are UNCHANGED and
   no artifact exists. Pre-flight refusal is the chosen branch: the graph
   never advances ahead of a projection it cannot write.

The invariant: graph is SoT, artifact is a projection, and on any non-zero
exit the two cannot disagree.

## What would prove it

1. Missing node: `REFUSED: no node 'doesnot:exist'`, rc=2, no `Traceback`,
   no `FileNotFoundError`, no artifact created.
2. Bad ref via `write.py`: rc=2 and the node `.md` bytes byte-identical
   before and after, artifact absent — for outside-repo, `.agi/nodes/`, and
   directory targets.
3. Regression guard: the accepted good path still moves the artifact in the
   same action; a node with no ref is a rc=0 no-op; `--check` after mutating
   the artifact exits non-zero and does not write.

## What would disprove it

A traceback still escaping for a missing node; the graph body changing in
any run that exits 2; the pre-flight refusing a ref that is legitimate (the
coupling broken in the safe direction).
