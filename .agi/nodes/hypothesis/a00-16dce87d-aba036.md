# hypothesis:a00-16dce87d-aba036

## Hypothesis

The first-spawn path can be made to satisfy the held-pane invariant by routing
`_open_round` through the same `tmux_hold.start` seam used for restarts, rather
than calling `Popen` directly. The seam must receive the already-computed child
environment and the seat identity, then return the canonical held `pane_id`.

## Test

Run the production dispatch open-round path with tmux available and inspect the
process launch seam: no direct `Popen` occurs on the first spawn, and a stable
pane id is recorded. Terminate the pane, reopen the round, and assert the same
pane id is reattached without an experiment-only `tmux_hold.start` call. Repeat
with tmux/session unavailable and assert the direct-`Popen` fallback remains
usable.

## Prediction and falsifier

The claim is supported if first spawn and restart converge on one named hold
record, including the child environment, and a missing-tmux case degrades to
`Popen`. It is falsified if first spawn still bypasses the hold seam, if a kill
loses or changes the pane id, or if fallback removes the ability to restart.

## Scope

This is one seam-level hypothesis under `goal:g7.31.1.2.2`; it does not alter
the independent restart-environment and tmux-fallback goals.
