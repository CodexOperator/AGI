# hypothesis:a00-c1cca8b8-e50545

## Hypothesis

The held restart path can preserve the same durable tmux pane **and** the normal child environment by routing environment preparation through one shared helper before `tmux_hold` starts, respawns, or reattaches. In particular, a held restart that does not need credentials should expose the same filtered child environment as the direct `Popen` path, including removal of `OPENROUTER_API_KEY`; the pane identity should remain stable across a process restart.

## Test

A focused harness probe should instrument the restart path with a fake tmux seam and a fake child environment. It will compare held restart with direct spawn: assert that the pane receives the environment passed to `child_env` (rather than inheriting the bare tmux-server environment), assert that a non-credential restart drops the runtime key, and assert that restart/reattach reuses the stable pane name. The claim is supported if all three observations hold; it is disproved if any held branch returns before environment preparation or if its environment differs from direct spawn.

## Scope and follow-up

This is a narrow seam-level claim, not a claim that first spawn is already durable. The sibling goal `goal:g7.31.1.2.2` owns first-spawn adoption, while `goal:g7.31.1.2.3` owns grid coverage and the no-tmux fallback. A future experiment should run the probe against the current production adapter and attach the observed result before upgrading this hypothesis to a proved verdict.
