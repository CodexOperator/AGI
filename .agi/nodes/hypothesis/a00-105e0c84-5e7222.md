## Hypothesis

`goal:g7.28.1` added an opt-in `--persistent` mode to `dispatch.py`
(`_persistent_stop` / `_supervise_persistent`, the argparse flag, two
`if args.persistent:` blocks in the record/spawn path, and the post-spawn
hold). The regression claim: **with `--persistent` ABSENT nothing on the
kid/parent spawn path changed** — same child argv, exactly one `Popen`, no
enter into `_supervise_persistent`, and no `persistent` / `restart_count`
keys on the manifest record, for BOTH `tier=kid` and `tier=parent`.

**Proves it:** the same target run through the fake-spawn live path at each
tier, once without and once with `--persistent`; the two full argv lists are
EQUAL after normalizing only the run-generated fields, the non-persistent run
shows one Popen and a clean record, and the persistent control run shows the
supervisor entered and the record stamped.

**Disproves it:** any differing argv byte between the two runs, more than one
Popen without the flag, a supervisor entry without the flag, or the
non-persistent record carrying `persistent` / `restart_count`.

`experiment:dh137-non-persistent-spawn-regression` (32 passed). The one

regression.
