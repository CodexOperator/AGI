## Hypothesis

The profile-drift sweep's `unreadable` heuristic must decide linkage by the
profile KEY, not by a literal substring: a malformed (unparseable-YAML) node
that declares `profile_ref` in its frontmatter is genuinely profile-linked and
must surface as an `unreadable` row, even when the declaration uses legal YAML
whitespace before the colon (`profile_ref : "profile/s.md"`); and a
`profile_ref:` mention in the BODY prose of a malformed node must stay a clean
no-op, since only the frontmatter block is searched.

**Proved by:** `check_all` returning `status="unreadable"` for the spaced-key
malformed file (path and artifact named) and `--all` exiting 1, while the
body-only file yields no row and `--all` exits 0; plus a behavioural wire
showing the CLI exit tracks `check_all` itself, not a source string.

**Disproved by:** the spaced-key file being silently skipped (the P6 defect),
or the body-only file acquiring a row.
