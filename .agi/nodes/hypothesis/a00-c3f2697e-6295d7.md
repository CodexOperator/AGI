# hypothesis:a00-c3f2697e-6295d7

## Hypothesis

A single JSON-ingest CLI can satisfy the parent goal's complete residue contract without teaching the existing Grok adapter about transcripts: a Grok checkpoint envelope supplies a stable `session_id`, while the CLI derives `revision = sha256(canonical content)`, looks up the pair before writing, and uses `node_writer.write_node` only for a new revision.

This makes idempotence an explicit index lookup rather than a second minting system. An unchanged `(session_id, revision)` returns the existing node id; a changed content digest writes a new note/hypothesis node with `supersedes: <prior node id>`; malformed JSON, a missing session id, or a non-terminal checkpoint returns a named refusal and no node. The accepted node carries `edited_by` and `thought_session`, parents the live goal, and the CLI prints either its canonical id or its refusal.

The JSON envelope is intentionally the smallest test surface, not a claim that real Grok already emits this format. A later parser may normalize a real artifact into the envelope, but it must do so before this ingest core and must not change the identity or atomic-refusal rules.

## Minimum experiment

Against `tmp_path` as an isolated graph root:

1. Ingest one terminal envelope and assert one node file plus its reported id.
2. Ingest identical bytes again and assert byte-identical node identity, one file, and no second write.
3. Change content while retaining `session_id`; assert one additional node whose `supersedes` names the first.
4. Ingest malformed JSON, a missing `session_id`, and a running session; assert each refusal leaves the node count unchanged.
5. Set `AGI_ACTOR` and the session argument; assert both appear on the accepted node.

## What would prove it

All five checks pass through the same CLI against the real `node_writer`, including a concurrent/repeated-ingest check that does not depend on filesystem mtime or traversal order.

## What would disprove it

`node_writer`'s lookup/create boundary cannot make the pre-write lookup race-safe; one unchanged artifact can create two nodes; a changed revision cannot be linked by explicit supersession; or any invalid/non-terminal input leaves residue.

## Build boundary

A follow-up experiment should add one thin CLI plus one focused test file, without changing `grok_bot_adapter.py`, `dispatch.py`, or `rotate.py`. If deterministic identity is instead required to be the graph `mint_id`, this hypothesis is disproved and the engine identity API must be extended first; the present claim only requires the parent goal's same-id-or-supersession outcome.
