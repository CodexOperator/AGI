# hypothesis:a00-0ce0254c-af5685

## Hypothesis

The held-restart path can be made environment-safe without relying on tmux-server inheritance: the restart routine should compute the child environment exactly once, remove `OPENROUTER_API_KEY` when `needs_credential` is false, and pass that same environment through `tmux_hold` start/reattach/`_cmd` into the pane's Popen. A focused test should assert the held restart receives the filtered environment and does not merely inherit the caller's key.

## Test / acceptance criterion

Given a held restart with `needs_credential=False` and an inherited `OPENROUTER_API_KEY`, and a captured `child_env`/`tmux_hold` boundary, the held pane must be launched with the key absent. With `needs_credential=True`, the same env must contain the required credential. The test should fail on the current early-return implementation and pass only when the held path uses the computed child env.

## Falsifier

A probe is disproved if the held path can still launch a pane with the forbidden inherited key, or if the environment is recomputed/filtered differently between the restart decision and the pane command. This claim is about propagation and credential filtering only; it does not claim to solve first-spawn hold founding or the missing build-node/fallback issues in the sibling goals.
