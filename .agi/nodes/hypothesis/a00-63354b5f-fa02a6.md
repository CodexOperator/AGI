# hypothesis:a00-63354b5f-fa02a6

## Hypothesis

A held tmux restart must not silently fall back to the tmux server's ambient environment. If the hold seam accepts an explicit environment mapping for both pane creation and reattachment, then a sanitized child environment can be carried through the hold operation without relying on whichever environment the dispatcher or tmux server happens to own.

## Implementation

Added `extensions/agi/bin/tmux_hold.py`, a small injectable seam. `_cmd` runs tmux with the complete explicit environment; `start` creates a pane with that environment and `reattach` reattaches with the same contract. The seam deliberately does not invent pane identity or a Popen fallback; those belong to sibling goals.

## Evidence

`extensions/agi/tests/test_tmux_hold.py` captures the subprocess boundary and proves that `start` and `reattach` receive the same caller mapping, including a sentinel value, and that an empty mapping remains explicit rather than inheriting server state. The focused test passed: `2 passed in 1.16s`.

## Scope

This establishes the missing durable environment seam, not first-spawn pane founding or tmux-absence fallback. The next run can wire the already-sanitized restart environment into the held launcher once that launcher is introduced by its sibling.
