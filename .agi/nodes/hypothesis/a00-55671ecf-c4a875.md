# hypothesis:a00-55671ecf-c4a875

## Hypothesis

The first production spawn in `dispatch._open_round` can use the same durable
tmux hold seam as restart, so a named pane is created before the seat process
starts rather than as an anonymous `Popen`. The claim is testable by running
`_open_round` with a fake `Popen` and a recording hold implementation, then
checking that the hold/start call receives the seat's stable pane identity and
that the recorded process is not the only owner of the seat. A kill-and-
reattach probe should preserve the same pane id without an out-of-band
`tmux_hold.start()` call.

This would be disproved if the first-spawn path still reaches `Popen` directly,
or if the hold seam receives a newly generated/unrelated pane id while the
restart path uses the held pane. No production change is proposed here; the
next node should turn this into the smallest production-path probe and preserve
its evidence.
