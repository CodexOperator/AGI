# hypothesis:a00-0f7311ac-83f97d

## Hypothesis

A single messaging entrypoint, `deliver(from_harness, to_harness, ...)`, can call
`route()` and choose the transport by the equality of the two harness strings
alone. Equal harnesses use the native pane transport; unequal harnesses use the
nudge plus `send.py` transport. The entrypoint is the only place that dispatches,
and it never infers routing from a harness-name special case.

## What would prove it

A fixture-only test suite can spy on the two transport seams and prove all of
these cases:

- equal harness strings invoke the native transport exactly once and never the
  `send.py` transport;
- different harness strings invoke nudge and `send.py` exactly once and never
  build native `tmux send-keys` argv;
- the decision is the result of `route()` and not a duplicated name comparison;
- the messaging module has no import of rotate/dispatch internals;
- the public entrypoint preserves the message body and returns the selected
  transport/result in its existing return shape.

No live pane is needed: route, native transport, nudge, and `send.py` are
replaced by recording fakes or a subprocess seam.

## What would disprove it

- same-harness delivery can reach `send.py` or a native call can be selected for
  cross-harness delivery;
- `deliver()` bypasses `route()` or adds a harness-name branch;
- either transport is selected by a condition other than equality of the two
  harness strings;
- a test requires a live tmux pane, mutates a real inbox, or imports messaging
  through rotate/dispatch internals.

## Scope and acceptance

This is a small routing seam, not a new messaging subsystem. The experiment
should locate the existing `magic_pane` route/native/cross-send implementation,
introduce or finish `deliver` at that seam, and add focused unit tests. The
acceptance condition is the spy matrix above, not a live delivery demo. The
implementation must remain transport-agnostic: `deliver` may call the existing
route and transport helpers, but it must not own formation, policy, or pane
management. Record the exact file and test names in the experiment node so a
verdict can check the claim against bytes.

## Dependency note

The claim is a hypothesis about the enforcing entrypoint, not a measurement of
the current implementation. It is proved only after an experiment exercises
both branches and the focused tests pass; until then it remains a lean.
