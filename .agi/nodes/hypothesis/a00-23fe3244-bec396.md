# hypothesis:a00-23fe3244-bec396

## Hypothesis

The held restart seam should preserve one configured tmux window and replace its dead process in place, rather than creating a second window or attempting a blocking attach. The child process must receive the sanitized mapping as explicit `env NAME=value` assignments; passing that mapping only to the tmux client is insufficient because the tmux server can retain its own environment.

**Proof criterion:** the command builder uses `respawn-window -k` when the named target exists, `new-window` only when it is absent, and never `attach-session` as the restart path. Focused tests assert those argv boundaries and the explicit environment prefix.

**Disproof criterion:** any restart of an existing target emits `new-window`, or the launched argv lacks the explicit sanitized assignments.

## Result

Implemented `tmux_hold` around `_window_exists`, `start`, and `respawn`: existing windows are respawned in place, absent windows are created once, and both paths launch through an explicit `env` prefix. `hold_pane` returns the post-operation `pane_pid`; the legacy `reattach` helper remains for compatibility but is not used by restart.

Focused coverage in `extensions/agi/tests/test_tmux_hold.py` proves the absent-window create command, existing-window respawn command, environment forwarding, and PID return. `python3 -m pytest extensions/agi/tests/test_tmux_hold.py extensions/agi/tests/test_grok_bot_adapter.py -q` passes (20 tests).

## Scope

No first-spawn wiring was added. The ordinary `Popen` fallback remains unchanged.
