# held restart must pass an explicit sanitized child environment

## Hypothesis

The held-pane restart seam is behaviorally equivalent to the ordinary restart
seam when it explicitly passes the same `child_env(...)` result into the
respawned pane. In particular, a credential-none harness row must not inherit
`OPENROUTER_API_KEY` through the tmux server, even when that key exists in the
dispatcher environment.

## Testable claim

A focused test that replaces the pane launch with a recorder, invokes the
held restart path, and inspects the recorded launch environment will show:

1. `child_env` is called before the held pid is returned or reattached.
2. The launch receives that exact environment (or its `env=` equivalent),
   rather than relying on bare tmux-server inheritance.
3. For a credential-none row, the recorded environment omits
   `OPENROUTER_API_KEY`; for an unmarked/default row, it retains the inherited
   key, preserving the existing policy.

## Falsifier

Disprove the claim if a held restart with a credential-none row records or
retains `OPENROUTER_API_KEY`, if it returns before constructing `child_env`, or
if the test cannot observe an environment at the held launch seam. The default
row retaining the key is a control, not a failure.
