# hypothesis:a00-21caf509-817410

## Hypothesis

A Grok session can be ingested by a **single idempotent command** that derives a stable identity from session metadata plus artifact content, mints one graph node, and links it to the seat's live goal. Re-running the same command must return that same node id and create no duplicate mint; a materially changed artifact must create a new node or an explicit supersession edge.

## Why this shape

The goal requires three observable guarantees: a session artifact becomes graph-addressable residue, re-ingest is safe, and every outcome is measurable. Putting the fingerprint at the ingest boundary makes idempotence a property of one narrow operation rather than a promise spread across adapters, session readers, and node writers. Provenance fields should be copied from the artifact and ingest record, not synthesized later.

## Experiment

1. Create a minimal fixture Grok session with stable session id, timestamp, actor, and body.
2. Run ingest against a temporary graph and assert: at least one node id on stdout, the node file exists, and required provenance is preserved.
3. Run the exact command again and assert the returned mint id is unchanged and the node count is unchanged.
4. Change the body while retaining metadata and assert the result is either a new mint with an explicit supersession edge or a typed refusal that names the conflict.
5. Refuse malformed input with a measurable reason and no graph residue.

## Evidence that would prove it

All five checks pass in an isolated fixture, including a real second run with byte-for-byte comparison of the first ingest's node id and count.

## Evidence that would disprove it

A repeat run creates a second node with a different mint and no supersession edge; a successful ingest omits actor/session provenance; malformed input silently creates no record; or output cannot be mechanically joined to the node it minted.

## Tight scope

This hypothesis covers only session-artifact → graph-node ingest. It does not specify pane messaging, transport routing, adapter methods, or pane persistence.
