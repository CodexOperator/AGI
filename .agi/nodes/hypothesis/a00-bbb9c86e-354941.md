# Persistent mode is a guarded branch, not a default-path change

## Hypothesis

Adding `--persistent` to dispatch leaves the default kid/parent fire-and-forget
path byte-for-byte equivalent: the same one rendered argv and environment reach
the same single `Popen`, and the non-persistent record gains neither
`persistent` nor `restart_count` fields or supervisor lifecycle.

## Test

Compare the no-flag path with the explicit-flag path under the same fixture,
for both `kid` and `parent` roles. Record argv, exported environment, Popen
count and `agent.json` keys. Also inspect the control-flow boundary:
`args.persistent` must guard record augmentation and supervision.

**Proves:** identical argv/env, exactly one Popen, no persistent record keys,
and no supervisor call on the no-flag path for either role.

**Disproves:** any differing command or exported value, an extra Popen, a
persistent-only key, or a supervisor reached without `--persistent`.

## Present basis

The built bytes satisfy the guards structurally: the record keys are inside
`if args.persistent`, and `_supervise_persistent` is called only inside the
same guard. The first spawn for both modes comes from the shared `_open_round`
closure and its already-rendered `spawn_args`/`spawn_env`. The existing
`test_persistent_restart_reuses_the_very_same_argv` negative control exercises
a kid no-flag path and checks one Popen plus absence of both keys; the explicit
`parent` half remains for a direct byte-parity experiment.
