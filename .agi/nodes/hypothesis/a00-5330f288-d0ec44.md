# hypothesis:a00-5330f288-d0ec44

## Hypothesis

The first production dispatch of a persistent seat can use the same durable named-pane seam as restart, so the seat is launched inside `tmux_hold.start` (or an equivalent named-pane starter) without an out-of-band hold call. The pane identity is therefore stable when the seat process is killed with `kill -9` and dispatch is restarted.

## Test

1. Exercise the production `_open_round` first-spawn path for one persistent seat.
2. Do not invoke `tmux_hold.start` separately.
3. Record the pane id/name before and after `kill -9` plus restart.
4. Assert that both rounds report the same pane identity and that the pane remains discoverable to `tmux list-panes`.

## Falsifier

A first-spawn round that still creates the process with direct `Popen`, loses the pane identity across restart, or requires an explicit out-of-band hold call disproves the claim. The result must also reject a fabricated `created=true` marker as evidence of a held pane.
