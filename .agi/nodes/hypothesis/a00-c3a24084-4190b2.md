## Hypothesis

`dispatch … --persistent` can HOLD a seat process and, when the child dies,
re-open it through the **same rendered `spawn_args` / `spawn_env` / `_open_round`**
seam that produced the first spawn — no second argv path, no re-render — and the
agent's own manifest record can show the occupation (`persistent`, live `pid`,
`restart_count`). Fire-and-forget stays the default.

## What landed

`extensions/agi/bin/dispatch.py` (+70 production lines):

1. **`--persistent`** — opt-in `store_true` flag. Absent, every spawn path is
   byte-identical to before (proved by test 2).
2. **`_supervise_persistent(proc, reopen, …)`** — watches `proc.poll()`, and on
   death calls `reopen("ab")`, which is the caller's existing `_open_round`
   closure. That closure already holds the one rendered `spawn_args` and
   `spawn_env`; the supervisor builds no argv, so there is structurally no
   second path. Bounded at `_PERSIST_MAX_RESTARTS = 3`; each hand-off rewrites
   the record's current `pid` and `restart_count` and persists `agent.json`.
3. **Clean stop** — `_persistent_stop` is true on `<iter>/stop.<agent>` OR
   `AGI_PERSISTENT_STOP` in the dispatcher's env.
4. **Occupation in the record** — `persistent: true`, `restart_count: 0` on the
   agent record at spawn, kept current by the supervisor. `pid` is already
   there and is overwritten with the CURRENT child on each restart.
5. **Inline reaper off under `--persistent`** — the supervisor owns the held
   seat's lifecycle; the inline reaper is not allowed to restart the same seat
   a second way.
