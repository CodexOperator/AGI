# hypothesis:a00-2043ac6b-84c801

## Hypothesis

`tmux_hold.py` should be able to restart its target process when the tmux
executable or the configured session is unavailable, and that restart should
remain covered by a build/grid node so the source cannot silently regress.

A focused probe can prove the claim by invoking the restart path with tmux
removed from `PATH` and with an unset session: it should select direct
`Popen` (or an equivalent direct-process fallback), start the target, and
return success. The same probe should fail if the hold path raises or blocks
before attempting the fallback. Separately, `grid_coverage_check` should
resolve a build node/payload reference for
`extensions/agi/bin/adapters/tmux_hold.py`; absence of that reference is a
counterexample even if the runtime probe passes.

This hypothesis stays deliberately narrower than a general restart design:
it tests the restart decision and its provenance, not tmux policy, process
supervision, or cleanup semantics.
