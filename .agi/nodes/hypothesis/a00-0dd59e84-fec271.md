## Hypothesis

**Claim (DT.35 corrective).** The set of env names that `grok-bot-cli@0.3.1`'s
**source** reads is a **UNION of at least 25 names**, not the exact 22 the
DT.32 round asserted. The prior claim counted only two read classes — 20
literal `process.env.<NAME>` dot-accesses and 2 `truthyEnv("...")` literals —
and missed a **third, aliased class**: names read through a default-parameter
alias, where a function takes `env = process.env` (or is handed one) and then
reads `env.<NAME>`. No `process.env.<NAME>` dot-access grep can see those:

- `CODEX_HOME` — `codex-bridge.js:27-28`, `codexSocketPath(env = process.env)`
  then `env.CODEX_HOME`.
- `APPDATA`, `XDG_CONFIG_HOME` — `app-session.js:104-110`,
  `grokBotAppDataPath(home, platform, env = {})` reading `env.APPDATA` /
  `env.XDG_CONFIG_HOME`, reached from
  `grokBotGatewayDescriptorPath(..., env = process.env)` at :116.

Corrected union = 20 (dot-access) + 2 (truthyEnv literals) + 3 (aliased) = **25
names**. `AGI_MODEL` is absent from the corrected union under all four scans,
so the DT.29 D1/D2 compat/no-delivery conclusion holds — but the *method* that
established it must include the aliased read, or the next re-derivation drops
back to 22.

**Prove it by.** Four scans over the published 0.3.1 `src`
(`extensions/agi/tests/probes/probe_dt35.py`): (a) literal dot-accesses = 20;
(b) `truthyEnv("...")` literals = 2; (c) `env.<NAME>` alias reads = 3
(`APPDATA`, `CODEX_HOME`, `XDG_CONFIG_HOME`); (d) exactly one computed
`process.env[name]` site (`url-policy.js:13`) whose only callers pass the two
(b) literals, and no spread/`Reflect` read. Union = 25; the committed constant
`RECORDED_CLI_SOURCE_ENV_0_3_1` holds all 25, the test suite asserts the
aliased names are present and the set is >= 25, and both suites stay green.

**Disproved if.** A fourth read class resolves a name not in the union (e.g.
`AGI_MODEL` reaches the process through an alias, a spread, or `Reflect`), or
the union measures < 25, or the aliased names are absent from the committed
constant (a regression to the falsified 22).

**The falsified predecessor.** `hypothesis:a00-a1b4a408-ea08b5` claimed
"exactly 22". That exactness is falsified by scan (c); what remains true is the
>=25 union, which this node and its experiment carry.
