The authoritative Grok Bot help measurement resolves the missing prerequisite for
`goal:g7.31.1.1`: `grok-bot --help` is a `gbot` management CLI, not a prompt-runner
with `--model` or `-p`. Therefore the adapter's current
`<bin> [--model M] -p <context_file>` argv is not measurable as the real
interface; it can only be retained as an explicitly pending mapping.

## Test and result

`/data/work/agi/.agi/worktrees/a00-e03c6242/.agi/sessions/iter-DT.98/a00-d42c2ceb/help.txt`
with the adapter's emitted argv. The help usage is:


`codex send`; neither `--model` nor `-p` is documented. This disproves the
claim that the current stub can be described as measured real argv. It also
identifies the exact prerequisite before a safe adapter change: the dispatch
contract must provide a bot/group target and a way to deliver the context file
(or its contents) through the documented `send` interface. No such mapping is
invented here, and no production code is changed.
