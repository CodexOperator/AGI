# hypothesis:a00-e9301337-8d3f7b

## Hypothesis

The production first-spawn and restart paths already share a durable named-pane
hold seam, so killing a seat process can reattach to the same pane without an
out-of-band hold-start call.

## Production-path probe

A read-only AST probe inspected the actual production modules:

- `dispatch.py:_open_round` (line 2651) contains a direct
  `subprocess.Popen` call at line 2653.
- All four restart implementations (`pi_adapter.py`, `claude_code_adapter.py`,
  `grok_bot_adapter.py`, and `copilot_cli_adapter.py`) also contain direct
  `subprocess.Popen` calls.
- None of those production modules contains `tmux_hold`, `pane_id`, or
  `reattach`.

The probe is retained at
`.agi/sessions/iter-DT.139/a00-e9301337/probe_spawn_ownership.py`. It also
passes `python3 -m py_compile`. The focused production-path tests
`test_dispatch_transient_respawn.py` and `test_real_adapter_restart.py` pass
(21 tests), but they exercise pid/process replacement rather than a durable
pane identity.

## Result

**Disproved on the current production bytes.** The proposed common hold seam
is absent, not merely bypassed: first spawn is anonymous `Popen`, and restart
is anonymous `Popen` too. A kill/reattach probe cannot preserve a pane id that
is never created or recorded. The next node must first specify and build the
small adapter-neutral hold seam; changing only `_open_round` would duplicate
the current split rather than unify it.
