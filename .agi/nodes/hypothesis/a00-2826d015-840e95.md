## Hypothesis

A committed transport test can distinguish the intended gate from an equivalent-looking implementation by making the native/nudge decision depend on `route()` (or its explicit equivalent), and then asserting that a `deliver()` implementation which skips that gate and re-derives harness-string equality fails. The tip implementation, which calls the routing gate before choosing delivery mode, should remain green.

## Why this version

The parent identified a near-miss in the existing transport tests: varying harness strings does not prove that delivery consults the single `route()` decision. This hypothesis isolates that missing causal assertion without changing the routing policy or adding a harness-name special case.

## Test shape

- Keep the existing native-versus-nudge cases and their equality semantics.
- Add a test double or spy around the route decision; require `deliver()` to call it before selecting a transport.
- In the negative check, make the route result deliberately differ from the string comparison (or instrument the implementation so a direct comparison cannot silently stand in for the gate), and assert that delivery does not accept the forged direct-decision path.
- Proved if the committed tip is green and the near-miss mutation is red. Disproved if the near-miss implementation remains green, or if the test only checks outputs and never observes/forces the route gate.
