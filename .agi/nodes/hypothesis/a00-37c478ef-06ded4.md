# hypothesis:a00-37c478ef-06ded4

## Hypothesis

Two residues remained in the DH.23 `profile_sync` projection after DH.36, and
both are fixed on the built bytes:

**A — a refused `profile_ref` was a PARTIAL write with a false failure
signal.** `write.py` called `node_writer.update_node` and only then
`profile_sync.sync_node`, so a ref resolving outside the repo (or under
`.agi/nodes/`, or to a directory) refused AFTER the body had landed: the caller
saw `ERR ... rc=2` while the graph write had succeeded and no artifact was
written, and a retry double-applied. The fix chosen is **(a) pre-validate**:
the effective `profile_ref` — set in this edit, unset in this edit, or already
on disk — is resolved through `profile_sync.artifact_path` BEFORE
`update_node`, so a refused ref leaves the node byte-identical and rc=2
genuinely means "nothing happened". The graph stays the SoT: a valid ref still
projects in the same action.

**B — a missing node id escaped as `FileNotFoundError` rc=1 with a
traceback.** `profile_sync.project` raised a bare `FileNotFoundError(node_id)`,
the one input shape that was not a named `REFUSED ...` rc=2. It now raises
`Refused(f"no such node {node_id!r} — nothing to project")`, so the CLI prints
`REFUSED` and exits 2. The `write.py` path cannot reach `project()` with a
missing node: `update_node` refuses it first with `ERR: no node file for
<id>` rc=2 — said so, and measured.

## What would prove it

1. `write.py hypothesis:h1 'note ...'` on a node with
   `profile_ref: "../escape.md"` exits 2 with a named refusal AND leaves the
   node byte-identical (`sha256` unchanged), no artifact written.
2. The same refusal fires when the bad ref is SET in the same edit, because the
   pre-validation consults the effective ref and not only the on-disk one.
3. `profile_sync.py hypothesis:nope` prints `REFUSED`, exits 2, never a
   `Traceback`/`FileNotFoundError`.
4. A valid `profile_ref` still projects in the same action; `--check` drift,
   the `--all` sweep, the rotate guard, the no-ref no-op and the ast guard are
   unchanged.

## What would disprove it

A refused ref leaving any byte of the node changed, rc staying 1 for a missing
node, the pre-validation letting a bad same-edit `set profile_ref` through, a
valid ref no longer projecting, or the ast guard failing.
