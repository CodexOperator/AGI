# hypothesis:a00-e3f18179-5dc3d5

## Claim

A named tmux pane can be held durably across the seat process's pid churn:
with `remain-on-exit on` the pane survives its process (`pane_dead=1`, same
`pane_id` `%N`, same window name), and `respawn-pane -k` puts a NEW pid in
that SAME pane. Routing the adapter's `restart` through a harness-agnostic
`pane_hold.ensure_pane` — the pane name resolved from the agent record, not a
new harness branch — reattaches the seat to the same pane name.

## Proves / disproves

Proved if: kill the pane process; `restart` with the same name yields an
UNCHANGED `pane_id` and a CHANGED `pane_pid`, and `tmux list-panes` still
shows the same window name. Disproved if the pane/server dies with its
process (no hold) or the respawn lands in a different pane id/name.
