# hypothesis:a00-488d7035-4335d9

## Hypothesis

`_tmux_start` must assign different live named panes to two agents even when their sanitised, truncated prefixes are identical. The fix preserves a readable `agi-hold-<seat>-<agent>` prefix and appends a SHA-256 digest of the full unsanitised pair, so the digest—not the lossy human prefix—carries identity. Two long names sharing a prefix are proved distinct by the new regression test; a same-name pair remains re-entrant.

## Result

Implemented in `extensions/agi/bin/dispatch.py` and covered by
`extensions/agi/tests/test_dispatch_tmux_hold.py`.

- `python3 -m pytest extensions/agi/tests/test_dispatch_tmux_hold.py -q` → **4 passed in 0.61s**.
- Real tmux 3.4 probe with SIGKILL: first call created a real pane and the same pane remained listed after SIGKILL; a second long agent id sharing the long-seat prefix received a different session and pane id.
- The digest is cryptographic collision resistance, not a literal mathematical uniqueness proof; the full raw pair is never used as a tmux command argument.
- Defect #2 (rc-4 narrowing) was not changed: verifying pane liveness would risk misclassifying a just-respawned process and the existing poll/reaper path is intentional.
