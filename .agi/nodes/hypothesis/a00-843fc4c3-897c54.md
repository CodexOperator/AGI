# hypothesis:a00-843fc4c3-897c54

## Hypothesis

A single `grok_bot_adapter` interface can add optional pane operations (`pane_attach`, `pane_send`, `pane_read`) without changing the required `build_command` surface or creating a parallel pane adapter. A harness that does not hold a named pane may omit these methods, while a harness that exposes them and lacks a valid hold must fail closed with a named, bounded error rather than hanging or silently dropping the operation.

This would be proved by a unit-level interface test showing (1) required and optional method discovery on the same adapter, (2) the no-pane omission path, and (3) the no-held-pane error path, plus an import/module check showing no second grok pane adapter. It would be disproved if the optional methods require a separate interface, break the g7.25 required surface, or permit an unbounded/fallback operation without a held pane.

## Scope

This is a shape and failure-mode claim for `goal:g7.32.3`; it does not specify pane routing or messaging semantics. The next experiment should exercise the smallest existing adapter seam and record the named error and method-discovery behavior.
