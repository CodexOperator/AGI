THE DEFECT THE ORPHANED FIX ADDRESSES, which is the one that has cost this loop the most. `rotate.py loop` has, at least three times across nine prime generations, printed a successful rotation and created no tmux window (HANDOFF.md Rotation section, trap 0o). Every prime treated it as a mystery and worked around it with `spawn`. The cause is two silent failures stacked: the whole `claude` invocation, constitution head included, was handed to `tmux new-window` as ONE argv element, and past roughly 16KB tmux refuses with `command too long`; and `_launch_window` captured tmux's stderr into a variable it discarded, returning 0 unconditionally, so the refusal never reached a human. `spawn` and `loop` build the same line and differ only by `loop`'s 214-byte rotation continuation — so one worked and one did not. A knife-edge, not a design. That is why the same flags through `spawn` succeeded at once every single time a prime tried it.

FIXED AND PROVEN LIVE by belam-S1-L3-IX, 2026-09-08, at the owner's direct instruction ("Then let's figure out why it didn't work and fix that as well") after `rotate.py loop` refused to confirm its own rotation for the third time in one loop.

THE SYMPTOM, three primes running. Belam VI (trap 0o), Belam VII (the Rotation section, called "the most dangerous defect this session, because it fails silently in the direction of losing the ladder") and Belam IX all ran `rotate.py loop` and got a success line with NO tmux window behind it, while the SAME flags through `rotate.py spawn` worked first try every time. Two primes wrote it down as "loop's spawn path vs spawn's" and rotated with `spawn` instead. That reading was wrong, and it is worth naming why: the two commands share ONE launch path, so "loop's path is broken" could never have been the explanation.

THE CAUSE, measured not inferred. `_launch_window` handed the ENTIRE `claude` invocation -- constitution head included -- to `tmux new-window` as a single argv element. Run by hand, tmux answers `returncode 1`, `stderr: command too long`. The rotation line is ~16KB and tmux refuses past its own buffer. `cmd_spawn` and `cmd_loop` build the same line and differ by exactly one thing: `loop` appends a 214-byte ROTATION CONTINUATION. Measured: `spawn` 16255 bytes, `loop` 16469. **So `spawn` was not working -- it was clearing a hard limit by about two hundred bytes of luck**, and any growth in the head, the prompt file or the ladder row would have taken it out too, silently, at the exact moment a prime needed to hand over.

THE SECOND BUG, one line below the first and the reason nobody found the first for three sessions: `subprocess.run(..., capture_output=True)` captured tmux's `command too long` into a variable that was thrown away, and the function returned `0` UNCONDITIONALLY. tmux said exactly what was wrong, every time, and the code discarded it. **The L3.33 window-existence check catches the SYMPTOM and is what made this diagnosable at all -- it is a good guard and it stays -- but a guard on the symptom is not a fix for the cause, and the difference cost this loop three generations.**

THE FIX, both halves. (1) `_launch_window` now returns tmux's real exit code and prints its stderr. (2) Above `_TMUX_ARG_SAFE` (8192) the command is written to a mode-0600 script and tmux receives `bash <script>` -- a few dozen bytes -- so the launch line's length stops mattering permanently. The script is deliberately NOT deleted: bash reads a script incrementally, so removing it early can truncate a running successor. Below the threshold nothing changes, which a third test pins.

EVIDENCE. Three red-first tests in `test_rotate.py`, verified genuinely red by stashing the fix and re-running: 2 failed before, 3 pass after (the third is the no-regression guard and is correctly green in both directions). `test_rotate.py` 47 -> 50. And the live proof, which is the one that matters because this defect was invisible to unit tests for three sessions: `rotate.py loop --role prime_director --name belam-probe-D` against a REAL `claude` successor produced a live, thinking tmux window, where the identical command minutes earlier produced none. Probe cleaned up; all nine predecessor `belam-*` windows untouched.

WHAT THIS UNBLOCKS. `rotate.py loop` is the sanctioned rotation primitive and the super-ralph verb the whole seat ladder rotates through -- `rotate-self` and every perpetual seat in `goal:g17` launch through this same function. It has been unusable since Belam VI and every prime since has hand-rotated with `spawn` and written a warning to the next one. Related and still open: `l3-rotate-self-successor-override` proved rotation against a STAND-IN successor; this node is the first `loop` rotation against a REAL claude successor to produce a window at all.
