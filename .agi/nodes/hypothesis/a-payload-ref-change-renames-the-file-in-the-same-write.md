# hypothesis:a-payload-ref-change-renames-the-file-in-the-same-write

## Measured
- A build node names its file by `payload_ref` + `location` (a base NAME, `locations.payload_base`, locations.py:445). A write that sets `location` in the same edit wins over disk (write.py:2277-2279). The ORIGINAL defect (2026-09-27, DH.579, this node's first measurement): NOTHING moved the file -- `grep -nE 'git mv|shutil.move|rename\('` over write.py + node_writer.py = 0 hits, `os.replace` only for atomic temp writes -- so `set payload_ref=<new>` rewrote the row and left the file at the old name, dangling until a hand `git mv`. **Now CLOSED in the bytes**: the mover exists (`node_writer.plan_move` :549-576, `node_writer.move_payload` :579-606, `os.replace(src, dest)` at :601; the other `os.replace` sites, node_writer.py:1194 and :1270, are still the atomic temp writes). This paragraph is kept as the chain's original measurement, with its citations re-measured on 2026-09-27 (DH.603, a00-06ed089b) because k1 moved every line below it.

## CLAIM
(1) a node write that changes `payload_ref` to a new NAME in the same directory renames the file and updates the row in ONE write (mint_id unchanged, the grid history of the node continuous) (2) a change that moves the file to another DIRECTORY or another `location` is REFUSED, naming both paths, unless the write carries an explicit confirm (one named flag/verb arg); with it, the move happens, WHETHER OR NOT the old file is in this checkout -- the gate is about the ROW, which outlives the checkout (3) a declared ref that names a file THIS CHECKOUT DOES NOT HOLD is still repointed, because a row may name bytes that were never created, are deleted, or live in another worktree, and refusing that would make the field unwritable on a partial clone; nothing is invented for it and no move is logged; WHERE THE BYTES ARE IN THIS CHECKOUT, the write that moves them leaves the row resolving to an existing file, the old path gone, and an existing file at the destination refused (never overwritten).

> Narrowed 2026-09-27 (DH.579, experiment:a00-3d52306e-031125) and PUT INTO `testable_claim` (DH.603, a00-06ed089b). The prior text said "after ANY such write the row resolves to an existing file", which `test_payload_rename.py:159` (`test_a_declared_ref_with_no_file_here_is_not_a_refusal`) asserts the NEGATION of. A test that contradicts its own claim is a defect; the claim moved, not the test. Conjunct 2's shape is now the STRICT one: an absent source must NOT short-circuit the consent gate, because the row, unlike the bytes, does not disappear with the worktree. (That gate is no longer open -- see the falsifiers below; the frontmatter claim had not caught up with the bytes and said so, which is why a reader met a claim the tests contradicted.) The narrowed form is now the frontmatter `testable_claim`, not only this body: the claim a reader meets first is the claim the bytes hold.
