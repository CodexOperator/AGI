It doesn't need peak security now just good enough for agent colab.' The claim's HARD RULES line 'pynacl and cryptography only, no bespoke primitives' no longer applies. REPLACEMENT RULES: (1) a from-scratch, pure-python implementation from the published spec is permitted and preferred where it removes a dependency or integrates better — RFC 8032 Ed25519 and SEC 2 secp256k1 with EIP-191 message framing are each about a hundred lines; this is what makes the wallet path landable now with nothing installed; (2) SECURITY TARGET = good enough for agent collaboration, i.e. a spoofing guard between cooperating agents on shared infrastructure, not adversarial-grade — state this grade in the module docstring and in the verifier's help text, never above it; (3) the published TEST VECTORS must pass in the suite — RFC 8032 section 7 vectors for Ed25519, a known secp256k1 vector, and an EIP-191 signature that a real wallet recovers to the expected address — because passing the vectors is the whole difference between a lightweight implementation and a wrong one; (4) pynacl may still be used as an oracle in tests to cross-check the from-scratch signer on random inputs, without being a runtime dependency. Everything else in the claim stands, including the honest scope.

OWNER AMENDMENT 2026-09-10 (verbatim in doc:l4-owner-decisions): 'it should be built in a modular way that the actual encryption and security logic could be upgraded later once this project moves to a public subscription web app release'. ADDED TO THE CLAIM AS A HARD RULE: the signing and verification logic lives behind ONE swappable interface — a Signer/Verifier pair keyed by the sig_scheme string in the seat row, registered in a scheme table, with send.py and rotate.py calling only the interface and never a primitive. Upgrading the security layer at web release (a hardware key, a KMS, a different curve, real access control across tenants) must be a new scheme entry plus a row edit, with send.py and rotate.py untouched. PROVED BY (g): a test that registers a dummy scheme and rotates a seat onto it with no change outside the scheme table and the row. The from-scratch permission stands; modularity is what makes 'good enough for now' safe to ship, because now is not forever.
