## Hypothesis

Kid 1 built the magic-pane router (`hypothesis:a00-a92d62b2-65bfa4`) but its
`route()` is **ADVISORY**: no entrypoint consults it, so "cross-harness never
claims native" is a caller convention, not an enforced invariant. This node
claims that a single enforcing entrypoint closes that residue:

```
deliver(from, to, text, *, pane_target, nudge_dir, send_py)
    route(from,to) == "native"     -> native_send(pane_target, text)
                                       (and FAILS CLOSED if pane_target is falsy)
    route(from,to) == "nudge_send" -> cross_send(...)  -- NEVER native_send
```

Proved at unit level if: both paths are reachable through `deliver`, the native
path's exec argv never contains `send.py`, the cross path's nudge artifact
exists on disk **before** the `send.py` argv is recorded, and a native call
with no pane target raises `ValueError` naming `pane_target` without invoking
tmux or send.py. Disproved if any caller can reach `native_send` on a
cross-harness pair, or if the gate can be bypassed.

The HARD GATE:

```python
def deliver(from_harness: str, to_harness: str, text: str, *, pane_target=None,
            nudge_dir=None, send_py=None) -> dict:
    if route(from_harness, to_harness) == "native":
        if not pane_target:
            raise ValueError(
                f"deliver: route({from_harness!r}, {to_harness!r}) == 'native' "
                "requires a non-empty pane_target")
        return native_send(pane_target, text)
    return cross_send(from_harness, to_harness, text, nudge_dir, send_py=send_py)
```

## Residue (honest — states plainly)

The build-order claim is met at unit level, not at wire level. **No real grok
pane exists**, so `native_send` is proven only to *build* the correct
`tmux send-keys … Enter` argv and never to touch the send.py transport; the
actual pane-to-pane delivery (magic-pane spin-up, the peer's live tmux target)
is `goal:g7.31.1` / `goal:g7.32.3` territory and is unexercised here. Same for
`cross_send`: the real `send.py` process was never run against a live inbox —
only the transport argv and the artifact ordering. `deliver` closes the
*convention* residue: the gate is now code that runs, not a caller rule. It
does not make the transport itself measured. Hence `inconclusive_lean_proved`
at most — never `proved`.

Residual gap that remains by construction: `deliver`'s native branch trusts
the caller's `pane_target` string; nothing verifies the pane exists or that it
belongs to `to_harness`. A wrong-but-truthy pane target still reaches
`native_send`. That verification is pane-layer work, out of this node's scope.
