# hypothesis:a00-d396aae4-8c8555

## Hypothesis

`deliver()`'s transport choice is an **exhaustive** match on `route()`'s return
domain, not a two-way `if` whose else-branch is a default. **Claim:** for any
`route()` result outside `{NATIVE, CROSS}`, `deliver()` raises a named error
carrying the offending decision, and NEITHER `native_send` nor `cross_send` is
invoked.

**Proves it:** a test with `route()` patched to a value outside the domain in
which `deliver()` raises *and* both transport spies are recorded as never called.
**Disproves it:** any out-of-domain decision that reaches a transport, or a
raise that happens only after something was already sent.

The second half is the load-bearing half. A test asserting only `pytest.raises`
passes an implementation that raises *after* having delivered — the exact
failure this node exists to prevent.

## The residue this closes

Parent's wire probe (a00-fd1e9e1d): with `route()` returning a third value
`'bridge'`, `deliver()` did not refuse — it fell through to `cross_send` and
attempted a live `import send`. `route()`'s return domain was unenforced
anywhere; the gate was a default wearing a gate's shape.

## What was built

`extensions/agi/bin/magic_pane.py`:

- `class UnknownRoute(ValueError)` carrying `.decision` — the offending value,
  not a stringified afterthought. A caller that gets this exception can branch
  on what went wrong.
- `deliver()` now matches both decisions explicitly and `raise`s on anything
  else. The `return` before the transports is unreachable for a bad decision, so
  the "neither spy called" half is a property of the control flow, not of test
  ordering.

`route()` is unchanged and still equality-only. No harness-name special case.
**`deliver()` is not wired into `send.py`** — that is a different leaf.

## THOUGHT
The parent's own framing is the lesson: a gate whose else-branch is a fallback
is not a gate. I chose to make the domain *structurally* exhaustive (explicit
match + raise) rather than to add a guard clause on top of the default, so the
failure mode cannot be reintroduced by deleting the guard. I also spent the
falsifier budget on the "neither transport ran" half rather than on more cases
of the raise alone, because the raise alone is the weak assertion.
