# hypothesis:a00-43318912-f06071

## Hypothesis

The `unreadable` classification in `profile_sync.check_all` can be made exact
by reading the `profile_ref:` link hint from the **frontmatter region only**,
and the except-branch read can be guarded so a read failure becomes a **named**
`unreadable` row rather than an escaping exception.

Two conjuncts, both testable on the built bytes:

- **auth** — a malformed file whose BODY merely mentions `profile_ref:`
  (prose, doc line, code block) is NOT profile-linked and is skipped. Only a
  `profile_ref:` inside the first `--- … ---` block links.
- **gate** — a file that cannot be read (permission/IO) is surfaced as an
  `unreadable` row carrying its path and reason; `--all` exits 1 and the
  rotation guard names it. It never escapes `check_all` as a traceback.
- **wire** — the pre-rotation guard stays wired into `cmd_loop` before
  `spawn_window`, so the fixed sweep is what the rotation actually consults.

Disproved if: a body-only mention is still classified `unreadable`, or a read
failure still raises out of `check_all`, or the guard is absent/after spawn.

## What was done

`extensions/agi/bin/profile_sync.py`:

- Added `_raw_frontmatter(text)` — returns the raw text between the first two
  `---` delimiter lines (or `""` when there is none). The `profile_ref:` hint
  in the except branch is now tested against **that region only**.
- `_raw_profile_ref` now reads that frontmatter region (same region as the
  test), so the hint test and the value extraction cannot disagree.
- Guarded the except-branch `f.read_text`: a read failure appends a named
  `unreadable` row with the path and `TypeError: …`/`PermissionError: …`
  detail and continues — fail-closed with a name, never a bare traceback.

`extensions/agi/tests/test_profile_sync.py`: three new tests —
`test_body_only_profile_ref_mention_is_not_linked` (auth),
`test_unreadable_file_is_named_not_raised` (gate), plus the existing P7/P8
behavioural pair re-run unchanged (wire/non-regression).
