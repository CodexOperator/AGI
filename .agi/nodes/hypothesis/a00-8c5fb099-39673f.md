# hypothesis:a00-8c5fb099-39673f

## Hypothesis

`extensions/agi/bin/send.py` is the thin transport router `goal:g7.32.4`
calls for: it chooses a transport and never embeds rotation/formation/push
orchestration. **Falsifier 1** of the target states this as *zero imports of
`rotate` / `dispatch` orchestration symbols*. The claim is falsified if, from
the source bytes, send.py imports `rotate`/`dispatch` or references any
orchestration symbol of theirs.

## Method

New census, `extensions/agi/tests/test_send_thin_router.py`. It parses
`send.py` with `ast` (comments and docstrings are not AST nodes, so prose
that merely *names* a symbol cannot be counted as a reference), and it:

1. lists every `import rotate` / `import dispatch` site (module-level or
   lazy);
2. collects every actually-referenced `rotate.X` / `dispatch.X` attribute;
3. classifies each against an explicit `ORCHESTRATION_SYMBOLS` set
   (`_commit_spawn_row`, `_push_season_branch`,
   `_finish_pending_swap_on_push`) versus a named `UTILITY_SYMBOLS` set
   (`DEFAULT_TMUX_SESSION`, `_git_toplevel`, `_normalize_settings`);
4. reports Falsifier 2's substrate: module-level transport table present?
   `"grok"` literals or `harness ==` comparisons in the caller bodies
   `send`, `send_dm`, `send_room`, `_nudge_target`, `_nudge_window`?

Assertions are **characterization**, not `xfail(strict=True)`: the target
assertion (orchestration set empty) is FALSE on the current bytes, so a
strict xfail would XPASS and leave the suite red. Instead the measured truth
is pinned, so a later edit that *adds* coupling turns the file red on
purpose.

The grep-level reconnaissance in the kid brief listed 10 referenced rotate
symbols. The AST census **corrects it to 6**: `_persist_pending_key` (L202),
`_seats_ownrow_content` (L645), `_own_row_line` (L675) and `_find_seat`

`dispatch` is imported nowhere and referenced nowhere.

## Verdict against the falsifiers

**Falsifier 1 is RED.** send.py lazily imports `rotate` at 7 sites and
references **three orchestration symbols**: `_commit_spawn_row` (spawn-row
mint, L624), `_push_season_branch` (season-branch push, L792) and
`_finish_pending_swap_on_push` (deferred pending-key swap, L829). The
remaining three symbols (`DEFAULT_TMUX_SESSION`, `_git_toplevel`,
`_normalize_settings`) are UTILITY, not policy.

**Falsifier 2 substrate is mixed.** There is **no** module-level
`TRANSPORTS`/dispatch table, and the caller-facing bodies carry **no**
`"grok"` literal and **no** `harness ==` comparison — so transport choice
currently exhibits neither a table nor inline harness branching. The
asymmetry is worth naming: send.py is *policy-thin but orchestration-thick*.
The coupling is not harness-name branching; it is direct procedure calls
into `rotate`'s spawn/push/pending-swap internals, hidden behind lazy
imports that a LOC count does not see.

## What would close it

Move the three orchestration calls behind a transport/plugin seam, or move
the keygen row commit/push path out of `send.py` entirely. Then flip the
final characterization assertion's expected set to empty and the target
invariant is proved.

## Caveats

The census pins the current bytes; it does not measure runtime call
frequency, so a symbol referenced but never reached still counts as
coupling here. Classification of the three symbols as ORCHESTRATION is a
judgement made explicit in the test set, not derived from code structure.
