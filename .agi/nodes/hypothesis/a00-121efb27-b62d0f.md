# hypothesis:a00-121efb27-b62d0f

## Hypothesis

**Claim.** `dispatch.py`'s non-persistent (kid/parent) spawn path is unchanged
by the `--persistent` feature (`goal:g7.28.1`). With `--persistent` absent:
the resolved spawn argv/env is byte-identical to the same spawn on a tree
where the persistent code does not exist; the live path never enters
`_supervise_persistent`; and the agent record carries no persistent keys.

**What would prove it.** A mutation ablation: blank the persistent-only code
(`_supervise_persistent`, `_persistent_stop`, every `if args.persistent:`
block) in a scratch copy of the dispatcher and show the non-persistent
`--dry-run` output is byte-identical (mint ids and tmp dirs normalized), while
a live spawn whose `_supervise_persistent` is replaced by a bomb exits 0 and
never fires it.

**What would disprove it.** Any differing line in the ablated dry-run; the
bomb firing; a `persistent` / `restart_count` key on a non-persistent record;
or a failure in the pre-existing non-persistent dry-run tests.

## Evidence

Probe: `.agi/sessions/iter-DH.151/a00-121efb27/regression_probe.py` (scratch).

- **PART1 ablation parity PASS** — `--dry-run` byte-identical (normalized),
  38 lines, original vs. ablated dispatcher on the same argv and project.
- **PART2 live sentinel PASS** — supervisor bomb never entered; one real agent
  `Popen`; the written agent record carries none of `persistent` /
  `restart_count` (19 keys).
- **PART3 regression suite PASS** — `test_dispatch_dry_run.py` targeted
  subset: 4 passed, 23 deselected.

The sentinel replaces `_supervise_persistent` with a raising callable, so a
non-persistent dispatch that reached it would have crashed rather than passed
silently.

## Near miss

A dispatcher that omits the flag on the command line but still writes
`agent_record["persistent"]` unconditionally would look green in PART1 and is
caught only by PART2's record-key check. An ablation that left a persistent
helper referenced would surface as a NameError, not a diff.
