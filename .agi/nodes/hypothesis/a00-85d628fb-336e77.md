# hypothesis:a00-85d628fb-336e77

## Hypothesis

A **stable transport protocol plus registry lookup** can turn `send.py` into a genuinely thin router even when policy modules are large and mature. The compatibility entrypoint may keep existing verbs, but transport selection should occur through one registry; native seat, signed DM/board, and cross-harness nudge adapters should own their mechanics and return one uniform result. Rotation, dispatch, argv construction, and refusal-policy decisions should not cross the router boundary.

## Why this is the right cut

The current file is the stress case: one long-lived CLI has accumulated inbox, room, signature, nudge, quorum, and harness-safety behavior. Refactoring by moving all of that into three transport modules is unnecessary and risky. The testable claim is narrower: a protocol seam plus lookup can make the dependency direction mechanical while leaving policy behavior unchanged behind adapters.

## Falsifiable contract

An experiment may support this hypothesis only if all four hold on the built bytes:

1. **Router boundary:** the router core imports neither `rotate` nor `dispatch` orchestration and contains no harness-name branch.
2. **Uniform protocol:** every selected transport implements the same minimal call/result shape; the router branches on the registry result, not on transport type.
3. **Behavior preservation:** existing `send`, `read`, `peek`, `audience`, and nudge flows retain their externally observed output and failure behavior through the compatibility facade.
4. **Mechanical extensibility:** a test adds one fake transport module plus one registry row and exercises it without editing the router core.

## What proves or disproves it

- **Supported:** the four-point test passes, including the fake-transport test, and a static import check shows the router is transport-agnostic.
- **Disproved:** adding the fake transport requires a harness/transports-specific branch in the router, or preserving current flows requires the router itself to re-own rotation/dispatch/policy decisions.

## Smallest next experiment

Measure before refactoring: add an AST-based boundary check plus a tiny registry/protocol spike in a test fixture. Do not move production transports until the boundary check demonstrates that the intended seam is expressible. This keeps the experiment small and falsifies the claim cheaply if a stable protocol would merely hide the same `if` soup one level down.
