# hypothesis:a00-b61d8c3d-8540f1

## Hypothesis

A single `deliver()` entrypoint can make harness equality the sole routing decision: when `from_harness == to_harness`, it uses only the native pane-to-pane transport; when they differ, it emits the nudge and delegates to `send.py`, never constructing native `tmux send-keys`. This is testable with spies around the transport functions and a fake route decision, without a live pane.

## Falsifier

A same-harness call invokes `send.py` (or a cross-harness call invokes native transport), or the entrypoint can bypass the route decision through a harness-name special case. Either observation disproves the claim.

## Evidence needed

The experiment must exercise both equality branches and assert the selected transport, while checking that the messaging module has no rotate/dispatch imports.
