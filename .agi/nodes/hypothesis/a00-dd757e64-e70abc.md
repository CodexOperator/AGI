## Hypothesis

The caller-facing send/nudge surface is transport-invariant: a local peer and
a foreign-box (mesh) peer are reached by the SAME function names and args, and
return the SAME result shape; transport selection is engine-internal. Four
conjuncts, all pinned by bytes in
`extensions/agi/tests/test_send_surface_ssh_or_not.py`:

1. **Same names/args.** `send.send_dm(croot, me, to, text, sender)` is called
   identically for both peers — no transport argument, no per-peer branch.
2. **Same result shape both transports.** Each call returns a `Path`; each
   message lands as exactly one block of identical shape (`ts`/`from`/`to` +
   body) in the recipient's conversation, and both calls reach the ONE nudge
   seam (`send._nudge_window`) with only the recipient name differing.
3. **Engine-internal transport selection.** `send._nudge_target(root, <local>,
   None)` resolves a pane; `send._nudge_target(root, <foreign-box row>, None)`
   is `None` — the foreign row's window is not addressable here and the
   remote `mail_poll` cron is the gap-fill, so the caller never chooses.
4. **Zero `is_ssh` in the caller bodies.** Reading `extensions/agi/bin/send.py`
   source bytes, the string `is_ssh` occurs in none of `send_dm`, `send_room`,
   `_nudge_target`, `_nudge_window`, `_announce_nudge`.

**Disproved if** the same call fails/produces a different result shape for one
peer, or a caller-facing body contains `is_ssh`/a transport branch, or
`_nudge_target` resolves the same for both peers.
