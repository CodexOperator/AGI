# hypothesis:a00-c4fb4a06-7c66cc

## Testable claim

A killed seat restarts into the same named tmux pane **even when its window is
not the session's current window**: session-wide enumeration shows exactly one
window named `seat-<hash>`, the same `#{pane_id}`, and `pane_dead == 0` after
restart.

## What was wrong and what was built

Round 1 (`extensions/agi/bin/adapters/tmux_hold.py`) enumerated with
`tmux list-panes -t <session>` **without `-s`**, so it saw only the session's
CURRENT window. With a foreign window current and the seat process dead,
`reattach()` could not see the seat's window, fell through to `start()`, and
issued a SECOND `new-window -n seat-<hash>` -- two panes for one seat, silently.

This round, on the built bytes:

- `panes()` enumerates **session-wide**: `tmux list-panes -s -t <session> -F ...`.
- `reattach()` addresses the pane by its **immutable `#{pane_id}`** captured
  from that session-wide view (`respawn-pane -k -t %N`), not by `session:name`
  re-resolved against the current window.
- `reattach()` **never fabricates identity silently**: if the named pane is
  genuinely gone (its window was killed, not just its process), `start()`
  re-creates it exactly once and stamps an optional `created` out-dict
  (`{"created": True/False, "pane_id": ...}`). `grok_bot_adapter.restart`
  passes that dict and records it on `agent.json` under `tmux`.
- The opt-in cell is unchanged: `harness["tmux"]` unset still uses the direct
  `Popen` path; `grep -c grok` stays 0 in `dispatch.py` and `rotate.py`.

## Regression guard

`extensions/agi/tests/test_tmux_hold.py` -- fake tmux that deliberately models
current-window semantics (a `list-panes` without `-s` returns ONLY the current
window), so dropping `-s` reproduces the duplicate rather than a green lie:

- `panes()` issues the session-scoped form (`-s`) and sees a non-current window;
- `reattach()` with a foreign current window calls `respawn-pane -t %N` and
  issues no `new-window`/`new-session`;
- `start()` reuses the non-current named pane;
- reattach of a genuinely gone pane creates exactly one and records
  `created=True`; reattach of a held pane records `created=False`.
