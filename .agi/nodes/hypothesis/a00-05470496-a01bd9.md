# hypothesis:a00-05470496-a01bd9

## Hypothesis

Every durable held-pane restart path computes the same scrubbed `child_env` as the first-spawn path and passes it into the pane/respawn command. In particular, when `needs_credential` is false, `OPENROUTER_API_KEY` is absent from the environment observed by the held child, even if the controller inherited it.

## Testable claim

An integration probe can enable held restart, replace the real pane command with a recorder, and inspect the environment passed to that command. The claim is supported when the recorder sees no forbidden runtime key and sees the harness variables that `child_env` is supposed to add. It is disproved when the held command sees the inherited key, or when the restart seam has no environment argument and therefore falls back to the tmux server environment.

## Falsifier and scope

A direct unit probe of the hold restart seam is sufficient: mock the pane launcher, invoke the default held restart, and assert that its environment is the output of the selected adapter's `child_env`. A test that only examines a pre-hold `Popen` call does not count, because it cannot distinguish the held path from the first-spawn path. This hypothesis is pending implementation of the hold seam; no production change is made by this node.
