# Held restart sanitizes before it respawns

## Hypothesis

A held restart should use the same credential-filtered environment as the
initial `Popen` path. If the restart branch computes `child_env(...)` before it
returns the held pid, and `tmux_hold` passes that environment when it creates
or reattaches a pane, then a held child receives the intended harness
environment and does not retain `OPENROUTER_API_KEY` when
`needs_credential` is false.

## Test

A focused restart-path unit test should force `HOLD_PANE=True`, hold a fake
pid, and intercept the environment supplied to `tmux_hold.start` (and the
reattach command when applicable). It should assert:

1. `child_env(...)` is called before restart returns;
2. the pane receives the returned environment rather than bare server
   inheritance; and
3. with `needs_credential=False`, the captured child environment omits
   `OPENROUTER_API_KEY` while retaining a marker harness key.

## Falsifier

The claim is disproved if the default held-restart path returns before
computing the sanitized environment, or if a probe of its respawn/reattach
seam still sees the forbidden credential. If tmux cannot accept an explicit
environment, a correctly documented equivalent such as a temporary
`env`-prefixed command is sufficient; silent bare tmux inheritance is not.
