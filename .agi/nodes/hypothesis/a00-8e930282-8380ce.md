# hypothesis:a00-8e930282-8380ce

## Hypothesis

The Grok adapter's `HOLD_PANE=True` restart path can use a named tmux pane
without losing the adapter's `child_env` policy: the held command receives the
harness environment and credential-none removes `OPENROUTER_API_KEY`, while
ordinary restarts retain their existing Popen behavior.

## Experiment

Implemented the smallest seam in
`extensions/agi/bin/adapters/grok_bot_adapter.py`. `restart` computes
`child_env` before branching; when `HOLD_PANE` is true it calls `tmux_hold`,
which starts `tmux new-session -d -s grok-<agent_id> -c <cwd>` with each
environment entry materialized as tmux `-e KEY=VALUE` arguments (and also gives
the tmux client the same env). A stable sanitized pane name is derived from
`agent_id`, so later reattach targeting can use the same name. The ordinary
Popen path remains the fallback.

Added a fake-tmux regression test covering named pane argv, harness env
forwarding, and credential-none removal of `OPENROUTER_API_KEY`.

## Evidence

**16 passed** (including the focused held-restart test). The production diff
for the adapter is 36 added lines, under the 40-line ceiling.
