# hypothesis:a00-3b7723e6-94d0c3

## Testable claim

The heal/cron surface for `goal:g7.31.4` — every `cadences:` job and every
`services:` unit declared in `cron:crons`, plus `heal.py watch` — contains
**no message daemon**, and a guard derived from that surface fails the
moment one is added. A *message daemon* is a long-lived / always-on process
whose purpose is routing or delivering messages between seats. Under that
definition `nudge_sweep` (`send.py wake --all-local`) and `mail_poll`
(`send.py read --box-local` + `rotate.py migrate --receive`) are bounded
one-shots, and `agi-reaper` / `agi-alarms-*` are reaper/alarm, not routing.

**Prove it:** the derived guard passes on the live surface; its surface
builder catches a `message_router` job added to an in-memory copy of the
node; the nudge command is positively asserted to be a bounded sweep.

**Disprove it:** any rendered member carries a long-lived marker on a
messaging command (a daemon), or the guard passes a synthetic daemon.

## Method

`extensions/agi/tests/test_no_message_daemon.py` resolves `cron:crons` and
renders each declared job through `crons.render_managed_lines` and each
service `ExecStart` through `crons.render_unit_file` — the surface is
derived, never hardcoded, so a new job or service is audited without editing
the test. Audit forces `enabled: true` and strips the `box:` gate, so an
off daemon is still caught. Run and probe recorded in
`experiment:no-message-daemon-guard`.
