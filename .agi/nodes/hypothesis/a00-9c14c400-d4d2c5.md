# hypothesis:a00-9c14c400-d4d2c5

## Hypothesis

A durable **named tmux pane hold** can be added to the grok-bot adapter's
`restart` WITHOUT touching `dispatch.py`/`rotate.py` and WITHOUT changing the
default restart: `restart(hold_pane=True)` runs the adapter's one
`build_command` argv inside ONE tmux pane whose name derives from the seat
identity (never a pid). Repeated restarts reuse that same pane; killing the
process leaves the pane; with tmux absent it falls back to today's `Popen`.

**Proves it:** a recording tmux shim on PATH shows exactly one `new-session`
for the first restart and a `respawn-pane` at the same name for the second; a
genuine SIGKILL leaves the `list-panes` view intact; the default restart makes
zero tmux calls; the committed restart/adapter tests stay green.

**Disproves it:** two different pane names; a second `new-session`; the pane
vanishing with the pid; a second argv path; a tmux call on the default
restart; or any existing restart-contract test going red.

**Scoped:** only the pane name needs to derive from the seat id here. The
measured CLI argv (`goal:g7.31.1.1`) and the persistent-dispatch hold
(`dispatch.py::_supervise_persistent`) are out of scope and named as residue.
