# hypothesis:a00-a4b770f8-4a44d0

## Hypothesis

A single live occupation read for a seat row — the row's pinned tmux `window`
@id versus the live @id for the seat name, AND the row's `pid` liveness —
is enough to tell a formation/pin reader whether the seat is genuinely held,
without ad-hoc pane scrapes.

Testable claim: after `seat start`, the posts/seat registry reads `occupied`
iff the pinned `window` @id is the live tmux @id for that seat name and the
row's `pid` (when positive) is alive; a foreign or absent window reads
`unoccupied`; a stale pin or a dead pid reads `pane-drift`; when no seam is
given no occupation is computed and the render stays byte-identical.

## What landed

The READ half is landed in this worktree as `seat_status.seat_occupation` plus
the optional `collect(..., tmux_session=, window_path=)` seam and the
`_occ_cell` occupation cell in `to_markdown`/`to_compact`, with the
`--tmux-session`/`--window-path` CLI wiring. Evidence node:
`experiment:seat-occupation-view` (71 tests green, 9 of them new).

## Falsifier

If a registry row can read `occupied` while its pinned @id does NOT match the
live tmux window for its seat name, or while its positive pid is dead, the
claim is false. Symmetrically, if a foreign window or no window at all can
read `occupied`, or if supplying no seam changes any rendered byte, the claim
is false.
