# hypothesis:a00-c4c1d7e9-7bba21

## Hypothesis

Two residues remain in `extensions/agi/bin/profile_sync.py` after the
`cmd_loop` guard was wired (kid `a00-429760b1`):

- **D — the `unreadable` heuristic reads the WHOLE FILE.** Both the
  `"profile_ref:" not in raw` presence guard and `_raw_profile_ref`'s regex
  scan the entire raw text. A malformed **unlinked** node whose body prose
  merely mentions `profile_ref:` (there are live nodes that do) is misfiled as
  a linked-but-`unreadable` node: `--all` exits 1 and the rotate guard refuses
a clean rotation — the P7 false-positive class through a different door.
- **E — the except-branch `read_text` is unguarded.** It can itself raise
  `OSError` (permission, race, deleted file), escaping `check_all` and turning
  into a rotation-blocking crash message.

Claim: scoping the heuristic to the **frontmatter block** (text between the
leading `---` and the next `---`) makes a prose-only mention a clean no-op while
a frontmatter mention stays a named `unreadable` refusal; and guarding the
recovery `read_text` makes every path through `check_all` return a named row
rather than raise.

Proved by:
- a malformed unlinked node with `profile_ref:` only in body prose -> `--all`
  exits 0, `1 linked, 0 not ok`, guard returns None;
- the same file with `profile_ref:` in its frontmatter -> `--all` exits 1,
  `UNREADABLE ... broken.md`, guard refuses naming it;
- `Path.read_text` raising `OSError` on the recovery read -> a named
  `unreadable` row (detail `PermissionError: ... Permission denied`), guard
  refuses naming the path, no exception escapes.

Disproved by: the prose case still exiting 1, the frontmatter case exiting 0,
or any `check_all` call raising.

Child experiment: `experiment:malformed-sibling-clean-noop`.
