pane/session pin matching `tmux`" holds on REAL tmux bytes, not only on the
fixture seam.

Testable claim, split in two:

1. **PANE half.** `rotate._successor_window_id(seat, session, None)` returns
the real `@id` from `tmux list-windows`; `rotate._successor_row_write(...)`
writes that token into the row's `window` cell; and
`seat_status.seat_occupation(row, session, None)` reads `occupied` with
`window == live`.

`_backfill_session_ref` (`rotate.py:2854`). So immediately after seat start
`session_ref` and `session_name` are empty.

that turn the same row to `pane-drift` / `unoccupied`.
Disprove: the occupied read or the `@id` match failing against a real server,
or seat start actually carrying a non-empty `session_ref`.
