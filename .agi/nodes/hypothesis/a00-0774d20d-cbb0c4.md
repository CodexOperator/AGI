# hypothesis:a00-0774d20d-cbb0c4

## Hypothesis

`write.py create` — the mint half of the verb layer — did NOT keep a linked
node driftless at birth. DH.72 closed the EDIT route (one
`profile_sync.refuse_effective_ref` called by `submit` and by the dry-run
preview), but `create` ran no effective-ref judgement and performed no
projection, so:

- `write.py create hypothesis x --set profile_ref=../escape.md` returned
  **rc=0** and minted a node carrying a ref the edit route refuses at rc=2;
- `write.py create hypothesis x --set profile_ref=profile/out.md` (legal)
  returned rc=0 but **wrote no artifact** — a newly linked node was drifted
  by construction until a later edit touched it;
- the same create under `--dry-run` printed as if it would succeed.

Claim: routing the create path through the SAME
`profile_sync.refuse_effective_ref` before `write_node`, and through the same
`profile_sync.sync_node` after a successful mint, makes create refuse an
illegal effective ref by name at rc=2 with nothing written, project a legal
ref in the same action, and leave the unlinked create untouched. Disproved if
any create probe still mints a node with an illegal ref, returns rc=0 for an
illegal ref, or returns rc=0 without an artifact for a legal ref.

## Experiment

`write._profile_ref_refusal(root, node_id, set_fm)` is the create-side name
for the one rule: it calls `profile_sync.refuse_effective_ref` and returns the
refusal string. `main` calls it in the create branch **before** the dry-run
short-circuit, so a dry run refuses what the real mint refuses;
`create()` calls it before `write_node`, so a refused mint leaves no node and
no artifact behind; and a successful `create()` calls
`profile_sync.sync_node(root, res.node_id)` (catching `NoRef` as the unlinked
no-op) so a legal ref lands in the same action. The rule is not copied — both
callers reach the same `refuse_effective_ref` the edit route uses.
