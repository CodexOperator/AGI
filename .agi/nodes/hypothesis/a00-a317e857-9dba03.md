## Hypothesis

`extensions/agi/bin/ingest_session.py` can keep its no-silent-drop invariant
over *arbitrary* session ids by making its idempotence key **injective**: a
canonical UUID keeps the bare slug `grok-session-<uuid>` (so the real corpus
and the node already in the graph stay idempotent), and every other raw id gets
a `sha256(raw_id)[:8]` suffix, so two distinct ids that sanitize alike address
different files.

Testable claim, continuing `hypothesis:a00-dee8ad86-1ab674` whose second probe
failed: `Probe-aaaa-1111` and `probe_aaaa_1111` (distinct ids, same sanitized
shape) ingest as TWO nodes, each carrying its own raw `source_session`; a
same-fixture re-ingest still prints `INGEST skip <id>` and mints nothing; a
canonical UUID re-ingest still prints `INGEST skip` on the bare slug.

Proved by: the child experiment node's raw transcript. Disproved by: the second
of the colliding pair printing `INGEST skip`, or one node file serving both
sessions.

## Mechanism

Two disjoint cases in `slug_for`, and the file's existence remains the
idempotence key via `write_node(..., on_exists=SKIP)`. The UUID branch is
guarded with `sid.lower()` so UUID case-insensitivity is preserved (case is not
significant in a UUID), while case-variant non-UUIDs still receive distinct
hashes. Nothing else in the CLI changed.
