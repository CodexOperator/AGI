# hypothesis:a00-a66c4705-cb17ab

## Hypothesis

`dispatch._open_round` can be the single production launch seam for both the first persistent spawn and every later reopen if it delegates to a durable-seat adapter, rather than choosing `Popen` itself. The adapter must return both a pollable process handle and launch provenance: `created=True` only when this call actually founded the stable named pane, and `created=False` when it reused an existing hold. A fallback `Popen` must return `created=False` when the durable adapter was not the creator.

This checkout currently has no `extensions/agi/bin/adapters/tmux_hold.py`, despite sibling `goal:g7.31.1.2.3` naming it. Therefore the first implementation must either create that missing adapter as a graph-backed build under the sibling goal or deliberately implement the equivalent seam here; silently optional-importing an absent module would preserve the defect under the name of a seam.

## Test

Drive the production `_open_round` closure through `dispatch.main()` with the durable adapter faked at its module boundary: first invocation creates stable pane `@7` and starts the child; child death causes the same closure to reopen; the second invocation reuses `@7` and reports `created=False`; a no-tmux case falls back to `Popen` and also reports `created=False`. Assert the calls, identity, provenance, log, cwd, and environment rather than merely importing a helper.

A second, narrow real-tmux probe may start a harmless fixture child in an isolated tmux server/session, kill only that child, and reopen through the same closure. It must observe the same pane identity; cleanup must remove only the isolated session.

## What would prove it

1. The first production dispatch crosses the durable adapter boundary while tmux is available; it does not directly call `Popen`.
2. The reopen is the same closure and resolves the same named pane identity.
3. The manifest/launch record carries the adapter's actual `created` result: true only for the creating launch, false for both reuse and fallback.

## What would disprove it

Any one falsifies the claim: production first spawn still calls `Popen`; restart adopts a different pane; `created=True` is inferred from intent rather than returned by the launch; or the fallback is represented as pane creation.

## Scope

This node owns only the first-spawn/reopen handoff in `extensions/agi/bin/dispatch.py` and focused tests. Child-env transport remains `goal:g7.31.1.2.1`; the missing adapter build node and explicit no-tmux fallback ownership remain `goal:g7.31.1.2.3`. This round made no production change, so no line-budget claim is offered.
