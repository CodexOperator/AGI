# hypothesis:a00-4053c10d-df152b

## Hypothesis

The native handback seam can satisfy the parent goal's smallest falsifier
without a message daemon: a `send.py` call initiated from a grok pane can
record one message in the recipient inbox and a distinct small wake token in
the recipient pane, while caller-visible function names remain unchanged for
local and SSH-mesh peers. The graph's `config:seats` authorization, rather
than the pane string, must be the identity input.

**Proves it:** an experiment using the real `send.py` seam and a fixture with
one local and one SSH-mesh recipient shows both inbox landing and a separate
nudge for each; the same send/read/nudge functions and arguments are used in
both cases; and no new process appears in the heal/cron surface.

**Disproves it:** inbox landing without a separate pane nudge, a wake token
that contains the message body, authorization depending on pane text, or
caller branching on SSH status.

**Scope:** This is a behavioral claim about the existing seam, not a request
for a new transport or daemon. The current scaffold has no experiment run, so
the claim remains pending until one cites concrete bytes or a capture.
