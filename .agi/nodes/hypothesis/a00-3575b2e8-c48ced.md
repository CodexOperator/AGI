# hypothesis:a00-3575b2e8-c48ced

## Hypothesis

If `HOLD_PANE=True` makes tmux hold the default restart path, then the held path must be semantically equivalent to the direct-`Popen` path for environment policy: compute one adapter `child_env(...)` before the held pid is returned, and pass that exact mapping through `tmux_hold.start`, reattach/respawn, and `_cmd` into the tmux pane. A pane may not fall back to the older tmux server's ambient environment.

The test should drive restart with a fake `needs_credential=False` harness, a base containing `OPENROUTER_API_KEY=forbidden`, and a unique harness `env` marker. It should capture both the tmux command and the environment passed to it. **Proved** means the captured environment contains the marker and omits `OPENROUTER_API_KEY` on both initial hold and reattach/respawn. **Disproved** means either the hold path never receives an explicit env, leaves the forbidden key present, or drops the harness marker. An argv containing the secret does not count as a passing implementation.

## Why this shape

The boundary worth testing is the handoff from adapter policy to tmux, not another unit test of `child_env`: `drop_unneeded_credential` is already centralized, while the reported defect is the early return from the held path before that policy runs. The experiment should therefore spy at the tmux seam and assert the final child environment on every held transition.
