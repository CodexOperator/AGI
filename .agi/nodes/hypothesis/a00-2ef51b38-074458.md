# hypothesis:a00-2ef51b38-074458

## Hypothesis

`tmux_hold` should be one small adapter-level hold seam, not tmux logic copied into each harness adapter. A caller should provide the durable attach/spawn operation plus a direct `Popen` fallback; when tmux is absent, the configured session is unset, or the named pane cannot be found, the seam should invoke that fallback and return its pid. Adapters that do not opt into named-pane durability should continue through their existing direct-spawn path unchanged.

## Why this shape

The named file `extensions/agi/bin/adapters/tmux_hold.py` does not exist on this tip, so `goal:g7.31.1.2.3`'s grid-coverage defect is real rather than stale. The four current adapter `restart` implementations each own a direct `subprocess.Popen` path, while `rotate.py` owns the tmux launch seam. A shared hold helper can therefore compose the two existing seams without special-casing a harness name in `dispatch.py` or duplicating tmux error handling in every adapter.

## Falsifier

**Proved** if a focused experiment builds `tmux_hold.py` and tests all three no-hold conditions (tmux executable unavailable, session unset, pane missing), with a fake `Popen` proving each path returns the fallback pid; it also proves the no-tmux path never calls attach and the success path never calls fallback.

**Disproved** if a shared seam must infer harness-specific argv, record mutation, cwd, environment, or log policy; or if opting one adapter into hold changes direct restart for unconfigured harnesses. That would show the seam is not actually common and belongs inside one adapter instead.

## Next experiment

Measure pre-fix state, build the helper and its focused tests, then prove both branches. A build node must be minted from the experiment's MVP so grid coverage and the payload arrive together.
