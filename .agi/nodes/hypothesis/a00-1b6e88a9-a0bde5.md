## Hypothesis

`write.py`'s `--dry-run` preview and `profile_sync.py`'s CLI both reported a
state the real path refuses. DH.69's accepted fix (tip c8ec39312) validated
the EFFECTIVE `profile_ref` inside `submit()` only, so a dry run of an edit
the real run refuses printed as if it would succeed (dry rc=0, real rc=2);
and `profile_sync.project()` raised a bare `FileNotFoundError` for a missing
node id that `main()` did not catch, so the CLI tracebacked at rc=1 instead
of naming the refusal at rc=2.

Claim: ONE effective-ref helper called by BOTH `submit()` and the dry-run
preview makes the two agree on all four cases (illegal on-disk ref + body-only
edit; illegal ref SET by the edit; legal ref; `unset profile_ref` repair),
and a missing node id becomes a named refusal at rc=2. Disproved if any dry
run still diverges from the real run, or the library `FileNotFoundError`
contract for `project()` is broken.

## Experiment

`profile_sync.refuse_effective_ref(root, node_id, set_fm, unset_fm)` is the
one helper: it resolves the `profile_ref` the write would LEAVE on the node
(this edit's `set profile_ref` if it carries one, else the on-disk value; an
`unset profile_ref` leaves none) through `validate_ref`, returning the
resolved path or None. `submit()` calls it before `update_node` and re-raises
`Refused` as `EditError`; `_preview_dry_run_gate` calls it and on `Refused`
prints `ERR: profile projection refused: ...` to stderr and returns 2. A dry
run writes nothing on every path, so no partial write is possible.
`project()` still raises `FileNotFoundError` (the library contract is intact);
`main()` catches it and prints `REFUSED: no node file for <id>` at rc=2.
