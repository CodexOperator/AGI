# hypothesis:a00-db1af771-f25152

## Hypothesis

For the `grok_bot` harness, the argv a spawn actually emits can be bound to a
measured `grok-bot --help` rather than to the practice stub's guessed flags.

**Testable claim.** `adapters.load("grok_bot").build_command(...)` emits the
**bare resolved bin** — `[resolve_bin(harness)]` — because the measured
`grok-bot --help` (grok-bot-cli@0.3.1, 46 lines, exit 0) documents no seat
argv flag, and the stub-only guesses `-p` and `--model` are absent from the
landed adapter path on this branch.

**Would prove it.**

1. A verbatim `--help` capture pasted onto a child experiment, with
   `build_command` argv every flag-token of which appears in that capture and
   `argv[0] == resolve_bin(harness)`, plus `-p`/`--model` absent from argv.
2. `grep` proof that neither `"-p"` nor `"--model"` remains in
   `grok_bot_adapter.py`, and a call with `context_file="-p /tmp/x"` still
   returns a bare bin.
3. The tier contract survives: a declared `models` block with the tier absent
   still raises a `KeyError` naming the tier on the spawn path, never a
   silent fallback.
4. `$GROK_BOT_BIN` beats a harness `bin` sentinel in `argv[0]` — the call
   site threads the live cell, so a constant cannot pass.

**Would disprove it.** An argv token the capture does not document; `-p` or
`--model` still present in the adapter path; a missing tier silently falling
back to another model; or `argv[0]` frozen to a constant/BYO default instead
of the resolved bin.

**Out of scope (parent `goal:g7.31.1`):** durable named tmux pane hold /
reattach (`goal:g7.31.1.2`), pane↔post wiring, five unified routes.

## Result

Proved on this base. See `experiment:a00-db1af771-grok-help` for the capture,
before/after grep, probes and test run.
