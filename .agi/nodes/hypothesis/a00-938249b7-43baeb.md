# hypothesis:a00-938249b7-43baeb

## Hypothesis

**The harness pair is the whole routing decision.** `goal:g7.32.2` asks for
two paths:

- **same harness** (grok→grok): native pane send, never shells out to
  `send.py`;
- **cross harness** (grok→claude/pi): a nudge artifact, **then** `send.py`
  as transport.

The claim is that `classify(sender_harness, recipient_harness)` — equality
of the two harness names and nothing else — picks between them, and that the
cross path is expressible as nudge-artifact-then-`send.py`-subprocess with
the seam's own direct imports free of `rotate`/`dispatch` (falsifier 3).

**The measured surprise is the transport, not the seam.** `send.py` imports
`rotate` at 7 sites and reaches 6 `rotate` internals. The seam's direct
import set is clean either way — `import send` would not add `rotate` to the
seam's own imports — so falsifier 3 does not by itself force a subprocess
boundary. What the `send.py` coupling does change is the seam's **transitive**
surface: an in-process seam drags the whole rotate orchestration into its
runtime, a subprocess seam does not, and `goal:g7.32.4`'s "send.py is thin"
premise is currently false in the tree.

## Testable claim

1. `classify` returns `native` on a same-harness pair with **zero**
   `send.py`/subprocess calls, and `cross` otherwise.
2. The cross path's trace carries the nudge artifact **before** the
   `send.py` invocation.
3. The routing seam's import set ∩ {`rotate`, `dispatch`} = ∅, while
   `send.py`'s `import rotate` sites > 0 (7).

**Proved** if all three hold on a measured run. **Disproved** if either
path can be produced without the pair deciding it, if the cross trace
cannot show nudge-then-send, or if `send.py` turns out to import neither
`rotate` nor `dispatch` (in which case the send.py-not-thin finding is
empty).

## Why it matters

`goal:g7.32.4` wants `send.py` thin, and `goal:g7.32.2` forbids the
messaging module from importing rotate/dispatch internals. The seam can pass
falsifier 3 by direct imports alone, but an **in-process** seam would pull
the entire rotate orchestration into the messaging runtime, because
`send.py` is not the thin router g7.32.4 assumes — it carries 7 `rotate`
import sites itself. Choosing the subprocess boundary keeps the messaging
runtime's transitive surface bounded and makes the choice reversible when
g7.32.4 actually thins `send.py`.
