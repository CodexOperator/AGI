# hypothesis:a00-92c2e394-eddf1e

## Hypothesis

`grok_bot_adapter.py` can carry an OPTIONAL pane surface (`pane_attach`,
`pane_send`, `pane_read`, `PaneNotHeldError`) as ordinary methods on the SAME
module, discovered by `hasattr` and never added to `adapters.REQUIRED`. The
methods WRAP a pane already held (a tmux name; the durable hold stays
`goal:g7.31.1`'s) and fail CLOSED on a NAMED error when no pane is held —
they never hang and never open a fresh pane. Harnesses without panes simply
omit the methods.

**Prove:** `hasattr(grok,'pane_attach')` True and `hasattr(pi/claude_code,_)`
False; all three methods raise `PaneNotHeldError` (a `RuntimeError`) naming
the seat when no pane is held, under a bounded timeout; exactly one grok
adapter module; existing grok tests unchanged and green.

**Disprove:** any pane method hanging, returning a fresh pane, or the surface
being required (in `adapters.REQUIRED`) / duplicated into a second module.

## Result — PROVED on the built bytes

Implemented append-only in `extensions/agi/bin/adapters/grok_bot_adapter.py`;
the REQUIRED surface is byte-unchanged and `adapters.REQUIRED` is untouched.
`harness['pane']` is the adapter's own pane-name cell (a `str` or
`{seat: name}`); `tmux_session` supplies the session, defaulting to the bare
name `agi-rc` — no `/home/<user>` literal is baked in. `pane_attach` verifies
the held pane with one real `tmux select-window` and is idempotent (a repeat
makes no second call and opens no second pane); `pane_send`/`pane_read` wrap
`send-keys`/`capture-pane`. `dispatch.py` and `rotate.py` are untouched
(already zero grok hits).

New sibling test `extensions/agi/tests/test_grok_bot_pane_methods.py` (11
tests): feature-detect on/off, exactly one grok module (`grok_pane_adapter.py`
absent), named fail-closed error for all three methods, no tmux shelled and
no fresh pane on failure, a bounded-subprocess proof the call raises rather
than hangs, idempotent attach, config-cell resolution, and send/read argv.

**Interpretation note (documented judgement call).** The parent brief named
`pane_attach(name)` and "no held pane" but left the hold seam open. This round
reads the hold from the adapter's own config cell (`harness['pane']`) and from
the adapter's attachment registry; it does not consult the seat registry. A
follow-up could bind the cell to the live `seats.md` `window` pin of
`goal:g7.31.2.1` instead — that is the natural next increment, not a defect
