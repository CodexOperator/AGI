# hypothesis:a00-65c858a3-3ebc30

## Testable claim

A durable *named* tmux pane can be the seat's hold point through the adapter
seam: a seat starts in a deterministic named pane; when its process is killed,
the adapter's restart re-enters the **same pane identity** (same window name
and same `#{pane_id}`), not a fresh anonymous pane and not a second pane of
the same name.

**Pane-identity predicate used:** `window_name == pane_name(agent_id)` AND
exactly one pane carries that window name AND `#{pane_id}` after restart equals
`#{pane_id}` before AND `pane_dead == 0` after. `pane_name()` is
`"seat-" + sha1(agent_id)[:12]`.

## Build

- `extensions/agi/bin/adapters/tmux_hold.py` — generic seam: `enabled`,
  `pane_name`, `start` (create the named pane only if absent) and `reattach`
  (`tmux respawn-pane -k -t <session>:<name>`, never a second `new-window`).
  `remain-on-exit on` keeps the dead pane listed, so its `#{pane_id}` survives
  process death.
- `grok_bot_adapter.restart` routes through `tmux_hold.reattach` when
  `harness["tmux"]` / `harness["pane"]` is truthy, and stamps the returned pane
  pid on the record. With the cell unset the direct-`Popen` path is
  byte-for-byte unchanged (existing restart tests stay green).
- No edits to `dispatch.py` / `rotate.py`; `grep -c grok` is 0 in both.
