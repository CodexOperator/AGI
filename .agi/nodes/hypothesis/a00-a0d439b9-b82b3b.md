# hypothesis:a00-a0d439b9-b82b3b

## Hypothesis

The first-spawn defect in `goal:g7.31.1.2.2` is best prevented at the single production boundary in `dispatch._open_round`: whenever the seat is configured for held execution, that boundary should ask `tmux_hold` to start or reattach a named pane before falling back to direct `Popen`, and should return the same stable pane identity on the subsequent recovery. This keeps pane creation and restart on one path rather than adding a second out-of-band start call to the experiment.

## Test

A focused probe of `_open_round` with the hold path enabled should observe `tmux_hold.start`/reattach and a non-empty stable pane id on first launch; after simulating a killed child and retrying, the same pane id should be used. The probe should also assert that the direct-`Popen` branch is reached only when held execution is unavailable or explicitly disabled, and that no `created=true` field is fabricated on that fallback.

The claim is proved if the first-launch probe and recovery probe both satisfy those observations. It is disproved if first launch still calls `Popen` directly, if pane identity changes after recovery, or if the fallback fabricates the hold metadata. This remains a test seam to be implemented and exercised in a later experiment; this node makes the acceptance boundary explicit.
