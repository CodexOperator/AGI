# hypothesis:a00-810b8e08-548ae9

## Hypothesis

A `spawn_check: unverified` stamp whose reason is exactly `spawn_gate`'s
"schema '<T>' is discriminated on '<D>', which this node does not set" is
FALSE once the node's frontmatter supplies `<D>`, and it must not survive the
update that supplies it. `node_writer.update_node` is the one place to fix it,
because it is the one routine every writer path routes through.

**Proved by:** a build node minted without `build_kind`, then updated with
`set build_kind=code`, has neither `spawn_check` nor `spawn_check_reason` in
its frontmatter afterward, while a node carrying a legitimate unverified
reason (an unresolved parent) keeps both. Five real build nodes on the tip
(`agi-brief-drafting.js`, `agi-round-review.js`, `workflow.py`, `review.json`,
`drafting.json`) are cleared through `write.py`.

**Disproved by:** the stamp surviving the update, or a blanket clear removing
the unresolved-parent reason.

## Scope

Parent `goal:g7.32.2` residual round DT.92, residue 1 (primary). Residue 2
(count is 5, not 6) and residue 3 (`## Agent Notes` on the parent) are
recorded on `goal:g7.32.2` itself.

## What was done

- `spawn_gate.does_not_set_reason(name, discriminator)` — one generator for
  the message; `SpawnSchema.rule_for` now calls it.
- `node_writer._clear_stale_does_not_set_stamp` — called from `update_node`
  after the `set_fm` merge; drops both stamp fields only when the update
  supplies the schema discriminator and the pre-existing reason equals that
  exact text.
- Regression: `extensions/agi/tests/test_node_writer.py` (two new tests, plus
  a discriminated `[build].md` in the throwaway fixture).
