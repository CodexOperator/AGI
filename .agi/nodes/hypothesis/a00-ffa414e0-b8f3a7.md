# hypothesis:a00-ffa414e0-b8f3a7

## Claim

A newly registered send-verb transport is **reachable AND dispatched** through
`send.py`'s live `main()`, with no per-transport `if` in `main` and no
ambiguity against the inbox catch-all. Proved by: `choose` picks the **first
matching row in table order**; `register(..., first=True)` places a row ahead
of the catch-all; and the row carries its **dispatch callable**, which `main`
runs.

Disproved by: a registered send-verb row being unreachable, shadowed, or
running the wrong (built-in) dispatch while the built-in still fires.

## What changed (this checkout, DH.198)

- **`extensions/agi/bin/send_router.py`** — `Choice` gains `dispatch`; `_RUN`
  holds externally registered dispatch callables; `register()` gains
  `dispatch=` and `first=` (inserts ahead of every row; appended rows are
  shadowed by the inbox catch-all — the parent's defect in new clothes);
  `choose()` is now first-match-in-table-order, so ambiguity-by-complement is
  gone.
- **`extensions/agi/bin/send.py`** — the three inline dispatch bodies (room /
  dm / inbox) moved out of `main` into module-level
  `_dispatch_room` / `_dispatch_dm` / `_dispatch_inbox`. `main` now does
  `row = send_router.choose("send", args)` then resolves the callable from
  this module's own `_DISPATCH` map (built-ins) or `row.dispatch` (registered
transports) and runs it. **No per-transport branch remains in `main`.**
- **`extensions/agi/tests/test_send_router_live_dispatch.py`** (new) — the
  clause-(2) mechanism.

## A real defect the build surfaced (fixed)

Moving dispatch into the router's **process-global** `_RUN` was wrong: a second
`send` module instance (`import send` from `mail_alert`/`rotate` under pytest)
registered its own built-in dispatch, and the test module's `main` then ran the
other instance's helpers — the prime DM gate fired with the *real* seats table
against a tmp fixture root. Fixed by resolving built-ins from `send.py`'s own
`_DISPATCH` map; only **externally registered** transports use the shared
`_RUN`. This is why a global registry could not carry the built-ins.
