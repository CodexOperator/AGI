# hypothesis:a00-aba59771-204b39

## Hypothesis

**Claim: the `--persistent` seat record is occupation-honest on every
supervisor exit path.** After `_supervise_persistent` returns, the persisted
record carries `persistent_state` in `{stopped, exhausted, failed}` and
`pid is None`, so no dead child's pid is presented as the live occupant —
and the manifest entry and the session `agent.json` agree, because the
supervisor mutates the same dict `_merge_manifest` writes.

This is the residue the parent round's probe C falsified: with
`max_restarts=2` and an instantly-dead `reopen`, the old supervisor exited
the loop but left `persistent: true`, `pid=9002` — a dead pid named as the
live occupant. A reader could not tell "held seat running" from "hold
finished" without re-deriving liveness.

- **Prove it** if every exit path (`_persistent_stop` clean stop,
  `restarts >= max_restarts`, `reopen` raising) writes a terminal
  `persistent_state` and clears `pid`, on both the manifest and the session
  `agent.json`.
- **Disprove it** if any exit path leaves `persistent_state == "running"`,
  or leaves a `pid` that no live process holds.

## Why this version differs

`_supervise_persistent` gained a `state` cell set at spawn and on each exit
(`stopped` via the `while … else`, `exhausted` at the restart bound,
`failed` on a `reopen` exception), plus a terminal write that nulls `pid`.
`persistent: true` still means "this round asked for persistent"; the new
cell is what disambiguates an occupied seat from an ended hold.

## Probes

- **gate — max_restarts=0, dead child:** `reopen` never called;
  `persistent_state == "exhausted"`, `pid is None` on record and agent.json.
- **gate — `AGI_PERSISTENT_STOP=1`:** no restart; `persistent_state ==
  "stopped"`, `pid is None`.
- **wire — max_restarts=2, instantly-dead `reopen` (the failed case):**
  2 reopens; `persistent_state == "exhausted"` (`!= "running"`), `pid` is
  not any re-opened dead child's pid and is `None` on both surfaces.

All three pass; see `experiment:a00-aba59771-honest-exit`. The
`--detach`/manifest merge needed no change: `agent_record` is the same
object appended to `new_records`, so the terminal state rides the existing
merge.
