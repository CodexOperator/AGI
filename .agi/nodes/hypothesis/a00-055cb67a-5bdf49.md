## Hypothesis

`magic_pane.deliver(from_harness, to_harness, text, ...)` is the enforcing
entrypoint the router lacked: it consults `route()` and selects the transport
SOLELY from that verdict, and it REFUSES a caller-supplied transport that
contradicts the verdict, by name. Built and measured this run, unit/hermetic
only — no live tmux pane, no live send.py process, no network.

```
  deliver(from,to,text)
        │
        ├─ verdict = route(from,to)          # equality only, no name literals
        │
        ├─ requested_path contradicted verdict?  ──▶ ValueError naming BOTH
        │
        ├─ "native"     ──▶ native_send(pane_target, text)   # tmux, never send.py
        └─ "nudge_send" ──▶ cross_send(..., nudge_dir)       # artifact FIRST, then send.py
```

Proved on the built bytes if: (1) the same-harness path emits exactly the
`tmux send-keys ... Enter` argv and invokes send.py zero times; (2) the
cross-harness path writes the nudge artifact before send.py is invoked, calls
send.py exactly once, and never invokes tmux; (3) a contradicting request is
refused by name before any transport call. Disproved if any transport is
chosen from anything but `route()`, or a contradiction slips through.
