## Hypothesis

The first production dispatch is a durable named-seat seam: the dispatcher must
reach a named, inspectable process (the current seam is expected to be a
`subprocess.Popen` child with `start_new_session=True`, not a tmux pane).

**Proved** if the first-spawn path is directly exercised with a fake child and
shows a process launched from the rendered argv, with a durable session/process
identity recorded for recovery. **Disproved** if the production path has no
actual first-spawn seam, or if it launches only a fire-and-forget shell with
no recoverable identity. The existing persistent-dispatch test is a useful
falsifier: it requires argv identity across restart and a live-pid manifest
record, but does not by itself prove tmux naming.
