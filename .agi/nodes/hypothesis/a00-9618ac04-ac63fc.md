# hypothesis:a00-9618ac04-ac63fc

## Hypothesis

**A tmux hold that DECLINES is a hold; a tmux hold that RAISES is a brick.**

`extensions/agi/bin/adapters/tmux_hold.py` should expose ONE seam —
`hold_or_none(harness, agent_id, argv, *, cwd, log_file) -> int | None` — that
returns the seat's pane pid when the hold happened and `None` for every other
outcome, with no exception ever crossing the boundary. `grok_bot_adapter.restart`
calls that seam first and runs its existing `subprocess.Popen` path untouched
when it gets `None`. So: with tmux absent, or with no session name configured,
**restart still returns a real pid and still stamps the record.**

The reference `_session()` raised `RuntimeError("no session name")`, and a
default-on hold then died before any `Popen` — the seat could never restart.
The claim is that replacing the raise with a `str | None` resolver plus a
sentinel-returning entry point, *and actually calling it from `restart`*, is
the whole fix.

## What would prove it

1. `grid_coverage_check` (or a build `payload_ref`) covers `tmux_hold.py`, and
2. with `tmux` off PATH, `grok_bot_adapter.restart` returns a pid via Popen and
   stamps `agent.json`; and
3. with no session name resolvable, the same — no exception escapes; and
4. the inverse: when the hold DOES succeed, the pane pid is returned and
   `Popen` is never reached (so the seam is wired, not merely present).

Point 4 is the half that distinguishes this from a module that satisfies the
prose and loses the mechanism. A `hold_or_none` that is defined, unit-tested
against a fake `_run`, and never called from `restart` proves nothing about
seats — and would be the near miss this node is written against.

## What would disprove it

Any of: `restart` returning `None` or raising when tmux is unavailable; a
held restart leaving `agent_record` unstamped (the seat then reads as dead to
`is_alive`); or `Popen` still being called on the held path.

## Outcome

BUILT and measured on the built bytes — `experiment:tmux-hold-fallback-probe`
(10 new tests in `extensions/agi/tests/test_tmux_hold_fallback.py`; 84 passed
across the adapter/credential suites, 137 in `test_dispatch.py`). All four
prove-conditions hold. The module, the mvp contract, and the build node landed;
the measured 134 production lines exceed the 40-line ceiling and carry a
re-brief request in the experiment node.
