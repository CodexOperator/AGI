# hypothesis:a00-48126e22-639371

## Hypothesis

Against a **REAL tmux 3.4 server** (never a fake), the durable named-pane seam
`extensions/agi/bin/adapters/tmux_hold.py` (branch tip `c9ba12428`) holds a
seat's pane across a real process death: after `kill -9 <pane_pid>` and
`reattach(...)` the seat re-enters the SAME `#{pane_id}` and the SAME window
name, only `#{pane_pid}` changes, and the `created` dict reports
`created=False`. A genuinely destroyed window (real `tmux kill-window`) is
re-created exactly once with `created=True` and a NEW `#{pane_id}`.

## Testable claim

Kill the seat process of a real-tmux-backed seat; `reattach` re-enters the
same `#{pane_id}` (same pane, not a fabricated second one) with
`created=False`; a really killed window is rebuilt once with `created=True`
and a new `#{pane_id}`.

## Falsifier / disproof

Any captured `tmux list-panes` where (a) `#{pane_id}` changes on plain process
death, (b) the window name drifts, or (c) a destroyed pane is silently handed
back as if held (`created=False` for a pane with a new `#{pane_id}`).

## Method — standalone command sequence, zero production lines

The seam was materialized in session scratch
(`git show c9ba12428:...tmux_hold.py`), never edited in the repo. The driver
(`run_experiment.py`) used a throwaway session `hold-exp-a00-48126e22` and
harness `{"tmux": True, "tmux_session": <throwaway>}`, agent id
`agent:dh90-a00-48126e22`, `pane_name` = `seat-495299a91a03`.

1. `spawn(...)` with real long-lived argv `sleep 600` — capture BEFORE.
2. `kill -9 <pane_pid>` — confirm process dead (`os.kill(pid,0)` fails) and
   capture MID: pane still listed.
3. `reattach(...)` with fresh argv `sleep 601` — capture AFTER, assert window
   name identical, `#{pane_id}` IDENTICAL, `#{pane_pid}` differs,
   `created=False`.
4. Call `reattach` once more — confirm `created=False` still.
5. Negative control: `tmux kill-window -t <pane_id>` genuinely destroys the
   pane; `reattach` must re-create exactly once with `created=True` and a NEW
   `#{pane_id}`.
6. Teardown: `tmux kill-session -t hold-exp-a00-48126e22` (only our session;
   pre-existing `pane1..paneN` untouched).

## Result

The seam holds against a real server: `%175` survives a real `kill -9`
(process dead, pane listed), reattach lands back in `%175` (`created=False`),
twice. The negative control distinguishes held from rebuilt: after a real
`kill-window`, the seam re-creates `%176` once with `created=True`.
`#{pane_pid}` churns (3994495 → 3994513 → 3994529 → 3994567) while
`#{pane_id}` is stable (`%175`), which is exactly the process-independent
seat occupation the goal asks for. The prior round's stated limitation —
"a real-tmux fact cannot be proven without a real server" — is now closed.
