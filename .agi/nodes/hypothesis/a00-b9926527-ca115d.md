# hypothesis:a00-b9926527-ca115d

## Hypothesis

The persistent record never erases a live occupant.

**Claim.** `_supervise_persistent`'s terminal write branches on the current
child's liveness (`proc.poll()`), not on which exit path produced it: a child
still ALIVE keeps its pid and gets a non-`running` state that names the end of
the HOLD (`released`); a dead child clears `pid` (`stopped`/`exhausted`/
`failed`). A reader of `agent.json`/`manifest.json` can therefore always tell
"hold ended, child gone" from "hold ended, child still running".

**Proves it.** Built bytes of `dispatch._supervise_persistent`, driven by
`_StubProc`:

- wire — `AGI_PERSISTENT_STOP=1` with a child whose `poll()` is `None` (ALIVE)
  → persisted `pid` equals that live child's pid, `persistent_state ==
  "released"` (not `running`, not `stopped`). This is exactly the parent's
  probe D, which was falsified before this round.
- gate — `max_restarts=0` + dead child → `pid is None`, state `exhausted`.
- gate — `max_restarts=2` + instantly-dead `reopen` → `pid is None`, state
  `exhausted` (prior round's fix must not regress).
- gate — `AGI_PERSISTENT_STOP=1` + DEAD child → `pid is None`, state `stopped`.

**Disproves it.** Any of those persisted records naming no pid while the child
is alive, or naming a dead/anonymous pid while the child is dead; or a state of
`running` after the hold has ended.

## Result

Built and green. `extensions/agi/bin/dispatch.py` (19 added / 6 removed —
under the 40-line ceiling); `extensions/agi/tests/test_dispatch_persistent.py`
7 passed. Two pre-existing tests encoded the falsified behaviour (they asserted
`pid is None` on the clean-stop path while their stub child was alive); they
were corrected rather than deleted, and the gate that stubs a DEAD stopped
child was kept as the counter-case.
