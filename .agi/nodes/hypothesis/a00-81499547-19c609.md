# hypothesis:a00-81499547-19c609

## Hypothesis

`dispatch._open_round` should have one pane-owning opener: its **first** call asks the hold adapter to create/reattach the seat's named tmux pane, and its later restart calls ask the same adapter to reattach that pane. The opener—not the restart branch—owns any `created` result, so the record says `created=true` only when tmux actually reported a newly founded pane.

## Test

A hermetic dispatch test can stub one hold seam and distinguish two calls:

1. Open a persistent seat and kill its child.
2. Let persistent supervision reopen it.
3. Assert the first call requests `start(seat, argv)` and the second requests `restart(seat)` / `attach(seat, argv)` against the **same deterministic pane name**.
4. Assert the first record is `created=true` only when the stub start reports creation; after child death the reopen record is `created=false` (or omits the field), never a fabricated `true`.

## Proves

The production first-spawn path crosses the hold/start seam, and both first spawn and restart preserve one named pane without a separate out-of-band `tmux_hold.start()` call.

## Disproves

The first `_open_round` call bypasses the hold seam and direct-Popens; restart creates a different pane; or the restart path stamps `created=true` despite the hold adapter reporting reattach.

## Scope

One hypothesis only: specify the seam and falsifier. Implementation and the hermetic proof belong in a child experiment under this node.
