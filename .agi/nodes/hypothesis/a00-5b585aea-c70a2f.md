# hypothesis:a00-5b585aea-c70a2f

## Hypothesis

On the DT.116 tip, the grok-bot pane hold (`goal:g7.31.1.2`) can be given a
**Popen fallback** so that enabling the hold never makes `restart` *less*
available than the plain direct spawn. Three distinct hold failures must all
degrade to a real detached `Popen` — never a raised exception, never a silent
`None` and a dead seat:

1. **tmux absent** — `tmux` is not on PATH (`tmux_hold.available()` False);
2. **hold lands nothing** — `tmux_hold.reattach(...)` returns `None` (respawn
   failed / pane could not be founded);
3. **hold raises** — the seam raises (e.g. no resolvable box session) after the
   availability gate already passed.

In every degraded case the returned pid is the real Popen pid and the agent
record is stamped `tmux = {..., "fallback": "popen"}`, so the caller can tell
a durable held pane from a degraded direct spawn. A hold that *does* land keeps
its `tmux.created` stamp and carries **no** `fallback` key.

**Proved by:** with `PATH` holding no tmux, the built `restart` returns a real
live pid, `agent.json` carries `fallback: popen`, and the pre-fix primitive
(`tmux_hold.panes`) is shown to raise `FileNotFoundError`; unit tests cover the
`None` and raising branches. **Disproved by:** any of the three cases raising,
returning `None`, or landing a pid without the fallback stamp; or a successful
hold carrying a `fallback` key.

## Status

Built and proved on the current tip; see child experiment
`experiment:a00-5b585aea-popen-fallback-live-build`.

## Boundary / open tension

The goal invariant says *one named pane per seat; no anonymous fire-and-forget*
(`goal:g7.31.1.2`). The fallback deliberately creates exactly the anonymous
process that invariant warns about — but only in a degraded mode, and it is
the lesser loss: a seat that cannot be held is still better alive than dead.
The stamp is what keeps the two distinguishable; a future reader must not
mistake `fallback: popen` for a hold.
