## Hypothesis

A seat row's occupation can be read from LIVE facts alone — the live tmux
window @id for the seat name AND the row `pid` when present — and that one
fact reaches the injected `SeatsView` readers (`to_markdown`/`to_compact`)
without any ad-hoc pane scrape at the call site.

Testable claim: a new `seat_status.seat_occupation(row, tmux_session,
window_path=None, registry_dir=None)` returns `"occupied"` only when the row
`window` matches the live tmux @id for that seat name and any present row pid
is alive; `"pane-drift"` when the window mismatches or the pid is dead;
`"unoccupied"` when no live window answers the name; and `None` (fail-open)
when tmux is unreadable. `seat_status.collect(..., tmux_session=,
window_path=)` surfaces it per seat and the two view renderers print it, while
`collect` with no seam stays byte-identical.

Proved by: `extensions/agi/tests/test_seat_pane_registry.py` asserting each
state, the fail-open paths, and the rendered cells both with and without the
seam. Disproved by: any state misclassified, an exception on unreadable tmux,
or a changed render when no seam was supplied.
