# hypothesis:a00-6aaf0235-f70ce8

## Hypothesis

A single messaging product seam (`extensions/agi/bin/messaging.py`) can carry
magic-pane traffic for `goal:g7.32.2` by deciding **native vs cross** on
harness identity alone, with no pane-hold, no adapter pane methods, and no
send.py internals inside it.

**Testable claim.** With `route(sender_harness, target_harness)` returning
`"native"` iff the harness strings are equal and `"cross"` otherwise:

1. the native path drives only a duck-typed `pane.pane_send(text)` and never
   touches `send.py` (a spy runner records zero calls);
2. a pane with no `pane_send` fails closed with a named error, never hangs;
3. the cross path emits ONE structured `NudgeArtifact` as its first trace
   event and then invokes the `send.py` CLI as the only transport, giving the
   ordered trace `[("nudge_artifact", …), ("send_py", argv)]`, and never
   calls `pane_send`;
4. `messaging.py` imports no `rotate` / `dispatch` symbol.

**Proved by:** `extensions/agi/tests/test_messaging.py` (5 tests, all
passing) watched against a fake pane and a spy runner — the run is
`experiment:magic-pane-messaging-router-a00-6aaf0235`.

**Disproved by:** any native-path `send.py` invocation, any cross trace whose
first event is not the nudge artifact, or an AST hit for a `rotate`/`dispatch`
import in `messaging.py`.

## What stays out

Pane hold (g7.31.1), the real adapter pane methods (g7.32.3), and send.py's
router internals (g7.32.4). No formation or policy decisions live here.

Predecessor: no live grok pane (fake pane + spy runner).
