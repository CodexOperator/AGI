# hypothesis:a00-53d64e2f-d02c5b

## Hypothesis

The `cmd_loop` rotation primitive is gated by the SAME pre-rotation profile
-drift check as `cmd_rotate_self`: on a deliberately desynced graph `cmd_loop`
exits non-zero and names the drifted node BEFORE it reaches `spawn_window`,
while an in-sync graph still rotates; and that wire is proven by BEHAVIOUR
(calling `cmd_loop`) rather than by a source-string grep.

**Proved if:** a scratch graph whose linked artifact is mutated makes
`cmd_loop(...)` return 1 with `profile drift` + the node name on stderr and
never calls `spawn_window`; an in-sync scratch graph still reaches
`spawn_window`; the same probe FAILS on a build that omits the guard.

**Disproved if:** the guard sits after a side effect (a spawn), or a clean
graph is blocked, or the test passes on an unguarded build.

## What was built

`extensions/agi/bin/rotate.py` (`cmd_loop`): a `pguard = _check_profile_drift(root)`
call in the same order as `cmd_rotate_self` — branch guard, then profile drift,
BEFORE the meter and BEFORE `spawn_window`. Refusal prints the named message to
stderr and returns 1. `root is None` is already returned earlier, so
`_check_profile_drift(None) -> None` is preserved and never reached.

`extensions/agi/tests/test_profile_sync.py`: the source-string grep
(`assert "pguard = _check_profile_drift(root)" in src`) was REPLACED by a
behavioural probe that calls `cmd_loop` on a drifted scratch graph and asserts
rc=1 + `profile drift` + the node name + that `spawn_window` was never called,
plus the clean-graph half that asserts `spawn_window` IS reached.

## cmd_spawn: left unwired, deliberately

`cmd_spawn` does NOT carry the drift guard, and this is a reasoned exception,
not an oversight:

- The falsifier asks for detection *before the next seat rotation*. Rotation
  runs through `cmd_rotate_self` and `cmd_loop`, both now gated. `cmd_spawn` is
  the manual / first-seating launcher reached only via the `rotate.py spawn`
  CLI, not a rotation.
- The crash-recovery successor-respawn path (`heal.py`) calls
  `_rotate.spawn_window` DIRECTLY, never `cmd_spawn`, so gating `cmd_spawn`
  would not even close a successor-spawn hole.
- Gating the universal launcher on drift would make the ONE tool an operator
  can use to bring up a repairing seat while drift is unresolved self-refusing
  — turning a detectable, repairable condition into a lockout. The graph SoT
  should refuse to ROTATE on drift, not refuse to be repaired.
