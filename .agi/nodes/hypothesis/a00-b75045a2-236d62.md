# hypothesis:a00-b75045a2-236d62

## Hypothesis

Kid 1's general AST gate (`hypothesis:a00-bc652841-541f5f`) holds
`rotate.py` to "orchestration only" only if it is blind to no *style* of
per-harness code. It was blind to four named shapes (parent's negative
probes). Extended in the same file, the gate can close all four while the
live `rotate.py` still reports **zero** offenders and needs **zero**
production edits.

**Proved if:** each of the four probes is reported by name, and
`test_rotate_stays_orchestration_only` still finds an empty offender list on
the live file (including the shipped `harness == "claude-code"` at L979 and
`getattr(args, "harness", None) == "copilot-cli"` at L2191).

**Disproved if:** any probe still returns `[]`, or any new rule flags the
live file (a false positive would force a production edit, which is the
thing the gate exists to forbid).

## The four parent probes, each now fixed

| # | shape (parent's probe) | rule that now catches it | result |
|---|---|---|---|
| 1 | `getattr(args, "harness", None) == "grok"` | A: `==`/`!=` against an operand whose unparsed NAME tokens include `harness` | `['grok']` |
| 2 | `harness in ("grok", "x")` | A: `in`/`not in` with a harness read on the left collects every string in the container | `['grok', "x"]` |
| 3 | `def _grok_flags(h)` (no argv suffix) | C: underscore-delimited token in `{grok, claude, copilot, pi}` | `['_grok_flags']` |
| 4 | `def _build_grok(...)` (no suffix) | C: same token rule | `['_build_grok']` |

Rule **B** is new and independent of any comparison shape: any `ast.Constant`
string equal to a known harness id (`{claude-code, copilot-cli, pi, pi-local,
  grok, grok-bot}` — read off the template dir and `config.json`) other than
the shipped two is an offender. Docstrings are skipped by `id()`, so
*documenting* a retired id stays legal.

## Why the old detector was blind to probe 1

It keyed on `isinstance(node.left, ast.Name) and node.left.id == "harness"`.
The live file's own idiom (L2191) is `getattr(args, "harness", None)`, whose
LHS is a `Call` — so a `grok` branch written in the file's own house style
would have passed. The new test matches the operand's unparsed *word tokens*,
not a substring: `harness_template.role_source(hid) == 'ladder'` (L919) must
not match, and the token test keeps it out.
