## Hypothesis

`dispatch … --persistent` can close `goal:g7.28.1` conjunct 2 without a second
argv path and without inventing a second registry writer:

- **release:** when the hold ends (restarts exhausted, `reopen` raised, clean
  stop) the agent record stops claiming `persistent: true` over the last
  (possibly dead) pid -- `persistent: false`, `occupation: released` -- so no
  reader can take a corpse for a live seat;
- **occupation:** the held child's LIVE pid is written into the seat's
  `config:posts` row through the EXISTING `rotate._write_identity_cells` seam
  on start and each restart, and cleared to the no-pid sentinel `0` on
  release, so `seat_status.seat_occupation` no longer reads `pane-drift`;
- **invariants intact:** fire-and-forget is still the default and the restart
  still reuses the captured `spawn_args`/`spawn_env`.

### Falsifiers

1. After a terminal hold, `agent.json` / the manifest still carry
   `persistent: true` with a dead `pid` (parent probe C's falsification).
2. The seat row is never written on start/restart, or still names the dead pid
   after release.
3. A non-persistent spawn changes behaviour, or a restart rebuilds argv.

writes/clears the row pid through `rotate._write_identity_cells` -- the writer
`rotate._backfill_session_ref` delegates to (not a second registry writer;
see the experiment's "Deviation, stated").
