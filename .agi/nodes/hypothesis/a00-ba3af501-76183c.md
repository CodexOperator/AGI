# hypothesis:a00-ba3af501-76183c

## Hypothesis

A grok-bot seat's pane hold is equivalent across BOTH spellings of the same
seam: the child environment a seat is born with at FIRST spawn is the child
environment it is born with again when `restart` re-enters the SAME named tmux
pane (`goal:g7.31.1.2`, invariant "Restart goes through the same
adapter/template seam as first spawn").

Specifically: `grok_bot_adapter.restart`'s hold branch must pass the same
`child_env(harness=harness, base=dict(os.environ), tier=tier)` the non-hold
`Popen` branch passes, into `tmux_hold.reattach(..., env=env)`. `tmux
respawn-pane` inherits the tmux SERVER's environment, not the dispatch child's,
so an `env`-less reattach silently strips a reaper-restarted seat of its
`harness["env"]` cells, its `AGI_*` identity and any minted key.

**Proved if:** on real tmux, a seat whose birth writes its harness env cell and
a base-environ var to a marker file writes the SAME values on first spawn and
again after its pane process is killed and `grok.restart` reattaches to the
same `#{pane_id}` — without regressing `created: False` on the held path or
`created: True` on a genuinely gone pane.

**Disproved if:** the marker differs (or empties) after the restart, or the
restart fabricates a new pane / records `created: True`.

## Evidence

`experiment:tmux-hold-restart-env-parity` — real tmux 3.4 on a scratch session
(`agi-dt67-probe-<pid>`, killed at teardown; never the live `agi-rc`). First
spawn marker `hello|base-hello`; after SIGKILL of the pane process +
`grok.restart`, marker `hello|base-hello` with `created: False` on the same
pane. The negative probe reproduces the old behaviour (env-less reattach →
empty marker), confirming the test is not vacuously green. `test_tmux_hold.py`
11 passed; grok/adapter suites 50 passed; dispatch/restart suites 150 passed.
