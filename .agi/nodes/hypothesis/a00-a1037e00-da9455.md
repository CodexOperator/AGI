# hypothesis:a00-a1037e00-da9455

## Testable claim

A restart hold implementation for goal `g7.31.1.2.3` should be a real,
grid-versioned adapter (`extensions/agi/bin/adapters/tmux_hold.py`) and
should not make restart depend on tmux being installed or a session already
being present.  The next experiment can test both parts separately:

1. enumerate tracked engine files and declared `payload_ref`s (or inspect
   the coverage checker) to see whether the adapter is covered;
2. with tmux unavailable and with the hold session unset, call the restart
   seam and assert that it still constructs a direct `Popen` process with
   the expected environment and working directory.

The claim is supported if the adapter is covered by a build node and both
negative-environment probes reach a restart.  It is disproved if the adapter
is absent from the grid, or if either probe raises/returns without a process.
The current checkout is informative but not proof: no `tmux_hold.py` is
present in the engine tree, while `dispatch.py` still directly calls
`Popen`; an experiment should confirm whether this is an untracked intended
file or a stale goal before implementing anything.

## Scope and method

Keep the probe local and deterministic: monkeypatch the tmux availability
and session lookup, capture the fallback constructor, and assert on its
arguments.  Do not require a live tmux server.  The experiment should also
run `grid_coverage_check.py` and report the exact missing-file count rather
than adding an exclusion.
