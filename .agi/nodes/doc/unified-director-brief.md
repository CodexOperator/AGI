## §3 Rotation and cards
- Card = `.agi/sessions/quorum/<post>.md` in YOUR worktree, written DURING the work (a card written at the end does not exist for the run that dies), replaced WHOLE each write, committed by exact path. First line of every card: the pointer to this node and to your master's customization (§4).
- **Write the card by ABSOLUTE path inside your worktree, never a relative path and never the main checkout's path** (measured 2026-09-18 05:45Z: a director wrote its card with the main checkout's absolute path, missing the `/.agi/worktrees/post-<post>` segment, so it landed UNTRACKED in MAIN every time and blocked the Prime's merge while `git show HEAD:<path>` read as a mystery revert; separately the harness can flip a session's cwd between the worktree and the main checkout between turns, so a relative `.agi/...` write is unsafe too). Same for every file you write; git commands run with an explicit `-C <worktree>` or a leading `cd <worktree> &&`.
- Sections a cold successor needs, in order: state block · plan with done/next/blocked · what landed one line each · 🔴 where it stops + the exact next command · traps · known-good verification · BANKED.
- **Rotate at the line -- the exact recipe (owner 2026-09-18 17:1xZ: a director stalled at 0.45 instead of rotating).** The meter hook prints `[meter] post=<post> <f> ... line=<L>` on every prompt; when `f >= L` (compare `f` only, never the second number; directors L = 0.44-0.47 from `ladder.director_rotate_at`) you rotate ON THAT TURN, no matter what is in flight -- live rounds are re-dispatched or harvested by your successor from the card. Steps, in order, all from your pane with cwd = your worktree: (1) write your card WHOLE with a FRESH one-line `🔴 Where it stops` (what is live, what is queued, the exact next command) and commit it by exact path; (2) run `python3 extensions/agi/bin/rotate.py rotate --stops "<that one line>"` -- bare, keyed, never `-h`, never `--dry-run`, never `--force`; it merges origin itself (never merge by hand ahead of it), writes the successor row + meter pin, seats the successor and answers its ack. (3) Read what it prints. Every refusal names itself; fix exactly that and re-run: `stops slot EMPTY/AMBIGUOUS/unchanged since rotate-out` -> rewrite the 🔴 line (or pass a new `--stops`); `posts row dirty` -> commit or discard THAT row's file only, never bundle; `behind origin` -> it is not you: re-run once (rotate merges), else `git -C <worktree> merge --no-rebase origin/season2/main` then re-run; `index.lock` -> wait 30 s; `card-age` -> your own last act is what it clocks, write the card again; `MERGE_HEAD` -> `git merge --abort` in your worktree, then re-run. Never AskUserQuestion, never "holding to confirm", never wait for a human: a refusal you cannot clear in two tries goes to your master as one `[rotation]` line with the refusal text verbatim, and you keep working until the answer.
- **A live run is never a reason to hold a rotation (owner 2026-09-18 20:4xZ in the sanctuary-master pane: "director thought still not rotating itself ... hesitant to self rotate"; measured cause = director-thought's own card: a `workflow.py run` launched with the Bash tool's `run_in_background` dies with the session).** Launch every long run DETACHED from the pane -- `systemd-run --user --unit=agi-<post>-<run_key> --working-directory=<ABSOLUTE path of your post worktree> [-p MemoryMax=6G -p MemorySwapMax=0] -- python3 extensions/agi/bin/workflow.py run <wf> ...` (a transient SERVICE under the user manager: not `--scope`, not `run_in_background`, not a bare `&`) -- so a rotation kills nothing: the run's record and branch carry its state, the card names the unit + run key, and the successor reconciles with `systemctl --user list-units 'agi-*'` at wake. The one thing a rotation does kill is a `run_in_background` job: never launch one. At `f >= L` you write the card and rotate, live runs or not. **`--working-directory` is load-bearing (director-sanctuary 2026-09-18 22:5xZ, reproduced twice; code half = SM.129 `hypothesis:l5-workflow-py-takes-an-explicit-root-so-a-detached-run-never-depends-on-cwd`):** systemd does not inherit the pane's cwd and `workflow.py run` resolves the project from cwd only, so without it the run exits 2 `no .agi project root found from cwd` in under a second while `systemd-run` prints `Running as unit` and returns 0 -- the launcher sees success and nothing runs. Right after every launch: `systemctl --user status <unit>` (active + a real child). When SM.129 lands, pass `--root <worktree>` to `workflow.py run` as well; `--working-directory` stays.
- **A live ROUND is never a reason either (owner 2026-09-18 20:5xZ, both directors stalled past the line; measured 20:3xZ on this box):** a parent dispatched by `dispatch.py` on a tree with SM.112 runs with ppid 1 inside its own user scope (`/user.slice/.../run-<id>.scope`), not under your pane -- a rotation kills no round. The only stall left is the one you choose: at `f >= L` the NEXT action is the card + `rotate`, never one more landing, review or dm.
