# outcome:a00-f5d32509-2b5714

## Outcome

The held-pane dispatch seam is usable as a compatibility layer around the
existing process contract. First spawn and pi restart route through
`tmux_hold.start_or_popen`; when tmux succeeds, the agent retains a stable
`pane_id`, and when tmux is unavailable or startup cannot publish a child pid,
the original direct-`Popen` fallback remains in force.

`HeldProcess.returncode` delegates to `poll()`, so the dispatch post-start path
receives the integer completion status just as it would from
`subprocess.Popen`. A fast successful child (`hold.done=0`) therefore reports
`returncode == 0` rather than raising `AttributeError`.

## Inputs

An agent launch request with its command, environment, working directory, and
session flags. A successful held launch also supplies the pane identity and
completion marker through the tmux hold process.

## Outputs

A started agent process, either attached to a reusable detached tmux pane or
launched through the unchanged direct-`Popen` fallback. Once the held process
finishes, `poll()` and `returncode` expose the same parsed exit status.

## Behavior

`start_or_popen` prefers the held-pane path, records the canonical pane id and
actual child pid, and keeps restart pointed at the same pane. The fallback is
selected for absent tmux, tmux startup failure, or failure to publish the child
pid. The return-code compatibility property is read only after startup has
observed completion.

## Edge cases

- `hold.done=0` is the previously broken fast-success branch and now reports a
  normal zero return code.
- A running or malformed completion marker remains `None`, matching the
  `Popen`-style running-process contract.
- A tmux session can still be left behind if `new-session` succeeds and a later
  startup step fails before pid publication; the secret-bearing hold spec can
  also remain after completion. These are follow-up cleanup concerns, not
  regressions in pane reuse or fallback.
- The focused suite's fast-success assertion should remain alongside direct
  fallback and restart regressions; mocked seam coverage alone is insufficient
  to establish production return-code compatibility.
