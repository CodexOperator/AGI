# experiment:a00-ab8f77fc-8327fd

## Experiment

The kill-switch branch of `crons.py apply` (`extensions/agi/bin/crons.py`,
`_unit_actions`, the `wanted == False` path at ~L573) had a silent hole: when
`crons_live: false` (or a service disabled) with the unit FILE present and NO
reachable user bus, `_systemd_bus_env()` returns `None`, the `disable --now`
was skipped with **no line at all**, yet the unit file was still unlinked and
`daemon-reload` was named-skipped. So the unit kept running, the file
vanished, and the log said nothing about the disable.

Fix (in place, kill-switch branch only):
- Restructured the branch so `disable --now` + file removal + `daemon-reload`
  run as one sequence ONLY when a bus exists.
- No bus now records `unit <name> present, no user bus: disable --now SKIPPED
  (unit may still be running)` AND keeps the file (decided: do NOT remove),
  plus the existing `unit <name> no user bus, skip daemon-reload` line.
- Justification for keeping the file: the hyphen-claim itself names the
  hazard — removing the file while the unit runs leaves a running unit systemd
  no longer knows (an orphan it can never manage or stop). We cannot complete
  the kill without a bus, so the honest state is "couldn't stop it, file stays
  so systemd still tracks it"; a later apply with a bus re-enters the branch,
  disables, removes, reloads — the kill still converges, just not this pass.

Added test `test_kill_switch_absent_file_stays_when_no_bus` in
`extensions/agi/tests/test_crons.py`: kill switch + present + no bus →
named `disable --now SKIPPED` line + daemon-reload skip line, NO `remove unit`
line, file still present, no fake-systemctl call, no FAILED.

## Evidence

- `python3 -m pytest extensions/agi/tests/test_crons.py -q` → 68 passed
- Full engine files `test_crons.py test_envfile.py test_heal.py` → 120 passed
- FALSIFIER check: the silent path is gone — the no-bus kill now always emits
  at least the named `disable --now SKIPPED` line (asserted).
- Pre-existing test `test_kill_switch_with_unit_present_runs_disable` (bus
  present) still green: disable --now, remove, daemon-reload all run.
