# experiment:a00-9d07d3b8-694590 -- the read-only guarantee, tested inside its own sandbox

## The residue (parent's finding, confirmed on the shipped bytes)

`test_boxkit_probe.py::test_one_pure_resolver_and_the_writer_never_drift` looped
`override in (None, <tmp>/fixed-cache)` x `use_runtime in (True, False)` with both
`AGI_MEMCAP_CACHE` and `XDG_RUNTIME_DIR` deleted.  The
`(override=None, use_runtime=False)` case therefore falls through in
`mem_cap._cache_path_pure` to `tempfile.gettempdir()` -- the REAL `$TMPDIR` -- and
the WRITER half, `_probe_cache_path` -> `_private_dir`, mkdirs + chmods 0700
`<real tmp>/capdir` there.  The read-only claim was enforced by a test that wrote
outside `tmp_path`.

## What I changed (test file only, 0 production lines)

| step | change |
|---|---|
| base | `monkeypatch.setattr(tempfile, "gettempdir", lambda: str(tmp_path / "faketmp"))` before the loop -- the one base BOTH resolvers can reach now lives inside the sandbox |
| proof | per case, for BOTH `pure` and `writer`: `pathlib.Path(path).is_relative_to(tmp_path)`; the drift assert is kept, now on the captured `writer` value |
| kept | `assert not fresh.exists()` -- the PURE resolver still creates nothing |
| import | `tempfile` added to the stdlib import line |

Nothing outside `tmp_path` is read or inspected: the proof is a path assertion per
case, not a snapshot of the live temp dir.
