## Experiment

Kid 2 of the L5 rename-post chain. Kid 1 fixed the dm/comms half; this round
fixes the `rotations.md` prose+alerts half the brief and the hypothesis's own
live probe named.

WHAT WAS RED (pre-fix, measured): a tmp git repo + linked worktree cut BEFORE
MAIN committed a `rotations.md` line mentioning `old`; stage rename-post from
MAIN graph, then `_apply_staged` from the worktree:

    stage rc=0 (13 surfaces incl. `rotations.md mention`, `alerts.edges key`,
    `alerts.edges value`, `alerts.audit member`)
    boundary rc=2 `rename-post REFUSED: staged plan drifted -- rotations.md
    mention: rotations.md:3 -> rotations.md:3(edited), ...`

Cause: `_rename_surfaces` read `_rotations_node_path(root)` =
`<caller>/nodes/.geometry/rotations.md`, so stage (MAIN) and boundary
(worktree, stale checkout) read two different files.

FIX (scoped, `extensions/agi/bin/rotate.py`, +20 net lines):

- new `_shared_rotations_node_path(root)` routes through
  `locations.shared_project_root(root)` (the MAIN graph) and joins
  `nodes/.geometry/rotations.md`.
- `_rename_surfaces`: the prose `mention` loop AND the alerts read now use it:
  `_load_alerts_raw(root, _shared_rotations_node_path(root))`.
- `_load_alerts_raw` gained an optional explicit `path` (default unchanged:
  `_rotations_node_path(root)`), so its other callers are untouched.
- NOT changed: `_load_templates` and every other template/spawn reader keep
  `_rotations_node_path(root)`. Reason: a rotation TEMPLATE is what a worktree
  seat should RUN, and a worktree seat's rotation config is its own graph
  fork; MAIN's copy is not automatically the right one. The rename surface
  enumeration is different: it compares two derivations of the same table, so
  it must read ONE node.

CALLER-ROOT AUDIT of `_rename_surfaces` (brief item 2):

- shared-resolver-bound now: `sessions = _sessions_dir(root)` (session files,
  top-level pins/logs), dm logs/sidecars via `_dm_season_rooms` ->
  `send.comms_root` (kid 1), and NOW the `rotations.md` mention rows and the
  `alerts` rows via `_shared_rotations_node_path`.
- still caller/row-derived BY DESIGN: `_own_sessions_dir(root, old)` (the
  post's own quorum card, worktree-first via the row `worktree` cell),
  `_sessions_dir(root)/"quorum"/"belam.md"` (shared room, already
  MAIN-rooted), `_load_seats(root)` -> `geometry_config.load_rows(root)` (the
  caller's geometry config; rows are read from the tree the command was
  given), `_town_post_branch(root, ...)` (reads local refs of the caller's
  repo), `_row_town_or_refuse`/`towns.row_town`.

FALSIFIER HELD: the drift gate was not weakened. A second test stages from
MAIN, then appends ANOTHER `old` mention to MAIN's `rotations.md`; the
boundary still refuses rc 2 with the stage intact -- a genuinely new surface
still drifts.
