# experiment:a00-550973b1-29eb86

## Experiment

I ran the focused held-pane, transient-dispatch, and real-adapter restart
suites. The first run exposed one remaining production incompatibility: a child
that exited successfully during the startup grace had its final `poll()` return
`0`, but `_startup_alive_or_complete` treated every false result as a failed
startup and retried it. I fixed that seam to recognize `returncode == 0` both
before and after the grace poll, while preserving retry behavior for non-zero
transient failures.

The existing focused tests cover the held-pane seam, tmux-unavailable fallback,
owned-session cleanup, supplied-pane preservation, stable pane reuse, transient
respawn, and real adapter restart. The clean-exit-zero test is the regression
that failed before the fix and passed after it.
