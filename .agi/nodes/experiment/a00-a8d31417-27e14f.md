## Experiment

Goal: cover heal.py's death-past-deadline branch (heal.py:317-336) — the
`outcome["still"]` loop where a pid ALIVE at the reap pass but DEAD by the
watcher's own deadline check records a DEATH. The pre-existing
`test_watch_dead_pid_past_deadline_is_a_death_not_timeout` used a pid dead
from the start, which `_reap_pass` reaps into `outcome["died"]`, so :320 was
never reached. Verified that gap is real: the OLD tests all pass yet the
:320 branch is dead in coverage terms for the alive-at-reap case.

What I did — added 3 tests to extensions/agi/tests/test_heal_watch.py:

1. `test_watch_dead_past_deadline_alive_at_reap_then_dead` — a `_FlipFlopAdapter`
   whose `is_alive(pid)` returns True on the FIRST call (so `_reap_pass` sees
   the agent alive and leaves it in `outcome["still"]`) and False afterwards
   (so heal.py:320 sees it dead). Round: pid 424242, timeout_s=1, started_ago=5
   (> deadline). Asserts: agent.json status=failed, fail_reason EXACTLY
   "pid 424242 died (detected by reaper)", finished_at set, no timeout_reason;
   manifest entry status/finished_at/fail_reason updated; EXACTLY ONE dm
   reason=death, NO reason=timeout; watch log has "marked DEAD past deadline"
   and no "marked timeout".

2. `test_watch_dead_past_deadline_no_double_dm_on_second_pass` — same setup,
   a second `--once` pass must not re-dm (the L4.123 double-dm guard): dm
   count stays ONE across two passes.

3. `test_watch_alive_past_deadline_still_timeout_not_death` — sibling path:
   an `_AlwaysAliveAdapter` (alive at BOTH checks) still records a TIMEOUT,
   never a death; asserts status=timeout, timeout_reason set, reason=timeout
   dm, no reason=death.

Result: all 9 tests in test_heal_watch.py pass (6 pre-existing + 3 new);
adjacent heal/dispatch suites 126 passed.
