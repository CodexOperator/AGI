### Residue 1 — the `bin` assert was vacuous

The old line asserted `row["bin"] ==
live_cfg["harnesses"]["grok-bot"]["bin"]`. It could not fail. `adapters.
resolve` at `bin/adapters/__init__.py` does `harness =
dict(harnesses[chosen])` — a shallow copy — so both sides are the same string
object. The assert compared a value to itself and would stay green even with a
wrong path.

Fixed in `extensions/agi/tests/test_grok_bot_adapter.py`,
`test_live_config_grok_row_resolves`, by exercising the spawn path instead:

1. `monkeypatch.delenv("GROK_BOT_BIN", raising=False)` so a stray env var
   cannot mask the config cell;
2. `live_bin != grok.DEFAULT_BIN` — the non-vacuous anchor, which fails if the
   config omitted `bin` or carried the bare fallback;
3. `grok.resolve_bin(row) == live_bin`;
4. `grok.build_command(harness=row, tier="kid", context_file="/tmp/x")[0]
   == live_bin` — the config cell reaches the argv that actually spawns.

Added `test_live_bin_cell_threads_through_to_argv`: a `/SENTINEL/grok-bot`
written into the RESOLVED COPY's `bin` reaches `argv[0]` and is not
`DEFAULT_BIN`, proving no constant or fallback masks the cell. The live
`live_cfg` is never mutated — only the dict `adapters.resolve` copied out.

No `os.path.exists` assert: `/home/ubuntu/.npm-global/bin/grok-bot` is not
installed on this box, so it would fail for the wrong reason. The claim is
that the cell is carried, not that the binary is present.

### Residue 2 — the probe tested the wrong function

The prior wire probe called `adapters.resolve`, which never reads `DEFAULT_BIN`
and never calls `resolve_bin`, so it could not see the fallback. The probes
recorded on this node run through `grok_bot_adapter.resolve_bin` /
`build_command`; the third probe deletes `bin` from a copy and shows
`resolve_bin` returns `DEFAULT_BIN`, so the fallback is reachable and the
live-cell assert is a genuine gate rather than a tautology.
