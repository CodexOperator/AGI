# experiment:a01-d450d5b0-1b8669

## Experiment

Tested whether `WarmLoadCache` + `directory_digest` from `graph_core/cache.py` can be adapted to memoize the `embed_graph` + `project` pipeline.

Built an `EmbedProjectCache` wrapper class that:
- Keys on `(directory_digest(root), embed_config_json, project_config_json)`
- Caches both `embed_graph` output (vectors) and `project` output (coords)
- Exposes `hits`, `misses` counters and a `clear()` method

Then ran a 5-claim test suite against it (see Evidence for full output):

### Claim 1 — Cache hit speed
Created a 10-node chain graph with 10 node files under tmpdir/nodes/.
Cold: embed + project = ~5.2ms. Warm: = ~0.003ms. Second call is ~0.06% of first call, well under the ≤1% threshold.

### Claim 2 — Invalidation on edit
Cold: miss. Warm: hit. Modified one node file (changed body text). Third call: miss again. Pattern: miss→hit→miss, all three reported correctly by counters.

### Claim 3 — Config sensitivity
Same graph, default configs: hit (second call). Different EmbeddingConfig dim=32: miss (key changed). Different ProjectionConfig seed=99: miss (key changed). All three detections correct.

### Claim 4 — Force flag
Two calls with unchanged graph → miss then hit. `cache.clear()` → miss on third call (force equivalent via wipe). Counters: 2 misses, 1 hit after clear.

### Claim 5 — Portability
Two copies of the same directory produce identical digest keys. Copied tmpdir to tmpdir_copy; both produce same digest; cache key is identical. Confirmed directory_digest is location-independent by construction (uses `relative_to(base)`).

### Verdict
All 5 claims **proved** against this implementation. The `directory_digest` + config-salted key pattern from `WarmLoadCache` adapts cleanly to the embeddings pipeline. No model work on cache hit; full recompute on file edit, config change, or cache clear.

### Caveat
The digest is over the entire `.agi/nodes/` subtree — any byte-level change (whitespace, comment) triggers a miss even if the graph structure is semantically identical. This is a design tension noted in the hypothesis but not a correctness bug.

class EmbedProjectCache:
    def __init__(self):
        self._cache = {}
        self._stats = {'hits': 0, 'misses': 0}
    def get(self, directory, embed_cfg=None, proj_cfg=None):
        digest = directory_digest(directory)
        key = (digest, json.dumps(vars(embed_cfg or EmbeddingConfig()), sort_keys=True),
               json.dumps(vars(proj_cfg or ProjectionConfig()), sort_keys=True))
        if key in self._cache:
            self._stats['hits'] += 1
            return self._cache[key]
        self._stats['misses'] += 1
        graph_path = Path(directory) / 'nodes'
        from graph_core.loader import load_directory
        graph, loaded = load_directory(graph_path)
        vecs = embed_graph(graph, embed_cfg)
        coords = project(vecs, proj_cfg)
        result = (vecs, coords)
        self._cache[key] = result
        return result
    def clear(self):
        self._cache.clear()
        self._stats = {'hits': 0, 'misses': 0}
    @property
    def hits(self): return self._stats['hits']
    @property
    def misses(self): return self._stats['misses']
