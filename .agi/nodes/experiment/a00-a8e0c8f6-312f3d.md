# experiment:a00-a8e0c8f6-312f3d

## Experiment

Built the g15.26 FIX: the pending `<seat>.key.pending` swap now completes at
EVERY push-OK site (and inside rotate-self BEFORE the successor key mints),
closing the orphan-on-fresh-rotate ordering defect.

**Code changes (call placement only; `_persist_pending_key` write shape,
`send._signing_key_obj` preference order and `heal._record_join` untouched):**

1. `rotate.py`: NEW shared helper `_finish_pending_swap_on_push(root, seat,
   push_line)` — completes a deferred swap **iff** `push_line` starts
   `push: OK`, prints the outcome, returns it. One gate; future push sites
   call THIS helper so they cannot drift into completing a swap on a FAILED
   push.
2. `rotate.py` `_commit_spawn_row` (the one existing site): inlined
   `if _push.startswith("push: OK")` block replaced by the shared helper.
3. `rotate.py` `cmd_rotate_self`: (a) after the rotate-out **stops** push
   (was rotate.py:11043) and after the only-behind **merge** push
   (rotate.py:11108), each `_stops_push` success now calls the helper with
   the seat; (b) **claim (a), the centre**: immediately BEFORE
   `_rotate_successor_key` mints a new successor generation (rotate.py:11259),
   gated on not `--dry-run`, `_complete_pending_key_swap` runs so on a seat
   already carrying a `.key.pending` (a prior push FAILED after the spawn-row
   write committed) the old gen-N->N+1 swap resolves onto disk BEFORE the
   fresh N+1->N+2 mint reads the key state — no orphaned pending, no
   double-counted key_history.
4. `send.py` `_commit_push_all_live` (the keygen --all-live push, send.py:752):
   after `rotate._push_season_branch` returns `push: OK`, loops `keyed_names`
   calling the shared helper for each (each only flips when its committed row
   matches its pending pub).

`cmd_ack`/`cmd_prepare` were verified on this base to make NO push (they do
not call `_push_season_branch`), so no site was added there — the shared
helper is the seam they would use if they ever push.

**Fixture evidence** (one two-tree fake-tmux + bare-origin fixture per claim
site, style of SL7.19/`_init_git_remote`):

- `test_finish_pending_swap_on_push_fires_only_on_push_ok` — helper gate:
  a `push: FAILED` and an absent push line leave `.key.pending` untouched

- `test_keygen_all_live_push_completes_pending_swap` — claim (b) send.py
  site: a keyed change on a second seat forces an `--all-live` commit+push;
