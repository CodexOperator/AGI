# experiment:a00-9ee1d97b-0e74b4

## Experiment

Implemented the fix the parent hypothesis (`l4-the-judge-runs-on-the-substituted-command`) required, in `extensions/agi/bin/rotate.py` `_run_first_turn_commands` (the first_turn runner): after `_resolve_startup_placeholders` + `_resolve_shell_vars`, the substituted `exec_cmd` is now RE-JUDGED IN FULL, not just operator-checked — `_env_prefix_refusal(exec_cmd, env_allow)` and `_producing_refusal(exec_cmd)` run before the existing `_operator_refusal(exec_cmd)`, all BEFORE `_command_units` splits it.

Why this closes the hole: a placeholder or env value can inject a whole `;`- or `|`-wrapped stage. The template judge saw the un-resolved `{seat}` / literal `$VAR`, so it passed; the executor splits on `;`/`|` (both MODELED separators) and `_operator_refusal` deliberately does NOT refuse them — so the injected `touch`-stage ran unjudged. Re-running `_producing_refusal` on `exec_cmd` splits on the same `;`/`|` grammar and refuses the off-allowlist stage (`touch ...`), naming it, before it ever reaches `_run_units_no_shell`. The `$VAR` injection likewise stays literal in the record (fix-b form), so no expanded env value lands there.

Tests added to `extensions/agi/tests/test_rotate_startup.py`:
1. `test_r_placeholder_injection_refused_no_marker` — placeholder value carries `; touch <marker>`; refused (`not on startup.allow` naming `touch`), marker never appears, record is the placeholder-expanded literal.
2. `test_s_env_var_injection_refused_no_marker` — `$SEAT` value carries `| touch <marker>`; refused naming `touch`, marker never appears, record keeps `$SEAT` literal.
3. `test_q_clean_substitution_still_runs` — a benign placeholder substitution still runs (rc=0), proving the new gate does not refuse the happy path.
