# experiment:a00-13fee083-d475a6

## Experiment

Build order (g15), not a measurement. `rotate.py rename-post` derived its
comms/dm surface table from the CALLER's root (`Path(root)/"comms"/
season-*/dm/`), so a stage taken from MAIN and the boundary apply run from the
post's own worktree (whose `comms/` is a stale/partial checkout) enumerated
DIFFERENT dm files and `_apply_staged` refused the stage as drift (rc 2).

Changed `extensions/agi/bin/rotate.py` (32 added / 7 removed, ceiling 40):
- new `_dm_season_rooms(root)` resolves the season rooms through the SHARED
  resolver `send.comms_root(root)` (ONE room per season on the MAIN checkout);
  `_dm_participants` walks those rooms. Stage and boundary now derive
  byte-identical `src`/`dst` no matter which checkout runs each.
- the `belam.md` prose read in `_rename_surfaces` now goes through
  `_sessions_dir(root)` (the shared sessions room), never
  `Path(root)/"sessions"`.

New test `extensions/agi/tests/test_rotate_comms_shared_root.py`: a real git
repo plus a linked worktree; MAIN `.agi` holds the dm room, the worktree has
none; stage from MAIN, `_apply_staged` from the worktree.
