# experiment:a00-0f318229-2d1697

## What I built

The parent's falsifier (`/tmp/p7.py`) stood: a THIRD writer taking `index.lock`
in the instant a peer commits turned a committed write into an rc-3
UNCOMMITTED refusal. Cause: `busy` is a read of git's error STRING, and the
clean-at-HEAD branch sat BEHIND `not busy` -- so the one path where the index
must be asked (the deadline) never asked it.

One change, `extensions/agi/bin/write.py` `_commit_write` (11 lines added, 4 removed):

| before | after |
|---|---|
| `tracked = all(ls-files --error-unmatch ...)`; `if (not busy and tracked and not status --porcelain ...)` | one `at_head =` conjunct over both reads, then `if at_head and (not busy or time.monotonic() >= deadline)` |
| plain `git status --porcelain` | `git --no-optional-locks status --porcelain` |

Design choices, stated:

- **Widened, not added.** The cheap fast path (`not busy`) is unchanged and still
  short-circuits: the index is asked on the DEADLINE as well, so a busy error
  string can no longer overrule the index. No second code path, one predicate.
- **`--no-optional-locks` is load-bearing.** Without it the read itself wants to
  refresh/write the index and queues behind the very holder that made the path
  busy -- the truth-read would inherit the stall it exists to resolve.
- **Conjunct 2 (ignored paths) and conjunct 3 (STILL STAGED) untouched.** The
  `tracked` conjunct is still the first term of `at_head`, and the reset/`
  diff --cached` block is byte-identical; a rewrite of the second guard was the
  larger risk, and its 3 rows stay green.

## Weakness I know about

The deadline read costs two subprocess calls on the slow path (one `ls-files`
per path), and it happens exactly when the index is contended -- under real
contention those calls can be slow, though `--no-optional-locks` keeps them
read-only. Wall-clock on this box varied 12s-131s for the same suite across six
identical runs, so the timing-sensitive row is load-sensitive by nature; I
widened its budget from 2.0s to 4.0s after one flake.
