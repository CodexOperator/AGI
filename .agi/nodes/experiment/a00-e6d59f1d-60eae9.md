# harness_template refuses an unknown `slot`/`when` by name at check time

## Experiment

Build order (`goal:g15`): the claim is behaviour to implement, not merely to
measure. Measured the pre-fix state, implemented the fix, proved it on the
built bytes.

**Pre-fix mechanism (verified):** `_check_parts` refused unknown element KEYS
(`_ALLOWED_KEYS`) but never checked the *names* a `slot`/`when`/`spread`
points at. `_emit` did `values.get(part["when"])` (L~174) and
`values.get(part.get("slot"))` (L~186); a miss returned `None` and the branch
returned `[]`, so a template naming `slot = "modell"` silently emitted
nothing — the silent-failure class the module docstring claims to close.

**What changed (`extensions/agi/bin/harness_template.py`, +20 production
lines):**
- new module constant `RENDER_VOCABULARY` (the 20 render names) — one source
  of truth;
- `_check_parts` now refuses any `slot`/`when`/`spread` outside it, by name:
  `unknown slot 'modell'` / `unknown when 'verbos'`, at `load()` time and in
  every `shapes.<name>.argv`;
- `render()` asserts its `values` keys equal `RENDER_VOCABULARY`, so the two
  cannot drift.

**Counterfactual:** a `.get` that satisfied the docstring's words by treating a
miss as empty did exactly what this fixes — the docstring asserted the class
was closed while the lookup silently dropped it. The check now lives in
`load`, so a bad name can never reach `_emit`.

`spread` is included: every shipped template's spreads (`extra_args`,
`model_args`, `mcp`, `tools`, `allowed`, `disallowed`) are in the vocabulary,
and tests stay green — so it was free.
