### Item 8 — ONE reconciling call count per audit side

- SAID: `payload["calls"]` must equal the sum of the buckets the SAME payload
  reports; the printed count and the recorded count are one read; excess keeps
  its floor-set meaning.
- MACHINE (pre-fix): `audit_payload` set `calls=int(calls)` while reporting
  a/b/c/d that summed to a different number (sensei.py:1574-1580 old);
  `cmd_rotate_out_audit` printed `len(calls)` yet passed `window["counted"]`
  (sensei.py:2261 old) and `cmd_wake_audit` passed `_calls` with no `s` bucket.
- FIX: `audit_payload` now names the EXCLUDED class as an additive bucket --
  `s` for wake (service-owed, outside the a+b+c floor window), `pre` for
  out (`send=output` report + harvest read) -- and derives
  `calls = a+b+c+d+extra`. `measured` is the FLOOR set (wake a+b+c; out
  a+b+c+d) so excess is unchanged. `finish_audit` computes the payload FIRST
  and prints `payload["calls"]`, so printed == recorded by construction.
  `cmd_rotate_out_audit` builds the non-pre buckets from the calls list and
  prints `pre=N` on the counts line; `window["counted"]` remains a+b+c+d.

  `len(calls)` was exactly the two-number split the item names; the fix keeps

  printed/recorded count becomes the reconciling 3.

### Item 9 — the harvest is a READ of the notified path

- SAID: key it to a read verb (cat/head/tail/sed/Read) whose operand IS that
  path; any other mention is not a harvest and is counted.
- MACHINE (pre-fix): `sensei.py:2261 old` used `prev[0][1] in cmd`, a plain
  substring over the WHOLE command, so `rm <path>`, `grep x <path>` and a send
  body naming the path were all `harvest of <task-id>` and excluded (`pre`).
- FIX: `_read_verb_operand_is` checks a `_READ_PATHS` read verb whose
  same-pipe-segment operand token EQUALS the path; `_harvest_read_of` also
  accepts a `Read` tool_use whose `file_path`/`path` is that path.
- NEAR MISS: `_synthesize_read_cmd` (sensei.py) reads keys `path`/`paths`, not
  `file_path`, so a CC `Read` of the notified output has an EMPTY synthesized
  cmd and was never a harvest before; the new helper reads `file_path` itself.
  Covered by a new Read-tool test.

### Item 10 — `send=output` is the report SHAPE, not the verb

- MACHINE (pre-fix): `sensei.py:1015-1016 old` returned `send=output` for ANY

  old) excluded EVERY send in the window.
- FIX: `_is_tagged_send` matches a leading `['"]\s*[tag]` in the message
  argument; only that returns `send=output`. An untagged send falls through to
  the normal rules (`d`, counted).
- DEVIATION (window-close send): the brief allowed keying the close send too
  IF it could be identified. MEASURED on the two live master transcripts

  position (the send before the rotate) would be a guess, so the `[tag]` rule
  shipped ALONE -- the safe direction (an untagged close is COUNTED, not
