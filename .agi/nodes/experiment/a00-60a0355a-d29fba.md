# experiment:a00-60a0355a-d29fba

## Experiment

Test the hypothesis's third disproof condition: whether the briefing module is the
**sole source of truth** for the chain rules and verdict taxonomy text, and whether
both callers (viewport, inject) respect that boundary without bypassing the module
to compute briefing data directly.

**Three checks:**

1. **Source isolation** — CHAIN_RULES text must exist in exactly one production
   source (briefing.py). Tests that assert its presence are not duplicates.

2. **Caller bypass** — neither viewport.py nor inject.py may define its own
   CHAIN_RULES/VERDICT_TAXONOMY, instantiate Briefing directly, or set
   briefing fields inline.

3. **Content parity** — across multiple window sizes (20, 40, 80, 150), the
   briefing sections (## graph snapshot through ## standard commands) must be
   byte-identical between the two callers after stripping preamble headers.

**Procedure:**

```bash
# Source isolation: grep for "chain length is never" across live codebase
# (excluding .git/, .claude/, .agi/nodes/, .agi/sessions/, .agi/refs/)

# Caller bypass: grep for CHAIN_RULES, VERDICT_TAXONOMY, Briefing( in callers

# Content parity: run both commands at 4 heights, extract only briefing sections
# ("## graph snapshot" through "## standard commands"), diff line by line
```

## What this adds over sibling experiments

Sibling experiments proved the extraction worked (`the-viewport-reaches-parity`),
the retirement was safe (`the-renderer-retired`), and the briefing output was
structurally identical (`a00-811b8503-ae99a5`).

This experiment proves the **data-contract boundary** — not just that the
output matches, but that the callers are structurally prevented from drifting
apart because they share one computation (`briefing.build()`) and neither can
re-derive briefing data from the graph. This is the invariant that prevents
`goal:g1.10`'s four-copy failure from recurring for the chain rules.
