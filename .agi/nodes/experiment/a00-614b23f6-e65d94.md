# experiment:a00-614b23f6-e65d94

## Experiment

Tested the parent claim — "after substitution the SAME judge (`_producing_refusal` + `_operator_refusal`) runs again on `exec_cmd`" — against the LIVE code in `extensions/agi/bin/rotate.py` `_run_first_turn_commands` (:4176-:4236, the first_turn runner) using a scratch harness that calls the real functions. Parent is a g15 bugfix intended to stop a placeholder/env value from adding an unjudged stage.

**What the code actually does.** Per entry the runner gates in this order: `_env_prefix_refusal(cmd)` on the TEMPLATE, `_producing_refusal(cmd)` on the TEMPLATE, `_resolve_startup_placeholders`, `_resolve_shell_vars`, then — and this is the whole finding — ONLY `_operator_refusal(exec_cmd)` before `_command_units(exec_cmd)` + `_run_units_no_shell`. `_producing_refusal(exec_cmd)` is **never re-run** on the substituted command. And `_operator_refusal` deliberately does NOT refuse `;` or `|` (both are modeled separators, comment at :3900). So an injected `;`-unit / `|`-stage sails through both gates.

**Placeholder vector — `x; touch <marker>`.** Template `python3 {worktree}/extensions/list.py {seat}` with `seat = "seatA; touch /tmp/.../pwned-MARKER"`. Template judge `_producing_refusal` → `None` (a single allowlisted part). `record_cmd`/`exec_cmd` after substitution: `python3 /tmp/.../extensions/list.py seatA; touch /tmp/.../pwned-MARKER`. `_operator_refusal(exec_cmd)` → `None` (no unmodeled op; `;` is modeled). `_command_units` splits it into TWO units; `_run_units_no_shell` runs both. `res[0]["refused"]` is absent, `rc=0`, and **`pwned-MARKER` exists**.

**Env-var vector — `$SEAT` carrying `; touch <marker2>`.** Same shape via `os.environ["SEAT"]="seatA; touch .../pwned2-MARKER"`. Template judge `None`; `_operator_refusal(exec_cmd)` `None`; runs; **`pwned2-MARKER` exists**. Record (`res[0]["cmd"]`) correctly keeps the literal `$SEAT` (fix-b env-secret scrubbing works for the `$VAR` literal path).

**Record-scrub nuance.** The `$VAR` record keeps `$SEAT` literal (good — no secret). But a placeholder value shows in the record as its resolved VALUE (`...list.py secretVALUE`), not `{seat}` — placeholders aren't env secrets so this is acceptable, but it is not "scrubbed back to its placeholder form" as the hypothesis's fix-b wording implies.
