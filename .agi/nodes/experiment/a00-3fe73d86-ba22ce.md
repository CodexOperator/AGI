## New finding, from a probe bug of mine

My first `mint_probe.py` gave `distinct=1` on **both** branches — because each
process built its OWN `mkdtemp` root, and the reservation namespace is
`shared_project_root(root) or root` (`workflow.py:_reserve_run_key`). Peers that
resolve different roots share no namespace and both take the base name. Benign
in production — `locations.shared_project_root` folds every git worktree onto
the one main graph root, so real launches never diverge — but it is a property
of the fix that no probe in this chain had named, and it is why a harness bug
looks exactly like a regression. Recorded as a `scope` probe on the corrected
node.
