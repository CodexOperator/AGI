```python

if keys and ("_repeat_key" not in stage or stage["_repeat_key"] in keys):
```

A dependent SLICE (`_repeat_key='a'`) never matches `{None}`, so every slice ran.

## The two mechanism changes (`workflow.py`, +41/-11 production lines)

1. `_run_round_stage` — the dispatch `subprocess.run(..., timeout=)` is now
   wrapped: `except subprocess.TimeoutExpired: return 3, None`. A hung round is
   a NAMED STAGE FAILURE (same rc as a refused spawn), not a raise that leaves
   `run_workflow` through the runner's context-only `try` and past the
   credential-revoking `finally` as a run-level abort.
2. `_failed_dependency(stage, failed_keys, simple_failed)` + `note_failed()` in
   the pi loop — a base that failed AS A WHOLE (no `repeat` of its own, e.g. the
   prelude `kind: round` parent) gates EVERY slice of its dependents. SM.105
   slice isolation is untouched: a repeated base still only skips the matching
   `_repeat_key`, because only a NON-repeated stage lands in `simple_failed`.
