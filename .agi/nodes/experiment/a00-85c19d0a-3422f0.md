### Pre-fix probe (RED)

`rotated_by: old` cell on the `old` row. Stage `cmd_rename_post` from MAIN,
then `_apply_staged` from the worktree, with `locations.shared_project_root`

```
PRE-FIX  stage rc 0  boundary rc 2  stage_left True

  row old.rotated_by -> row new.rotated_by
```

### Implemented fix (SCOPED, kid-2 pattern) in `extensions/agi/bin/rotate.py`

- New helper `_shared_seat_rows(root)`: `_load_seats` resolved from
  `locations.shared_project_root(root)` (MAIN checkout), identity outside a
  worktree. SCOPED to the rename surface enumeration; every other
  `_load_seats` caller keeps the caller-root rows.
- Inside `_rename_surfaces` ONLY: `sroot = locations.shared_project_root(root)
  or root`; the row-surface loop iterates `_load_seats(sroot)`; the town
  check `_row_town_or_refuse(sroot, old)`, `_find_seat(sroot, new)` and
  `towns.row_town(sroot, new_row)` all read the SAME shared row table, so a
  divergent town/row can no longer split the two derivations or raise a
  one-sided `RenameTownRefusal`.

### Post-fix probe (GREEN)

Same fixture, no monkeypatch: `stage rc 0  boundary rc 0  stage_left False`.
New fence tests in `tests/test_rotate_comms_shared_root.py`:
`test_boundary_apply_from_worktree_agrees_on_main_committed_row_cell` (rc 0,
stage consumed) and `test_gate_still_refuses_a_genuinely_new_row_cell_after_
staging` (a second cell MAIN commits AFTER staging still refuses rc 2, stage
