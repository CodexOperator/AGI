# experiment:a00-2ec3b4a6-b531ae

## Experiment

Built the mint gate for `research-review` stages 3 (`why`) and 4 (`brainstorm`).
Before: both prompts contained a live `write.py create` call with no gate, so a
disproved/inconclusive round minted a real idea + 1-5 hypotheses as a side
effect of reading. Change: a `mint` run arg (default ABSENT) threads through to
both stage prompts as `{mint}`, and the create text is wrapped under that value.

Files changed (production):
- `extensions/agi/workflows/research-review.json` (manifest, the source)
- `extensions/agi/workflows/agi-research-review.js` (derived; adds `const MINT`)

Both stage prompts now carry `MINT GATE: \`{mint}\` -- mint real nodes ONLY when
it renders non-empty ...`, the mint branch text is kept verbatim (a `mint:true`
run reproduces today's behaviour in intent), and the propose-only branch tells
the stage to run NO create, set `why_node none` / `hypotheses []`, and fill the
NEW always-present return fields `proposed_idea_title` + `proposed_idea_body`
(why) and `proposed_hypotheses` (brainstorm, objects of
`title,testable_claim,cost,falsifier`). Both manifest schemas declare those
fields, including in `required`.

GATE LITERAL — the mechanism, verified not assumed. `render_stage_prompt()`
formats through `_SafeDict`, so an ABSENT key renders as the EMPTY STRING, not
a KeyError. A Python `bool True` (what `--args '{"mint": true}'` gives) renders
as `True`, NOT `true`, so the gate is stated as "non-empty" rather than
"exactly the string true" — a literal-`true` gate would have silently disabled
minting for the very command this round was told to verify.
