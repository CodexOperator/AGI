# experiment:a00-f2e3b48b-5f8ec2

## Experiment

Kid A slice of `hypothesis:gpu-local-town-openai-endpoint`: **box + server + model 1**.
No tunnel, no engine route, no larger model — those are Kid B / Kid C.

**Box:** local-town, gpu-8g SUPER 8192 MiB, driver 595.84, `/data` 339G (317G free), 16 vCPU,
15 GB RAM, docker + nvidia-container-toolkit.

**Image:** `ghcr.io/ggml-org/llama.cpp:server-cuda`, repo digest
`sha256:d4bdfe78ad26a1ef3ccc834fc4e4a106d882e0f2163dd9a06e067c580c742101`
(`llama-server` build 10991, commit 930e2fa59). No source build, no Ollama, no vLLM.

**Model:** `unsloth/Qwen3.5-9B-GGUF` → `/data/ml/models/Qwen3.5-9B-Q4_K_M.gguf`, exactly
**5,680,522,464 B**, sha256 `03b74727a860a56338e042c4420bb3f04b2fec5734175f4cb9fa853daf52b7e8`,
downloaded straight to `/data` (0 bytes to core-town).

**Server:** `docker run --name llama-server --restart unless-stopped --gpus all --network host
-v /data/ml/models:/models IMAGE --host 127.0.0.1 --port 8080 --models-dir /models --models-max 1
--fit on --jinja -np 2`. Router mode was available in the image, so the `-m` + `--alias` fallback
was not needed. Binds loopback only.

### Results

`GET /v1/models` (loopback on the box) lists `Qwen3.5-9B-Q4_K_M` and reports the router child args.
`POST /v1/chat/completions` returns `HTTP 200` with **`finish_reason="stop"`** and
`message.content="pong"` (with `chat_template_kwargs.enable_thinking=false`; with thinking on,
Qwen3.5 emits `reasoning_content` and the 16-token cap yields `length`). `nvidia-smi` beside the
server call: **memory.used 6674 MiB / 8192 MiB**, 40–100 % util, 57–89 W idle-ish, loadavg ≈ 0.4–0.8.

`llama bench` (no `/app/llama-bench` in this image; `llama help all` exposes `bench`), run x5 in the
same image after stopping the resident server (it holds ~6.6 GB of 8 GB and `-ngl 99` OOMs otherwise),
with `nvidia-smi` sampled every 500 ms per run:

Every row: `backends: CUDA`, `n_gpu_layers: 99`, `gpu_info: NVIDIA GeForce gpu-8g SUPER`
(25 samples per direction). **pp512 ≈ 1560 tok/s (claim ≥ 500 ✓), tg128 ≈ 63.5 tok/s (claim ≥ 30 ✓),

full offload, or memory.used < 5 GB) does not occur — the GPU is unambiguously in use.

**Rollback proof:** `docker rm -f llama-server` → `curl` to `127.0.0.1:8080/v1/models` returns

`/v1/models` → HTTP 200. The server was left **running** for the Kid B tunnel slice.

### Caveat on "all layers in VRAM"
This server build at default verbosity prints no `offloaded N/N layers to GPU` / model-buffer lines
(greps for `tensor|buffer|device|layer|offloaded|CUDA0` return nothing), so full offload rests on
the bench rows (`backends: CUDA`, `n_gpu_layers: 99`, util 100 %, 5568 MiB) plus
`nvidia-smi memory.used 6674 MiB` with the server resident, not on a log line.
