# experiment:a00-ea8aa887-19ad8d

## Experiment

Phase 3 of `hypothesis:brief-py-assembles-every-first-turn-from-config`
(EF.19, third and last kid). Built the AMENDED template half of the claim and
left the caller rewiring for the next round, with the reason measured rather
than asserted.

### Built

1. **`template` is a PART, chosen by CONFIG.** `BRIEF_PARTS` gains
   `"template"` (`brief.py:2268`); `_part("template", ...)` resolves
   `post row .template` first, else `config:brief .templates[role]`
   (`brief.py:2329-2341`), and `_template_text` reads a build node's
   `payload_ref` FILE (a role brief that is prose, e.g. the Prime's) or the
   node BODY otherwise (`brief.py:2319-2330`). A named template that does not
   resolve raises `RenderError("brief template node not found: <id>")` BY
   NAME via `_node_text`.
2. **`config:brief` carries the chart** — `.templates = {director:
   doc:unified-director-brief, master: doc:unified-director-brief,
   prime_director: build:briefs-prime-director-successor}`, and
   `parts` for director/master/prime_director become `head, template, card`
   (+ `trajectory` for master and prime_director).
3. **The card is DATA.** `_part("card")` no longer runs `_expand`; a
   `{{template:}}` line in a card stays literal. `_expand` survives only on
   the `extras` part (parent/kid dispatch briefs).

### NOT built (split out, disclosed)

- **Conjunct 3, the `[handoff-head]` entry.** The amendment's premise —
  "leaving this entry reads the card TWICE (once as the card part of the
  Prime's render, once here)" — is **false on the current bytes**. Verified: a
  Prime successor is spawned by `rotate.py::spawn_window` through
  `_successor_command` (`rotate.py:1052-1076`) with `prompt_file =
  templates.prime_director.brief_file = extensions/agi/briefs/
  prime-director-successor.md`, and `brief.successor_prompt` prepends only the
  head (`brief.py:801`). The Prime's render path is NOT used for its spawn
  (`rotate.py:1866` deliberately excludes `tier == "prime_director"`), so the
  card arrives EXACTLY ONCE today — from `[handoff-head]`. Dropping the entry
  now would silently DELETE the Prime's card. Wiring the Prime through
  `brief.render` is the prerequisite, and that is conjunct 4-scale. I also
  cannot land a `config:rotations` write as a kid (the nested `templates`
  mapping is ring/`written_by`-gated to owner/prime_director), so the entry is
  left byte-identical.
- **Conjunct 4, one render for rotate/dispatch/adapters.** `dispatch.py:1365`
  and the three harness adapters (`claude_code_adapter.py:597`,
  `pi_adapter.py:207`, `copilot_cli_adapter.py`) still call
  `brief.assemble`. Routing them through `brief.render` needs the
  parent/kid params (`target`, `parallel`, `addendum`, `max_live`, ...) to
  become render config and needs `extras` to carry the dispatch brief — a
  larger change than the 40-line ceiling allows this round.
