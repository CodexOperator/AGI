## 1 -- the unit-dir fit rule is derived, not a copy of two cell tails

```python

+UNIT_DIR_CELL = re.compile(r"/systemd/[\w.@%{}$-]+$")        # :705
+def _unit_dir_tails():                                        # :708

+                     for m in [UNIT_DIR_CELL.search(str(v))] if m)
```

`_cell_fits_dir` now asks `endswith(tuple(_unit_dir_tails()))`. The tails are the tails of
COMMITTED `paths.boxkit` cells whose value ends in a two-component dir UNDER `systemd/` --
on this box, `systemd_system_dir` and `user_systemd_dir`, the same two the literal named.
The point is not the two names, it is that the file no longer OWNS them: rename either
cell and the rule moves with the config instead of inverting silently. Reading at CALL
time (not at import) is what lets a row that renames a cell see the rule move.

Row `test_the_unit_dir_fit_rule_follows_the_committed_cells` (:866) holds the rule
honest: the set is non-empty, a real `UNIT.d` piece fits under the committed config, and
after renaming every unit-dir cell off `systemd/` the set is EMPTY and the same piece no
longer fits.
