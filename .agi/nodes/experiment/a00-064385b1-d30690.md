# experiment:a00-064385b1-d30690

## What I did, item by item (fix in the bytes, or the one command that settles it)

### ITEM 1 / MISS 2 -- the stat arm of `_uninspectable` was a new fail-closed flake. FIXED.
The corrective described the window as "a pid that EXITS between that successful
listing and the stat". I could not reproduce THAT shape, and the reason matters:
`_uninspectable` is only ever reached from the `except OSError` around
`os.listdir(f"{base}/fd")` (cli.py:2429-2433). A SUCCESSFUL listing never calls
it. The real window is one step narrower and it is the one I fixed: the fd
listing came back dark (EACCES, a non-ENOENT), `_uninspectable` was entered, and
the `os.stat(base)` INSIDE it raised ENOENT because the pid exited in between.
Pre-fix that fell into `except OSError: return "?"` -- an UNKNOWN HOLDER -- and
refused the whole commit over a pid that was provably gone.

The fix is one arm, narrow on purpose (cli.py `_uninspectable`):

```python
    except OSError as sexc:
        # a pid that EXITED between the listing above and this stat is
        # provably no holder -- the same exit as the ENOENT arm above. Every
        # OTHER errno (EACCES, EPERM, ...) stays an UNKNOWN holder.
        return "" if sexc.errno == errno.ENOENT else "?"
```

and one docstring line, so the exit count in that docstring stays true.

### ITEM 2 / MISS 1 -- the round's own claim was false and a green test sat on it. TEST + NODE TEXTS, NOT THE BYTES.
Read in the bytes: `_mirror_terminal_into_manifest` ranks the record
(`_AGENT_STATUS_RANK`, cli.py:3004-3011, failed=3) against the entry
(`_merge_status_rank`, cli.py:1101) and only writes when `rec_rank >=
_merge_status_rank(entry)`. After `cmd_done` already mirrored `done` (rank 5),
the re-mirror at cli.py:1776-1778 cannot downgrade, so `target` stays None,
cli.py:1104 returns, and **manifest.json keeps reading `done`**. The node
assertions were false. I did NOT force the downgrade, because the guard is
load-bearing: `workflow.py` `_round_git_wait` reads the manifest and
`if rec.get("status") in ("failed","timeout","stalled"): return 3, None` is its
FIRST branch -- a manifest reading `failed` would drop the round's entire
harvest. The truth is the opposite of the claim and better for it, so the fix is
to make the test say what actually happens and to correct the two node texts
(experiment:a00-9dfef904-01bf3b item 4, and the hypothesis node's Agent Notes),
both of which asserted a manifest downgrade that cannot occur.
