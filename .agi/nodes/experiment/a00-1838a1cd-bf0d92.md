## THOUGHT

**What the instruction said vs what the machine does.** The brief called
`_publish_row_to_authority` (~:10377) unconditionally from `_commit_spawn_row`
(~:10604) and gated the swap on the trunk `push:` line only. The machine now
calls it only under `rekey=True`, consults the SAME `veto.is_frozen(shared,
"prime")` cell `_push_season_branch` (~:10316) consults, and the swap's success
predicate gained an `authority: OK` conjunct in BOTH gates.

**Deviation (documented).** The brief's C3 wording also makes a non-origin
SKIP defer. I implemented `authority: OK` as the sole success -- so any
non-OK line (FAILED, HELD, REFUSED, SKIPPED) defers. That is what breaks the
four neighbour tests above; I did not weaken the gate to keep them green
because the target hypothesis states the authority-consistency invariant
outright. A later round may narrow SKIPPED-no-authority-ref to "not gating" if
a tree with no authority is meant to keep the old behavior.

**Near-miss.** My first `_apply_successor_key_gated` parse used
`rpartition("\nauthority: ")[2]`, which STRIPS the `authority: ` prefix, so
`authority: OK` read as `OK -- ...` and `startswith("authority: OK")` was
False -> every re-key deferred. Fixed to test `startswith("OK")` on the
remainder (the standalone line passed to `_finish_pending_swap_on_push` still
receives the full `authority: ...` string, so its check is unchanged).

**C1 threading.** The re-mint fact is threaded from the two REAL mint sites
(`_rotate_first_key` -> `rekey=True`; `cmd_rotate_self`'s spawn-row commit ->
`rekey=bool(_key_rotation)`). Plain seating/heal commits keep the default
`rekey=False` and never touch the authority ref.
