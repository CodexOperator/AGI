# experiment:a00-e29b112a-5e0075

## Experiment

Built the two conjuncts of
`hypothesis:l4-a-bare-kid-commits-before-merge-trusts-it` on the live bytes.

**Chosen layers, and why.**

- Conjunct (1) — the commit — went in `cli.py`, NOT `season.py`. The scoped
  commit predicate (`_round_scope_ok` / `_round_own_node_paths`) and the
  worktree-only guard (never `add -A` a shared main tree, `goal:g4.1`) already
  live in `cli.py::_auto_commit_worktree`. `season.py` only ever sees a branch
  NAME; it cannot scope a commit, and a linked worktree may be shared by
  sibling kids, so `add -A` there would sweep a sibling's half-written node —
  the exact hazard `goal:g4.1` names. The successful kid `done` already
  commits (`cli.py:1739`); the measured hole was the kid-tier REFUSAL return
  at `cli.py:1589`, which returned rc 2 BEFORE that commit. Fixed there.
- Conjunct (2) — the loud refusal — went in `season.py`, because that is the
  merge layer a director actually calls and the layer that used to print a
  silent `zero commits ahead -- nothing to merge`. New read-only helper
  `_dirty_worktree(root, branch)` scans `git worktree list --porcelain` for a
  LINKED worktree checked out on the branch, skips the main checkout by name
  (shared tree), and `status --porcelain` it. Both `cmd_merge_kids` and
  `cmd_merge_up` now call it on the zero-ahead path and refuse with the
  worktree path + the uncommitted paths.

Production diff (measured, read-only `git diff --numstat`):
`cli.py` 4 added / `season.py` 40 added = **44 lines**, ceiling 40, under 2x.
