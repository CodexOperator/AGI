# experiment:a00-cb707d50-f62748

## Experiment

Hypothesis `l4-crons-dry-run-probes-answer-real-state`: the READ-ONLY probes
(`systemctl --user is-enabled` / `is-active`) and the unit-file byte
comparison mutate nothing, so a `--dry-run` apply must answer the same
question the live pass would ask and reach the same branch — printing seam
intent for a unit the live pass leaves alone is wrong.

The live no-op branch already existed (`experiment:a00-6a832110-35535b`,
`reconcile_units` in `extensions/agi/bin/crons.py`): when up-to-date it calls
the two probes, and if both end `(ok)` records `unit <name> enabled+active
(no-op)` and runs neither daemon-reload nor enable --now.

**The bug:** `_apply_systemctl` swallowed every call under dry run —
```
if dry_run:
    return f"{label} (dry-run)"
```
so `enabled.endswith("(ok)")` was false on *every* dry run, and a unit the
live pass marked `(no-op)` got `systemctl --user daemon-reload (dry-run)` +
`enable --now (dry-run)` printed instead. The dry run answered a question the
live pass does not ask.

**The fix:** added a `read_only: bool = False` keyword to `_apply_systemctl`:
- `dry_run and not read_only` → unchanged: return `"<label> (dry-run)"`, run nothing.
- `dry_run and read_only` → **run the subprocess for real** (it mutates
  nothing), return its real `(ok)` / `FAILED (...)`.
- `not dry_run` → unchanged.

In the `up_to_date` branch of `reconcile_units`, the two probe calls now pass
`read_only=True`; the `seam()` closure (daemon-reload, enable --now) stays
`read_only=False`, so mutations still never run under `--dry-run`. The
kill-switch branch and `cmd_remove` were untouched.

**Falsifier proved red.** Temporarily reverted the two probe calls to
`read_only=False` (forcing the `(dry-run)` string path): test
`test_dry_run_up_to_date_enabled_active_probes_real_state` went red
(`assert False: dry run must answer the probe and reach the same no-op
branch`). Restored to green.
