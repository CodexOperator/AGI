## Experiment

Closure of the residue of clause (c) of `hypothesis:l4-send-py-same-sender-

**The defect:** `_nudge_line` (`extensions/agi/bin/send.py`) computed
`keep = _NUDGE_LINE_MAX - len(prefix) - len(trunc_tail) - len(trailing)`
with **no floor**. `flat[:keep]` with a negative `keep` is a LONG slice in
Python (it drops the LAST `|keep|` chars), not an empty one, so a naturally
long `prefix + tails` budget (long seat/sender names) produced a line that
grew *past* the cap instead of shrinking. Measured on this tree:

    _nudge_line('sanctuary-director','sanctuary-director','word '*80,
                trailing=_NUDGE_INBOX_TAIL.format(seat='sanctuary-director'))
    -> 494 chars against _NUDGE_LINE_MAX = 95   (5.2x the cap)

**The fix** (send.py, `_nudge_line` only): the body slice `keep` is floored
at 0, and when `prefix + tails` alone busts the cap the line retreats
richest-tail-first -- drop the inbox `trailing` first, then the `(+N more)`
count, then the read-seat tail -- and only then gives the freed budget to
the body (never the reverse). First tail that fits wins; a body slice never
grows past the budget. Record semantics untouched (the dm still lands in the
dm file; this is delivery only).

**Tests added** (`test_send.py`):
- property test: for every seat AND sender length 1..40, with the inbox
tail, with `more>0`, and both, `len(_nudge_line(...)) <= _NUDGE_LINE_MAX`;
- pinned test: the exact measured counterexample shape (same long name +
inbox tail, lengths 1..40) stays `<= _NUDGE_LINE_MAX`.
