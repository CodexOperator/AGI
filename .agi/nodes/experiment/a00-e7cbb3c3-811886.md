# experiment:a00-e7cbb3c3-811886

## Falsifier (reproduced against kid 1's bytes)

Kid 1 landed the merged-dirty parking mechanism
(`_sweep_park_leftovers` + `git reset --hard`/`git clean -fd` when the park
proves itself) and it works — bytes are never lost. But the park DESTINATION
is wrong whenever the bring-home runs LIVE.

Fixture: one agent worktree `a00-7f3a11` cut as `loop/p-P@2` from
`season/s2`, one commit merged into `season/s2` (HEAD is an ancestor of the
base = MERGED); its round session dir `iter-901` exists ONLY in the worktree
(main has no `sessions/iter-901`); a terminal manifest; and one DIRTY tracked
file `base.txt` = `UNCOMMITTED BYTES THAT MUST BE PARKED\n`.

Pre-fix output:

    [sweep] homed a00-7f3a11 iter=iter-901
    [sweep] parked a00-7f3a11: 1 files -> sessions/_unhomed/leftovers/a00-7f3a11
    [sweep] removed a00-7f3a11 iter=? base=season/s2

The byte landed at `sessions/_unhomed/leftovers/a00-7f3a11/base.txt`, not at
`sessions/iter-901/leftovers/a00-7f3a11/base.txt`: the round is no longer
findable by its iter id, and the `removed` log line names `iter=?`.

## Cause (in the bytes)

`heal.py` read the iter name with a live glob (`_sweep_iter_name(wt)`) AFTER
the bring-home block. A LIVE `cli._session_complete` migrates and then
REMOVES each source's iter dir from the worktree, so the glob returned `?`
and `iter_dir` fell back to `_unhomed`. The sweep already solves this exact
order problem for ancestry: `base_pre` pre-resolves every worktree's base
BEFORE any bring-home runs, because a `--branch` round's single merge-home
removes the iter dir from EVERY tree. The iter name deserved the same
pre-resolution.

## Fix

In the same pre-pass as `base_pre`, capture `iter_pre[wt.name] =
_sweep_iter_name(wt)` before any bring-home. In the loop the park target and
the `removed` log line read `iter_name = iter_pre.get(agent_id, "?")`;
`_unhomed` remains only as the honest last resort for a worktree that carried
no `iter-*` dir at all. 14 production lines in `extensions/agi/bin/heal.py`
(`_sweep_finished_worktrees` pre-pass + park region only). Nothing else
changed: park byte-exactness, the -1 fail-closed refusal, `git worktree
remove` WITHOUT `--force`, the kept `loop/...` branch, unmerged refused by
name and never parked, and dry-run writing nothing are all untouched.

## Regression test

`test_sweep_park_destination_survives_live_bring_home` — the fixture above,
where the bring-home genuinely RUNS (round session dir only in the worktree,
main target absent so `cli._session_complete` migrates and removes the
source). Asserts the park path `sessions/iter-901/leftovers/a00-7f3a11/
base.txt` is byte-equal, that NO `sessions/_unhomed*` dir exists anywhere,
and that the log names `iter=iter-901` (never `iter=?`). Confirmed RED
pre-fix (FileNotFoundError at the expected iter path, `_unhomed` created),
GREEN post-fix.
