## The defect, measured

Pre-fix, `check_extra_suite` reported a nonzero-exit root as
`f"{root.name}: exit {rc}\n" + last 10 lines of output`. Two distinct faults, and the
gate probe found the second one that the brief did not name:

```
| probe | what the output actually carried |
|---|---|
| tail window | the `FAILED <nodeid>` short-summary block is N+ lines long, so a 10-line budget drops the first ids and degrades to a bare count |
| **`-q` prints NO short summary at all** | the invocation was `pytest <root> -q -rs`; `-r` selects the reported categories, and `-q` selects none, so no `FAILED <nodeid>` line existed in the output to be parsed. Even a 1-failure suite with an infinite window would name nothing. |
```

## The fix (verification.py, +28/-3)

| change | lines |
|---|---|
| `-rf` added to the declared-suite pytest argv so the FAILED summary is emitted at all | 3 |
| `_suite_fail_ids(output)` — regex `^(?:FAILED\|ERROR)\s+(\S+)` over the whole output, de-duplicated in first-seen order | 17 |
| the FAIL note leads with one `  FAILED <nodeid>` per line, then falls back to `(no FAILED node id in the output)` so an unnamed FAIL is loud, then keeps the old 10-line tail as supplementary context | 8 |
