# experiment:a00-0fc3e7d6-008920

## Experiment — per-template fail in `_known_harnesses`

BUILD ORDER, not a measurement (`hypothesis:l4-a-g15-claim-is-a-build-order-not-a-measurement`): the defect was measured, then IMPLEMENTED, then proved on the built bytes.

**The defect (pre-fix, `rotate.py`):**

```python
def _known_harnesses() -> tuple[str, ...]:
    try:
        return tuple(h for h in harness_template.available()
                     if harness_template.load(h).get("rotate", True))
    except Exception:
        return ("claude-code",)
```

ONE `try` wrapped the WHOLE comprehension. A single malformed template aborted the enumeration for every file, and the buildable set silently collapsed to `("claude-code",)`. The live cost: `copilot-cli`, perfectly valid, dropped out; `_validate_harness` then refused it with "declared but rotate.py cannot build it" — the wrong reason — so a seat harness the owner installed became unlaunchable because of an unrelated file.

**Changes (35 production lines, under the 40 ceiling):**

- `harness_template.load_all()` — parses each `available()` id in its own `try/except`, returning `(loaded, broken)`; a broken id maps to `Ns: text`, its siblings stay. An exception from `available()` itself still propagates: that is the whole-enumeration failure, not a file's.
- `rotate._known_harnesses()` — uses `load_all()`, prints one `ERR:` line per broken id on the way (stderr), returns the good buildable ids. The `("claude-code",)` fallback now fires ONLY when `available()` itself raises, exactly the case the old code could not distinguish from one bad file.
- `_validate_harness` unchanged: unknown ids are still refused by name and the declared-but-unbuildable check is not weakened.
