# experiment:a01-4c82aa55-2b3b37

## Experiment

**Test**: `store_in_graph` toggle on `EmbeddingConfig` writes embedding vectors into node frontmatter, reads them back on re-run, supports selective embed for new nodes, and is compatible with downstream consumers (`project()`).

**Implementation**: Added `store_in_graph: bool = False` to `EmbeddingConfig` (frozen dataclass). Modified `embed_graph()` to accept optional `graph_dir: str | None` — when `store_in_graph=True` and `graph_dir` is set, vectors are persisted to each node's `.md` file frontmatter under an `embedding` key via `save_node_file()`. On re-run, already-embedded nodes are read from frontmatter instead of recomputed. Two helpers:
- `_read_stored_vectors()` — walks the graph's nodes, reads frontmatter, returns dict of existing vectors
- `_write_stored_vectors()` — writes computed vectors to each node's frontmatter, skipping missing/unreadable files

**Input**: 6-node chain graph in temp dir with standard layout (`nodes/x/<id>.md`). `EmbeddingConfig(dim=64, seed=42)`.

**8 experimental claims tested**:

| # | Claim | Result |
|---|-------|--------|
| 1 | `store_in_graph` defaults to `False` | ✓ |
| 2 | `store_in_graph=False` works without `graph_dir`, no side effects | ✓ |
| 3 | `store_in_graph=True` writes vectors to frontmatter (all 5 files) | ✓ |
| 4 | Round-trip: 2nd call returns identical vectors within 1e-12 tolerance | ✓ |
| 5 | Idempotent re-run: 3rd call returns same vectors | ✓ |
| 6 | Selective embed: add n5 node, 5 existing unchanged, n5 gets 64-dim | ✓ |
| 7 | `project()` consumes frontmatter-read vectors (6 coords, 2-dim) | ✓ |
| 8 | `store_in_graph=False` leaves files untouched (no `embedding` key) | ✓ |

**Output**: 8/8 passes. All v2 embedding tests + frontmatter tests still pass (42/42).
