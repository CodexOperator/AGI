# experiment:a00-98fb9939-89089f

## Experiment

Testing hypothesis: write.py set must preserve scalar types.

**Root cause discovered**: `node_writer._needs_quoting` returned `True` for any scalar starting with `-`, because `-` was in the special-first-char set `"'[{&*!|>%@`#-?:,`. This caused `tier: -1` to be rendered as `tier: "-1"` (quoted string), losing the int type on round-trip. YAML parses `"-1"` as a string, not int `-1`.

**Fix**: Added a check in `_needs_quoting` — if `sval[0] == "-"` and `sval[1]` is a digit or `.`, the scalar is a valid YAML negative number (`-1`, `-42`, `-0.5`) and does NOT need quoting. Bare `-` and `- ` (dash-space) still get quoted (block sequence ambiguity).

**Verification**:
1. `node_writer._needs_quoting("-1")` → now `False` ✓
2. `node_writer.render_frontmatter({'tier': -1})` → `tier: -1` (unquoted) ✓
3. `yaml.safe_load("tier: -1")` → `{'tier': -1}` (int) ✓
4. `write._coerce("-1")` → `-1` (int) ✓ — already worked
5. Full test suite: 1454 passed, 0 failed ✓

**Re-type plan for the 91 deprecated nodes**: Run `write.py set tier -1` on each deprecated task node via a one-off script. Since `_coerce("-1")` was already returning int, the fix to `_needs_quoting` is the only piece that was missing for a clean round-trip.
