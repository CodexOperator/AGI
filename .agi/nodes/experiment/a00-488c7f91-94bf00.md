## 2 · The fix (one source, `extensions/agi/hooks/rotation_alert.py`)

```
_force_capture(..., line=None, session_id="")   # NEW trailing kwarg
_captive_rotate(..., state_dir, session_id="")  # NEW trailing kwarg
```

| # | change | conjunct |
|---|---|---|
| a | the latch reads the stamp's `session` beside `captured` and holds only when `not session_id or stamp_session == session_id`; a stamp naming ANOTHER session — or naming none (legacy) — reads as ABSENT | 1 |
| b | the capture WRITES `blob["session"] = session_id` into the stamp, so the latch is keyed by the session that captured from now on | 1 |
| c | `_maybe_force_capture` forwards its `session_id`; `main()` forwards `session_id or ""` into `_captive_rotate` (one kwarg plumbed, both call sites) | 1 |
| d | `_captive_rotate` returns **False** on `capture-latched`, so `main()` falls through to the over-line branch and PRINTS the imperative; the gate then re-decides in `_gated_rotate` (whose card-stale arm lands on the same session-keyed latch and reports `capture-latched` as the deferral). A latch is a memory, never a reason to go quiet | 2 |

Deliberately NOT changed: a caller that names no session keeps once-per-seating
latching (P7 — `capture-latched` still fires for the legacy `main()` path and for
any out-of-process caller), and a capture that is *declined* (`capture-no-spawn`)
still returns True, so a seat the operator has forbidden from spawning stays quiet
— a separate question from this claim.
